## アルゴリズムとビッグO記法

- **アルゴリズム**: 問題を解決したりタスクを実行したりするための明確な手順の集合です。アルゴリズムは有限のステップで終了し、各ステップは正確かつ明確でなければなりません。

- **Big O記法**: 入力サイズが増加するにつれてアルゴリズムのリソース使用量の漸近的な上限を表します。Big Oは、最良、平均、最悪の場合のいずれかに関わらず、定数因子や小さい項を無視して全体のスケーリング傾向を測定します。

### よくある時間計算量

- **O(1) - 定数時間**: 入力サイズに関係なく一定の時間で処理が終わります。

```python
def check_even_or_odd(number):
    if number % 2 == 0:
        return 'Even'
    else:
        return 'Odd'
```

- **O(log n) - 対数時間**: 実行時間の上限が入力サイズに対して最大で対数的に増加します。この上限が厳密な場合、アルゴリズムは対数時間で動作します。これは、問題サイズが一定の割合で繰り返し減少する場合に一般的で、バイナリサーチがその例です。

- **O(n) - 線形時間**: 実行時間の上限が入力サイズに対して最大で線形に増加します。この上限が厳密な場合、実行時間は入力サイズに比例して増加します。

```python
for grade in grades:
    print(grade)
```

- **O(n log n) - 対数線形時間**: 効率的な分割統治型ソートで一般的です。マージソートは最悪ケースでO(n log n)の計算量を持ちます。クイックソートは平均ケースでO(n log n)ですが、最悪ケースはO(n²)です。

- **O(n²) - 二次時間**: 実行時間の上限が入力サイズに対して最大で二次的に増加します。この上限が厳密な場合、実行時間は入力サイズの二乗に比例して増加します。これは、各ループがn回繰り返されるネストされたループで発生します。

```python
for i in range(n):
    for j in range(n):
        print("Hello, World!")
```

- **O(2ⁿ) - 指数時間**: 実行時間の指数的な上限です。この上限が厳密な場合、成長率は2ⁿに比例し、nが1増えるごとに倍増します。

- **O(n!) - 階乗時間**: 実行時間の階乗的な上限です。この上限が厳密な場合、成長率はn!に比例し、n個の異なるアイテムの順列の数を表します。

### 空間計算量

- **O(1) - 定数空間**: メモリ使用量が入力サイズに依存せず一定の上限で制限されます。

- **O(n) - 線形空間**: メモリ使用量が入力サイズに対して最大で線形に増加します。この上限が厳密な場合、メモリ使用量は入力サイズに比例して増加します。

- **O(n²) - 二次空間**: メモリ使用量が入力サイズに対して最大で二次的に増加します。この上限が厳密な場合、メモリ使用量は入力サイズの二乗に比例して増加します。

- **O(2ⁿ) - 指数空間**: メモリ使用量の指数的な上限です。この上限が厳密な場合、メモリ使用量は2ⁿに比例して増加します。

- **O(n!) - 階乗空間**: メモリ使用量の階乗的な上限です。この上限が厳密な場合、メモリ使用量はn!に比例して増加します。

## 問題解決の手法

- **問題の理解**: 問題文を何度も読み、入力、期待される出力、入力から出力への変換方法を特定します。

- **アルゴリズムとデータ構造の選択**: 時間と空間の要件で代替アルゴリズムを比較し、問題に適したデータ構造を選んでください。

- **疑似コード**: 言語に依存しないアルゴリズムの論理を高レベルで記述したもので、一般的な文章と`IF`、`ELSE`、`FOR`、`WHILE`などのプログラミング構造を混ぜて表現します。

```md
GET original_string
SET reversed_string = ""

FOR EACH character IN original_string:
    ADD character TO THE BEGINNING OF reversed_string

DISPLAY reversed_string
```

- **実装**: 疑似コードの計画に基づいて、読みやすくモジュール化されたきれいなコードを書いてください。一般的な作業には適切な組み込みツールを使いましょう。

- **エッジケース**: アルゴリズムが扱う境界にある特定の有効な入力です。必ず考慮しテストしてください。

- **テストと改善**: 提供された例やエッジケースでコードをテストしてください。バグをデバッグし、結果を確認し、明確さや効率を向上させるために解決策を改善しましょう。

## 配列

- **静的配列**: 作成時に固定サイズが設定され、要素は連続したメモリに格納されます。この隣接した配置により高速で定数時間のインデックスアクセス（O(1)）が可能です。最大アイテム数が事前に厳密に分かっている場合に静的配列を選んでください。

- **動的配列**: プログラム実行中に自動的にサイズが増減します。容量が足りなくなると、より大きなメモリブロックを割り当てて既存の要素をコピーすることでリサイズを内部で処理します。

**注意:** Pythonには伝統的な組み込みの静的配列はありません。Pythonのリストは動的配列です。

### Pythonのリスト（動的配列）

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### 動的配列の時間計算量

- **アクセス**: O(1)

- **末尾への挿入**: 平均でO(1)、リサイズが必要な場合はO(n)

- **途中への挿入**: O(n)

- **削除**: 中間はO(n)、末尾はO(1)

## スタック

- **スタック**: 後入れ先出し（LIFO）のデータ構造。要素は上から追加・削除されます。

- **プッシュ操作**: スタックのトップに要素を追加します。以下のPythonリストの実装では、通常のプッシュはO(1)の時間とO(1)の追加空間で済みます。リサイズが必要なプッシュはO(n)の時間とO(n)の追加空間がかかる場合があります。

- **ポップ操作**: スタックのトップから要素を削除します。時間計算量は通常O(1)、追加の空間も通常O(1)です。

```python
# Using Python list as stack
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operations
top_element = stack.pop()  # Returns 3
```

## キュー

- **キュー**: 先入れ先出し（FIFO）のデータ構造で、要素は後ろに追加され、前から削除されます。

- **エンキュー操作**: キューの後ろに要素を追加します。時間計算量はO(1)、空間計算量もO(1)です。

- **デキュー操作**: キューの前から要素を削除します。時間計算量はO(1)、空間計算量もO(1)です。

## 連結リスト

- **連結リスト**: 各ノードがデータと次のノードへの参照を持つ線形データ構造。ノードは鎖のようにつながっています。

### 単方向連結リスト

- **構造**: 各ノードはデータと次のノードへの参照を1つ持ちます。

- **走査**: ヘッドからテールへ前方向にのみ移動できます。

- **ヘッドノード**: リストの最初のノードで、通常は唯一直接アクセス可能なノードです。

- **テールノード**: リストの最後のノードで、`None`を指します。

### 連結リストの実装

- **ノードクラス**: ネストされた`Node`クラスが個々のノードを表します。各ノードはデータと次のノードへの参照を持ちます。

- **初期化**: リストにノードがないため、`head`参照は`None`で始まります。新しいノードの`next`参照も後続ノードがないため`None`で始まります。

- **長さの追跡**: リスト内のノード数を追跡する変数があります。

- **`is_empty()`**: `head`が`None`かどうかをチェックしてリストが空かどうかを判定します。

- **追加**: ヘッドから最後のノードまで走査し、そのノードの`next`参照を新しいノードに更新します。リストが空の場合は新しいノードがヘッドになります。

```python
class LinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None

    def __init__(self):
        self.head = None
        self.length = 0

    def is_empty(self):
        return self.head is None

    def append(self, data):
        new_node = self.Node(data)

        if self.is_empty():
            self.head = new_node
        else:
            current = self.head

            while current.next:
                current = current.next

            current.next = new_node

        self.length += 1
```

### 操作と時間計算量

- **先頭への挿入**: O(1)

- **末尾への挿入**: O(n) - 末尾まで走査が必要

- **途中への挿入**: O(n) - 挿入位置まで走査が必要

- **先頭からの削除**: O(1)

- **末尾からの削除**: O(n) - 前のノードを見つけるため走査が必要

- **途中からの削除**: O(n) - 削除対象ノードを見つけるため走査が必要

### 挿入と削除

- **先頭への挿入**: 新しいノードを作成し、その`next`参照を現在のヘッドに設定し、ヘッドを新しいノードに更新します。

- **末尾への挿入**: 最後のノードまで走査し、その`next`参照を新しいノードに更新します。

- **途中への挿入**: 挿入したい位置の前のノードまで走査します。新しいノードの`next`参照を次のノードに設定し、前のノードの`next`参照を新しいノードに更新します。

- **先頭からの削除**: ヘッドを2番目のノードに更新します。

- **末尾からの削除**: 末尾の一つ前のノードまで走査し、その`next`参照を`None`に更新します。

- **途中からの削除**: 削除対象ノードの前のノードを見つけ、その`next`参照を削除対象ノードの次のノードに更新します。

- **値による削除**: 走査中に前のノードを追跡します。対象がヘッドの場合は直接ヘッドを更新します。値が見つからなければリストや長さを変更せずに戻ります。削除が成功した場合のみ長さを減らします。

### 補助的な空間計算量

- **先頭への挿入**: 新しいノードの格納に必要な空間を除き、O(1)の補助空間。

- **末尾への挿入**: 新しいノードの格納に必要な空間を除き、O(1)の補助空間。

- **途中への挿入**: 新しいノードの格納に必要な空間を除き、O(1)の補助空間。

- **先頭からの削除**: O(1)の補助空間。

- **末尾からの削除**: O(1)の補助空間。

- **途中からの削除**: O(1)の補助空間。

### 双方向連結リスト

- **構造**: 各ノードはデータと2つの参照（次のノードと前のノード）を持ちます。

- **走査**: 双方向に移動できます。

- **メモリ**: 追加の参照があるため、単方向連結リストより多くのメモリを必要とします。

- **テール参照**: 最後のノードへの参照を保持することで、前の参照を使った逆方向の走査が可能になります。

## ハッシュマップとセット

### マップとハッシュマップ

- **抽象データ型（ADT）と実装の違い**: ADTはデータ構造がサポートする操作や論理的な振る舞いを定義する*インターフェース*です。具体的な実装は、これらの操作が実際にどのように構築されメモリ上で実行されるかを示します。

- **マップ（ADT）**: 一意のキーと値の集合を定義する抽象データ型です。内部の格納方法を指定せず、マップができることのルールを設定します。

- **ハッシュマップ**: マップADTの具体的な実装で、ハッシュ関数を使って基盤となる配列の格納位置を計算し、高速な検索を実現します。

### Pythonの辞書（ハッシュマップ）

```python
# Creating dictionaries
my_dictionary = {
    "A": 1,
    "B": 2,
    "C": 3
}

# Alternative creation
my_dictionary = dict(A=1, B=2, C=3)

# Access and modify
value = my_dictionary["A"]  # 1
my_dictionary["A"] = 4      # Update value
del my_dictionary["A"]      # Remove key-value pair

# Check membership
"C" in my_dictionary

# Get keys, values, items
my_dictionary.keys()
my_dictionary.values()
my_dictionary.items()
```

### ハッシュマップの時間計算量

- **平均ケース**: 挿入、取得、削除はO(1)

- **最悪ケース**: 多くのハッシュ衝突が発生するとO(n)

### ハッシュマップの補助的な空間計算量

- **挿入**: 通常の挿入はO(1)の追加空間。リサイズ時はO(n)の追加空間が必要になる場合があります。

- **検索**: O(1)の補助空間。

- **削除**: O(1)の補助空間。

### セット

- **セット**: 重複のない要素の無順序集合。重複は許されず、特定の順序は保持されません。

- **セットの要素**: セットは数値、文字列、および数値と文字列のみを含むタプルを含めることができます。リスト、辞書、他のセットはセットの要素になれません。リストを含むタプルは、タプル自体は不変でもセットの要素にはなれません。

```python
# Creating sets
numbers = {1, 2, 3, 4}
empty_set = set()  # Must use set(), not {}

# Add and remove elements
numbers.add(5)
numbers.remove(4)      # Raises KeyError if not found
numbers.discard(4)     # No error if not found

# Remove and return an arbitrary element
numbers.pop()

# Remove all elements
numbers.clear()

# Get the number of elements
len(numbers)
```

### セット操作

```python
set_a = {1, 2, 3, 4}
set_b = {2, 3, 4, 5, 6}

# Union, intersection, difference, symmetric difference
set_a.union(set_b)                  # or set_a | set_b
set_a.intersection(set_b)           # or set_a & set_b
set_a.difference(set_b)             # or set_a - set_b
set_a.symmetric_difference(set_b)   # or set_a ^ set_b

# Subset and superset checks
set_a.issubset(set_b)
set_a.issuperset(set_b)
set_a.isdisjoint(set_b)

# Membership testing
5 in numbers
```

### セットの時間計算量

- **平均ケース**: 追加、削除、メンバーシップテストはO(1)

- **最悪ケース**: ハッシュ衝突によりO(n)

- **長さの取得**: `len()`でO(1)。

### セットの補助的な空間計算量

- **挿入**: 通常の挿入はO(1)の追加空間。リサイズ時はO(n)の追加空間が必要になる場合があります。

- **検索**: O(1)の補助空間。

- **削除**: O(1)の補助空間。

- **長さの取得**: O(1)の補助空間。

## ハッシュ衝突

- **ハッシュ衝突**: 異なるキーが同じハッシュ値を生成することがあります。ハッシュテーブルでは、異なるハッシュ値が同じ配列インデックスにマップされる場合も衝突が発生します。同じインデックスを共有するエントリーは衝突解決戦略で処理されます。

- **衝突解決戦略**:

  - **チェーン**: 各配列インデックスが、そのバケットインデックスにマップされるすべてのエントリーを格納する連結リストを指します。

  - **オープンアドレッシング**: 衝突が起きた場合に、あらかじめ定義されたシーケンスを使って次の利用可能な配列インデックスを探します。

## それぞれのデータ構造の使いどころ

- **リスト**: 順序付きでインデックスアクセスが必要で、サイズが事前に分からない場合に使います。

- **スタック**: LIFO操作（元に戻す機能、式の評価、バックトラッキング）に使います。

- **キュー**: FIFO操作（タスクスケジューリング、幅優先探索）に使います。

- **連結リスト**: 頻繁に先頭での挿入/削除があり、サイズが不明でランダムアクセスが不要な場合に使います。

- **ハッシュマップ**: 高速なキーと値の検索、出現回数のカウント、キャッシュに使います。

- **セット**: 一意性のチェック、数学的な集合演算、重複の削除に使います。
