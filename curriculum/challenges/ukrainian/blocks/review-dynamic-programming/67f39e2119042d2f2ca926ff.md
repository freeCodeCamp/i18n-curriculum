## Вступ до динамічного програмування

- **Визначення**: Динамічне програмування — це алгоритмічна техніка, яка розв’язує складні задачі, розбиваючи їх на простіші підзадачі і зберігаючи результати, щоб уникнути повторних обчислень.
- **Перекриваючі підзадачі**: Одні й ті самі менші задачі з’являються багаторазово при розв’язанні більшої задачі. Замість повторного обчислення цих підзадач ми зберігаємо їхні рішення.
- **Оптимальна підструктура**: Оптимальне рішення задачі містить оптимальні рішення її підзадач. Це означає, що ми можемо побудувати найкраще рішення, комбінуючи найкращі рішення менших частин.

## Проблема підйому сходами

Класичним прикладом динамічного програмування є підрахунок різних способів дістатися вершини сходів із додатною кількістю кроків `n`, де кожен рух може бути підйомом на 1 або 2 кроки:

- **Наївна рекурсія**: Оскільки кількість способів дістатися кроку `n` дорівнює сумі способів дістатися кроку `n - 1` і кроку `n - 2`, пряме рекурсивне рішення багаторазово перераховує ідентичні підзадачі. Наприклад, обчислення кроку `5` двічі перераховує крок `3` і тричі крок `2`. Це призводить до експоненційної верхньої межі часу виконання `O(2^n)` і використання простору стеку викликів `O(n)`.

## Рішення динамічного програмування

Динамічне програмування усуває надмірні обчислення за допомогою двох основних підходів:

- **Мемоізація (підхід зверху вниз)**: Мемоізація зберігає результати викликів функцій у кеші (наприклад, у словнику) і повертає кешований результат, коли знову зустрічається та сама підзадача:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

З початково порожнім кешем мемоізація знижує часову складність до лінійної `O(n)`, вимагаючи `O(n)` простору для зберігання кешованих підзадач разом зі стеком рекурсивних викликів.

- **Табуляція (підхід знизу вгору)**: Табуляція усуває рекурсію, ітеративно будуючи розв’язок від найменших підзадач до цілі, зберігаючи проміжні результати у списку:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

Табуляція працює за час `O(n)` і використовує `O(n)` простору для списку, з ключовою перевагою уникнення росту стеку рекурсивних викликів.

- **Оптимізація табуляції з постійним простором**: Оскільки кожен новий крок залежить лише від двох попередніх значень, повну таблицю можна замінити двома змінними, які зберігають останні два підрахунки:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

Розглядаючи кожну арифметичну дію як операцію з постійним часом і кожне збережене значення як одиницю простору, ця оптимізація зберігає часову складність `O(n)`, зменшуючи допоміжну просторову складність до `O(1)`.

## Практичний приклад: задача про зміну монет

Проблема розмінювання монет — це класична задача оптимізації, яка ставить за мету знайти мінімальну кількість монет, необхідних для отримання цільової суми:

- **Алгоритм**: алгоритм використовує табуляцію, створюючи масив `dp` розміром `amount + 1`, ініціалізований значенням нескінченності (`float('inf')`), щоб представити спочатку недосяжні значення. Початковий випадок — `dp[0] = 0`, оскільки для суми `0` не потрібні монети. Для кожної суми `i` від `1` до `amount` алгоритм мінімізує `dp[i - coin] + 1` серед усіх допустимих номіналів монет (`coin <= i`). Якщо `dp[amount]` залишається нескінченністю, ціль неможливо сформувати, тому повертається `-1`:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

Для номіналів `[1, 3, 4]` і цілі `6` алгоритм обчислює `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`, отримуючи оптимальну комбінацію з двох монет (`3 + 3`).

- **Складність**: Алгоритм перевіряє кожен номінал для кожної підсуми до цілі, що дає часову складність `O(amount * number_of_coins)` і допоміжну просторову складність `O(amount)` для масиву DP.

## Застосунки динамічного програмування у реальному світі

- **Оптимізація маршруту**: GPS-системи використовують алгоритми динамічного програмування, щоб знайти найкоротші шляхи між локаціями.
- **Обробка тексту**: Перевірка орфографії та функції автозаповнення часто покладаються на динамічне програмування для обчислення відстаней редагування між словами.
- **Фінансове моделювання**: Інвестиційні стратегії та оптимізація портфоліо часто застосовують техніки динамічного програмування.
- **Розподіл ресурсів**: Задача рюкзака та її варіанти зустрічаються у плануванні, бюджетуванні та управлінні ресурсами.

## Коли використовувати динамічне програмування

Варто розглянути використання динамічного програмування у таких випадках:

- Проблему можна розбити на перекривні підзадачі.
- Проблема має оптимальну підструктуру.
- Наївне рекурсивне рішення передбачає повторні обчислення.
- Потрібно оптимізувати часову складність за рахунок просторової складності.
