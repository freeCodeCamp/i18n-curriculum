# --description--

Lernen wir, wie Ihre Systemsprache und Tastatureinstellungen Bash- und PostgreSQL-Workshops beeinflussen können.

Viele Programmierwerkzeuge erwarten, dass Befehle Standard-englische Tastaturzeichen verwenden. In Bash- und PostgreSQL-Workshops ist das besonders wichtig für Symbole wie Semikolons (`;`), Anführungszeichen, Schrägstriche und andere Sonderzeichen.

Wenn Ihr Betriebssystem oder Ihre Tastaturbelegung eine nicht-englische Sprachkonfiguration verwendet, können einige Zeichen anders reagieren als erwartet. Das kann zu verwirrenden Fehlern beim Eingeben von SQL-Befehlen oder Terminalbefehlen führen.

Für die beste Erfahrung während dieser Workshops wird empfohlen, vorübergehend auf die englische (US) Tastaturbelegung umzuschalten, während Sie den Kurs absolvieren. Das ist besonders hilfreich, wenn Befehle in Bash oder PostgreSQL unerwartete Zeichen oder Syntaxfehler erzeugen, wenn Sie Symbole wie `;` oder `\` eingeben.

GitHub Codespaces verwendet Ihre lokale Tastaturbelegung, daher wirkt sich eine Änderung der Belegung auf Ihrem eigenen Computer auch auf das Tippen in Codespaces aus.

Unter Windows:

1. Öffnen Sie **Einstellungen** > **Zeit und Sprache** > **Sprache und Region**
2. Fügen Sie **Englisch (Vereinigte Staaten)** hinzu, falls es noch nicht installiert ist
3. Wählen Sie unter Tastaturbelegungen die **US**-Tastatur aus
4. Verschieben Sie die US-Tastaturbelegung bei Bedarf an den Anfang der Liste

Unter macOS:

1. Öffnen Sie **Systemeinstellungen** > **Tastatur** > **Eingabequellen**
2. Fügen Sie die Tastaturbelegung **Englisch (US)** hinzu
3. Stellen Sie sicher, dass die US-Belegung als aktive Tastatur ausgewählt ist

Unter Linux-Distributionen wie Ubuntu, Debian oder Mint:

1. Öffnen Sie die Tastatureinstellungen Ihres Systems
2. Fügen Sie die Tastaturbelegung **Englisch (US)** hinzu
3. Verschieben Sie sie, wenn möglich, an den Anfang der Liste der Tastaturbelegungen

Einige Linux-Systeme erlauben auch das Überprüfen und Ändern der Tastaturbelegung über das Terminal. Prüfen Sie zuerst Ihre aktuelle Belegung:

```bash
setxkbmap -query
```

Wechseln Sie dann zur US-Belegung:

```bash
setxkbmap us
```

Testen Sie nach dem Wechsel der Belegung die folgenden Zeichen in einem Textfeld oder Terminal:

```md
; : / \ | ' " $ { } [ ] ( )
```

Wenn die Symbole korrekt angezeigt werden, ist Ihre Tastaturbelegung wahrscheinlich richtig konfiguriert.

Einige nicht-englische Belegungen behandeln Zeichen wie `'` und `"` als sogenannte Dead Keys, das heißt, sie warten auf eine Folgetaste, anstatt sofort zu tippen. Nach dem Wechsel zur US-Belegung sollten diese Zeichen sofort erscheinen. Wenn ein Zeichen immer noch nicht sofort angezeigt wird, ist das ein Zeichen dafür, dass Ihre Belegung nicht vollständig umgeschaltet wurde.

Wenn Sie eine physische Tastaturbelegung verwenden, die nicht US ist, wie AZERTY, QWERTZ oder regionale QWERTY-Varianten, können sich die Symboltasten an anderen physischen Positionen befinden. Verwenden Sie in diesem Fall die Bildschirmtastatur oder den Tastatur-Viewer Ihres Betriebssystems, um Tasten wie `;`, `/`, `\`, `|`, `'` und `"` nach dem Wechsel zur US-Belegung zu finden.

Die Verwendung der englischen (US) Tastaturbelegung hilft sicherzustellen, dass Bash- und PostgreSQL-Befehle während des gesamten Workshops genau wie erwartet funktionieren.

Nachdem Sie die Workshops abgeschlossen haben, können Sie wieder zu Ihrer ursprünglichen Tastaturbelegung zurückwechseln.
