## Що таке об’єктно-орієнтоване програмування?

- **Об’єктно-орієнтоване програмування**: стиль програмування, у якому розробники ставляться до всього у своєму коді як до реальних об’єктів. Його часто називають ООП. Чотири ключові принципи, які допомагають ефективно організовувати та керувати кодом, це **інкапсуляція**, **успадкування**, **поліморфізм** та **абстракція**.
- **Класи**: шаблон для створення об’єктів. Кожен об’єкт, створений із класу, має атрибути, які визначають дані, і методи, які визначають поведінку об’єкта.

## Що таке інкапсуляція?

- **Інкапсуляція**: Об’єднання атрибутів і методів об’єкта в єдину одиницю. Вона дозволяє приховати внутрішній стан об’єкта за простим набором публічних методів і атрибутів, які діють як двері. За цими дверима — приватні атрибути і методи, які контролюють, як змінюються дані і хто може їх бачити.
- **Приклад інкапсуляції**: Якщо ви хочете відстежувати баланс гаманця, ви дозволите внесення і зняття коштів, але не дозволите нікому змінювати сам баланс гаманця:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **Різниця між префіксуванням атрибутів одним і подвійним підкресленням**: префіксування атрибутів і методів одним підкресленням сигналізує, що вони призначені для внутрішнього використання. Це лише конвенція, і Python не обмежує доступ до них ззовні класу. Префіксування атрибутів і методів подвійним підкресленням викликає name mangling, який перейменовує `__balance` на `_Wallet__balance`. Це допомагає уникнути випадкових конфліктів імен у підкласах, але не робить доступ ззовні неможливим:

```py
print(account._Wallet__balance) # 500
```

## Що таке геттери і сеттери?

- **Геттери і сеттери**: методи, які дозволяють контролювати, як отримують і змінюють атрибути класу. Ви отримуєте значення за допомогою геттерів і встановлюєте їх за допомогою сеттерів.
- **Властивості**: вони поєднують геттери і сеттери та дозволяють отримувати доступ до даних. Вони виконують додаткову логіку за лаштунками, коли ви отримуєте, встановлюєте або видаляєте значення.
- **Чому властивості замість методів**: властивості використовують замість методів для кращої читабельності та чистішого коду. Вони дозволяють отримувати значення через точкову нотацію, як звичайні атрибути, без круглих дужок.
- **Декоратори**: декоратор — це функція, яка змінює або обгортає інші функції чи класи, не змінюючи їхній оригінальний код. Ви застосовуєте декоратор, розміщуючи `@decorator_name` безпосередньо над визначенням функції або класу. Наприклад, розміщення декоратора `@property` над методом перетворює його на властивість, яку можна отримувати як атрибут, викликаючи всередині декорований метод.
- **Створення геттера**: щоб створити геттер, використовуйте декоратор `@property`. Ось геттер, який отримує радіус кола:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **Створення сеттера**: Щоб створити сеттер, який встановлюватиме радіус, потрібно визначити інший метод з таким самим ім’ям і використати `@<property_name>.setter` над ним:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Як Python обробляє геттери і сеттери**: Після визначення геттерів і сеттерів Python автоматично викликає їх під капотом щоразу, коли ви використовуєте звичайний синтаксис атрибутів ось так:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

Всередині сеттера не слід призначати значення властивості безпосередньо, бо це спричинить `RecursionError`.

- **Делетер**: Після встановлення і отримання значення за допомогою сеттера і геттера ви можете контролювати, як воно видаляється, за допомогою `deleter`. Делетер виконує кастомну логіку, коли ви використовуєте інструкцію `del` для властивості. Щоб створити делетер, використовуйте декоратор `@<property_name>.deleter`.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## Що таке успадкування і як воно сприяє повторному використанню коду?

- **Успадкування**: Процес, за якого дочірній клас використовує атрибути і методи батьківського класу. Успадкування сприяє повторному використанню коду, забезпечує чітку ієрархію і дозволяє налаштовувати поведінку без переписування всього. Щоб реалізувати успадкування, дочірній клас приймає ім’я батьківського класу:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **Одинарне і множинне успадкування**: Коли дочірній клас успадковує властивості і методи від одного батька, як показано вище, це називається **одинарним успадкуванням**. Коли дочірній клас успадковує властивості і методи від кількох батьків, це **множинне успадкування**. Ось синтаксис для цього:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **Функція `super()`**: Функція, яка дозволяє **викликати** метод батьківського класу, коли клас має іншу реалізацію цього методу або розширює його, без дублювання коду.

## Що таке поліморфізм і як він сприяє повторному використанню коду?

- **Поліморфізм**: Принцип ООП, який дозволяє різним класам використовувати однакову назву методу, але кожен клас реалізує його по-своєму при виклику. Ось синтаксис для цього:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **Поліморфізм на основі успадкування**: Батьківський клас задає метод, а кожен дочірній клас адаптує його під свої потреби.

## Що таке name mangling і як він працює?

- **Name mangling**: процес, у якому Python внутрішньо перейменовує атрибут, префіксований подвійним підкресленням, додаючи підкреслення та ім’я класу як префікс, перетворюючи `__attribute` на `_ClassName__attribute`.
- **Мета name mangling**: основна мета name mangling — запобігти випадковому перекриттю атрибутів і методів при використанні успадкування. Ось приклад коду, який робить це зрозумілішим:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## Що таке абстракція і як вона допомагає тримати складні системи організованими?

- **Абстракція**: концепція програмування, у якій складні деталі реалізації об’єкта або системи приховані, а показані лише суттєві функції. В Python та інших мовах програмування абстракція спрощує складні системи, підвищуючи повторне використання.
- **Приклад абстракції**: хороший приклад абстракції у повсякденному житті — це автомобіль, який дозволяє вам користуватися лише кермом, педалями та важелем перемикання, не знаючи, як працює двигун або гальма.
- **Як Python реалізує абстракцію**: ви можете створювати абстракції за допомогою звичайних функцій і класів, приховуючи деталі реалізації за простим інтерфейсом. Для більш формальних інтерфейсів модуль `abc` Python надає допоміжний клас `ABC` і декоратор `@abstractmethod`. Абстрактний базовий клас визначає спільні методи та властивості, які мають реалізувати конкретні підкласи.
- **Як визначаються абстрактні методи**: абстрактний метод визначається за допомогою `@abstractmethod`. Клас можна інстанціювати лише якщо він надає або успадковує конкретні реалізації всіх своїх абстрактних методів. Підклас, який залишає будь-який абстрактний метод не реалізованим, залишається абстрактним. Абстрактний метод може мати реалізацію за замовчуванням, яку підкласи можуть викликати через `super()`. Успадкування від `ABC` саме по собі не забороняє інстанціювання: `ABC()` і підкласи без абстрактних методів можна інстанціювати. Основний синтаксис абстракції виглядає так:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## Представлення об’єктів

- **Метод `__repr__`**: спеціальний метод, який повертає рядкове представлення об’єкта. Ідеально, якщо цей рядок виглядає як код, що створює об’єкт. Наприклад, `Employee('Charlie', 'developer')` має бути представлений як `Employee('Charlie', 'developer')`.
- **Функція `repr()`**: коли ви викликаєте `repr()` для об’єкта, Python під капотом викликає метод `__repr__` цього об’єкта. Для рядків `repr()` додає лапки і виконує екранування символів, які цього потребують:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **Конверсія `!r`**: всередині f-рядка додавання `!r` після виразу застосовує до нього `repr()`. Використання `!r` у `__repr__` зберігає коректність представлення, коли значення містить лапки або зворотні скісні риски, на відміну від ручного обгортання значень у лапки:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## Докстрінги та перевірка типів

- **Докстрінги**: рядок, розміщений як перша інструкція в класі або функції для їх документування. Докстрінги зазвичай беруть у потрійні подвійні лапки:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()` проти `type()`**: `isinstance(obj, ClassName)` повертає `True`, якщо `obj` є екземпляром `ClassName` або будь-якого з його підкласів, оскільки враховує повний ланцюг успадкування. Щоб перевірити точний клас, порівнюйте `type(obj)` замість цього:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## Кастомні виключення з додатковим контекстом

- **Збереження контексту у виключенні**: кастомне виключення може приймати додаткові дані разом із повідомленням. Виклик `super().__init__(message)` дозволяє вбудованому класу `Exception` зберігати і відображати повідомлення, а ви можете зберегти додаткові дані як атрибут. Коли ви ловите виключення, можете прочитати цей атрибут, щоб допомогти з налагодженням:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## Підказки типів

- **Підказки типів**: необов’язкові анотації, які сигналізують іншим розробникам, якого типу дані очікуються у змінній, параметрі або поверненому значенні. Python не застосовує їх під час виконання.
- **Підказки типів параметрів і повернених значень**: ви додаєте підказку типу параметра через двокрапку після імені параметра, а підказку типу поверненого значення через `-> return_type` після списку параметрів. Оскільки `__init__` — це ініціалізатор, який має повертати `None`, його підказка типу поверненого значення — `None`:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **Кастомні класи і списки як типи**: ви можете використовувати власні класи як підказки типів, а `list[ClassName]` означає список, що містить об’єкти цього класу:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
