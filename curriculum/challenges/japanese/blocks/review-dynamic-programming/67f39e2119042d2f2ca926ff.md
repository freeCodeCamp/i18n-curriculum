## 動的計画法の紹介

- **定義**：動的計画法は複雑な問題をより単純な部分問題に分割し、結果を保存して冗長な計算を避けるアルゴリズム手法です。
- **重複部分問題**：大きな問題を解く際に同じ小さな問題が何度も現れます。これらを繰り返し計算する代わりに解を保存します。
- **最適部分構造**：問題の最適解は部分問題の最適解を含みます。つまり、小さな部分の最適解を組み合わせて最良の解を作れます。

## 階段を登る問題

動的計画法の代表的な例は、正の数のステップ数 `n` の階段の頂上に到達する異なる方法の数を数えることで、各移動で1歩または2歩登ることができます。

- **単純な再帰**: ステップ `n` に到達する方法の数は、ステップ `n - 1` とステップ `n - 2` に到達する方法の合計であるため、直接的な再帰解法は同じ部分問題を何度も再計算します。例えば、ステップ `5` を計算すると、ステップ `3` を2回、ステップ `2` を3回再計算します。これにより、指数関数的な `O(2^n)` の時間計算量と `O(n)` の呼び出しスタック空間が発生します。

## 動的計画法の解法

動的計画法は、主に2つの方法で冗長な計算を排除します。

- **メモ化（トップダウンアプローチ）**: メモ化は、関数呼び出しの結果をキャッシュ（例えば辞書）に保存し、同じ部分問題に再度遭遇したときにキャッシュされた結果を返します。

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

初期状態で空のキャッシュを使うことで、メモ化は時間計算量を線形の `O(n)` に削減し、再帰呼び出しスタックと共にキャッシュされた部分問題を保存するために `O(n)` の空間を必要とします。

- **タビュレーション（ボトムアップアプローチ）**: タビュレーションは、最小の部分問題からターゲットまで順に解を構築し、中間結果をリストに保存することで再帰を排除します。

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

タビュレーションは `O(n)` の時間で動作し、リストのために `O(n)` の空間を使用します。主な利点は再帰呼び出しスタックの増加を避けられることです。

- **定数空間タビュレーションの最適化**: 各新しいステップは直前の2つの値だけに依存するため、完全なテーブルを最後の2つのカウントを保存する2つの変数に置き換えられます。

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

各算術演算を定数時間、各保存されたカウントを1単位の空間とみなすと、この最適化は `O(n)` の時間を維持しつつ補助空間計算量を `O(1)` に削減します。

## 実践例：コインチェンジ問題

コインチェンジ問題は、目標金額を作るのに必要な最小枚数のコインを求める古典的な最適化問題です。

- **アルゴリズム**：このアルゴリズムは、配列 `dp` を `amount + 1` のサイズで作成し、到達できない値を表すために初期値を無限大（`float('inf')`）に設定してタビュレーションを行います。ベースケースは `dp[0] = 0` で、金額 `0` を作るのにコインは必要ありません。各金額 `i` について、`1` から `amount` まで、利用可能なすべてのコインの額面（`coin <= i`）に対して `dp[i - coin] + 1` の最小値を求めます。`dp[amount]` が無限大のままなら、目標金額は作れないため `-1` を返します。

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

コインの種類が `[1, 3, 4]` で目標が `6` の場合、アルゴリズムは `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2` を計算し、最適な組み合わせは2枚のコイン（`3 + 3`）となります。

- **計算量**: アルゴリズムは目標までの各部分金額に対してすべてのコインの種類をチェックするため、時間計算量は `O(amount * number_of_coins)`、補助空間計算量は DP 配列のために `O(amount)` となります。

## 動的計画法を使った実世界のアプリケーション

- **ルート最適化**：GPSシステムは動的計画法のアルゴリズムを使って、場所間の最短経路を見つけます。
- **テキスト処理**：スペルチェッカーやオートコンプリート機能は、単語間の編集距離を計算するために動的計画法をよく利用します。
- **金融モデリング**：投資戦略やポートフォリオの最適化には動的計画法の手法が頻繁に使われます。
- **資源配分**：ナップサック問題やその派生問題は、スケジューリング、予算管理、資源管理に現れます。

## 動的計画法を使うべき場合

次のような場合に動的計画法の使用を検討してください：

- 問題が重複する部分問題に分解できる。
- 問題が最適部分構造を持つ。
- 単純な再帰的解法では計算が繰り返される。
- 時間計算量を優先し、空間計算量を犠牲にしてもよい。
