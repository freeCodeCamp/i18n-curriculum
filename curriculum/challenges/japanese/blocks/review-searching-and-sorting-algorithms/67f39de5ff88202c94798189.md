## 検索アルゴリズム

- **目的**: 検索アルゴリズムは、アイテムのリスト内でターゲットを検索することができます。
- **検索アルゴリズムの種類**: よく使われる検索アルゴリズムには、線形検索と二分探索があります。それぞれの違いを理解することで、どちらを使うべきか判断しやすくなります。

### 線形探索

- **線形検索アルゴリズム**: リストの最初から順にアイテムをチェックし、ターゲットが見つかるまで反復します。
- **検索成功時**: ターゲットが見つかった場合、そのアイテムがリスト内にあるインデックスを返します。
- **検索失敗時**: 講義の実装では、ターゲットが見つからなかったことを示すために `-1` を返します。Pythonでは、`-1` は非空リストの最後の要素のインデックスでもあるため、結果が `-1` かどうかをインデックスとして使う前に必ず確認してください。そうしないと、検索失敗時に誤って最後の要素を取得してしまう可能性があります。
- **効率性**: 線形検索はアイテムを順番にチェックするため、大きなリストでは非効率になることがあります。
- **時間計算量**: リストのサイズに比例して検索時間が増えるため、`O(n)` です。
- **空間計算量**: 入力サイズに関係なく一定の追加空間しか使わないため、`O(1)` です。

### 二分探索

- **Binary Search Algorithm**: ソートされたリストを繰り返し半分に分割してターゲット値を見つける効率的な検索アルゴリズムです。
- **Sorted Input Prerequisite**: Binary Searchは、入力リストが昇順にソートされている必要があります。
- **Search Range Initialization**: 最初の要素のインデックスとして`low = 0`、最後の要素のインデックスとして`high = len(arr) - 1`を初期化します。これらの変数は検索対象の範囲（両端を含む）を定義します。
- **Search Continuation Condition**: `low <= high`の間は検索を続けます。`low > high`になると検索範囲が空になり、ターゲットが見つからなかったことを意味します。
- **Midpoint Calculation**: 整数除算を使って中央のインデックスを計算します：`mid = (low + high) // 2`。
- **Target Comparison**: ターゲット値と`arr[mid]`を比較します。等しければ、ターゲットはインデックス`mid`で見つかっています。
- **Lower Boundary Update**: `arr[mid] < target`の場合、ターゲットはリストの右半分にあるはずです。中央とそれより前の要素を除外するために`low = mid + 1`に更新します。
- **Upper Boundary Update**: `arr[mid] > target`の場合、ターゲットはリストの左半分にあるはずです。中央とそれより後の要素を除外するために`high = mid - 1`に更新します。
- **Lecture Successful Search**: 講義の実装では、ターゲットが見つかった場合にそのインデックスを返します。
- **Lecture Unsuccessful Search**: 講義の実装では、検索範囲が空になった場合に`-1`を返します。
- **Workshop Path Tracking**: ワークショップの実装では、空の`path_to_target`リストを初期化し、検索中に訪れた各中央の値を追加していきます。
- **Workshop Successful Search**: ターゲットが見つかった場合、ワークショップは`path_to_target`とターゲットが見つかったインデックスを示すメッセージを含むタプルを返します。
- **Workshop Unsuccessful Search**: 検索範囲が空になった場合、ワークショップは空のリストと`"Value not found"`というメッセージを返します。
- **Time Complexity**: 各比較で検索範囲がおよそ半分になるため、`O(log n)`です。
- **Space Complexity**: 講義の実装は`low`、`high`、`mid`などの変数に対して`O(1)`の補助記憶領域を使用します。ワークショップの実装は、検索中に訪れた中央の値を`path_to_target`に保存するため`O(log n)`の補助記憶領域を使用します。

### 線形探索と二分探索の違い

- **前提条件**: 線形検索はソート済みリストを必要としませんが、二分探索は入力データが昇順にソートされている必要があります。
- **スケーラビリティ**: 二分探索は線形検索よりも大きなリストに適しています。
- **時間計算量の比較**: 線形検索は `O(n)`、二分探索は `O(log n)` の時間計算量です。

## ソートアルゴリズムと分割統治法

- **分割統治法**: 問題をより小さな部分問題に分割して解きやすくする手法です。再帰を使って実装されることが多く、マージソートのような効率的なソートアルゴリズムでよく使われます。

### マージソート

- **マージソートアルゴリズム**: 分割統治法に従うソートアルゴリズムです。
- **基本ケース**: 要素が0個または1個のリストはすでにソート済みなので、`len(array) <= 1` のときに再帰を停止します。
- **リストの分割**: リストを2つのスライスに分割し、それぞれを再帰的にソートします。
- **部分リストのマージ**: 2つのソート済み部分リストの未マージの次の要素を比較し、小さい方を出力位置にコピーしてインデックスを進めます。片方が空になるまで続け、残った要素をすべてコピーします。
- **ワークショップの実装**: ワークショップではスライスした半分を作成し、マージした値を元のリストに書き戻しながら `sorted_index` を進めます。元のリストを変更しても、スライスした半分の追加ストレージが必要なためインプレースソートではありません。
- **時間計算量**: リストを繰り返し半分に分割するため `log n` レベルあり、各レベルでのマージに `O(n)` 時間がかかるので、`O(n log n)` です。
- **空間計算量**: マージに追加のメモリが必要でインプレースソートではないため、`O(n)` です。
