## Algorithmen und Big-O-Notation

- **Algorithmen**: Eine Reihe eindeutiger Anweisungen zur Lösung eines Problems oder zur Durchführung einer Aufgabe. Algorithmen müssen in einer endlichen Anzahl von Schritten abgeschlossen sein, und jeder Schritt muss präzise und eindeutig sein.

- **Big-O-Notation**: Beschreibt eine asymptotische obere Schranke für den Ressourcenverbrauch eines Algorithmus, wenn die Eingabegröße wächst. Big O misst diesen allgemeinen Skalierungstrend unabhängig davon, ob Sie den besten, durchschnittlichen oder schlechtesten Fall betrachten, und ignoriert dabei konstante Faktoren und kleinere Terme.

### Häufige Zeitkomplexitäten

- **O(1) – konstante Zeit**: Der Algorithmus benötigt unabhängig von der Eingabegröße immer die gleiche Zeit.

```python
def check_even_or_odd(number):
    if number % 2 == 0:
        return 'Even'
    else:
        return 'Odd'
```

- **O(log n) - Logarithmische Zeit**: Eine obere Schranke für die Laufzeit, die höchstens logarithmisch mit der Eingabegröße wächst. Wenn die Schranke eng ist, läuft der Algorithmus in logarithmischer Zeit. Dies tritt häufig auf, wenn die Problemgröße wiederholt um einen konstanten Bruchteil reduziert wird, wie bei der binären Suche.

- **O(n) - Lineare Zeit**: Eine obere Schranke für die Laufzeit, die höchstens linear mit der Eingabegröße wächst. Wenn die Schranke eng ist, wächst die Laufzeit proportional zur Eingabegröße.

```python
for grade in grades:
    print(grade)
```

- **O(n log n) - Log-lineare Zeit**: Häufig bei effizienten Divide-and-Conquer-Sortieralgorithmen. Merge Sort hat eine Worst-Case-Komplexität von O(n log n). Quick Sort hat eine durchschnittliche Komplexität von O(n log n), aber seine Worst-Case-Komplexität ist O(n²).

- **O(n²) - Quadratische Zeit**: Eine obere Schranke für die Laufzeit, die höchstens quadratisch mit der Eingabegröße wächst. Wenn die Schranke eng ist, wächst die Laufzeit proportional zum Quadrat der Eingabegröße. Dies tritt bei verschachtelten Schleifen auf, bei denen jede Schleife n Iterationen ausführt.

```python
for i in range(n):
    for j in range(n):
        print("Hello, World!")
```

- **O(2ⁿ) - Exponentielle Zeit**: Eine exponentielle obere Schranke für die Laufzeit. Wenn die Schranke eng ist, wächst die Rate proportional zu 2ⁿ, was sich verdoppelt, wenn n um eins erhöht wird.

- **O(n!) - Fakultätszeit**: Eine fakultative obere Schranke für die Laufzeit. Wenn die Schranke eng ist, wächst die Rate proportional zu n!, der Anzahl der Permutationen von n verschiedenen Elementen.

### Speicherkomplexität

- **O(1) - Konstanter Speicher**: Der Speicherverbrauch ist durch eine Konstante begrenzt, unabhängig von der Eingabegröße.

- **O(n) - Linearer Speicher**: Der Speicherverbrauch wächst höchstens linear mit der Eingabegröße. Wenn die Schranke eng ist, wächst der Speicherverbrauch proportional zur Eingabegröße.

- **O(n²) - Quadratischer Speicher**: Der Speicherverbrauch wächst höchstens quadratisch mit der Eingabegröße. Wenn die Schranke eng ist, wächst der Speicherverbrauch proportional zum Quadrat der Eingabegröße.

- **O(2ⁿ) - Exponentieller Speicher**: Eine exponentielle obere Schranke für den Speicherverbrauch. Wenn die Schranke eng ist, wächst der Speicherverbrauch proportional zu 2ⁿ.

- **O(n!) - Fakultätsspeicher**: Eine fakultative obere Schranke für den Speicherverbrauch. Wenn die Schranke eng ist, wächst der Speicherverbrauch proportional zu n!.

## Arrays

- **Statische Arrays**: Haben eine feste Größe, die bei der Erstellung festgelegt wird, mit Elementen, die im zusammenhängenden Speicher abgelegt sind. Dieses benachbarte Layout ermöglicht schnellen, konstanten indexbasierten Zugriff (O(1)). Wählen Sie ein statisches Array, wenn die maximale Anzahl der Elemente im Voraus genau bekannt ist.

- **Dynamische Arrays**: Können sich während der Programmausführung automatisch vergrößern oder verkleinern. Wenn der Speicherplatz ausgeht, wird die Größe im Hintergrund angepasst, indem ein größerer Speicherblock zugewiesen und vorhandene Elemente kopiert werden.

**Hinweis:** Python hat kein traditionelles eingebautes statisches Array. Python-Listen sind dynamische Arrays.

### Python-Listen (dynamische Arrays)

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### Zeitkomplexitäten für dynamische Arrays

- **Zugriff**: O(1)

- **Einfügen am Ende**: Durchschnittlich O(1), O(n) bei notwendiger Größenanpassung

- **Einfügen in der Mitte**: O(n)

- **Löschen**: O(n) in der Mitte, O(1) am Ende

## Stacks

- **Stacks**: Last-In, First-Out (LIFO) Datenstruktur. Elemente werden nur oben hinzugefügt und entfernt.

- **Push-Operation**: Ein Element oben auf den Stack legen. Für die untenstehende Python-Listen-Implementierung benötigt ein gewöhnlicher Push O(1) Zeit und O(1) zusätzlichen Speicher. Ein Push, der eine Größenanpassung erfordert, kann O(n) Zeit und O(n) zusätzlichen Speicher benötigen.

- **Pop-Operation**: Ein Element vom oberen Ende des Stacks entfernen. Die Zeitkomplexität beträgt typischerweise O(1), und der zusätzliche Speicherbedarf ist normalerweise O(1).

```python
# Using Python list as stack
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operations
top_element = stack.pop()  # Returns 3
```

## Queues

- **Queues**: First-In, First-Out (FIFO) Datenstruktur, bei der Elemente hinten hinzugefügt und vorne entfernt werden.

- **Enqueue-Operation**: Ein Element hinten in die Queue einfügen. Zeitkomplexität: O(1), Speicherkomplexität: O(1).

- **Dequeue-Operation**: Ein Element vorne aus der Queue entfernen. Zeitkomplexität: O(1), Speicherkomplexität: O(1).

## Verkettete Listen

- **Verkettete Listen**: Lineare Datenstruktur, bei der jeder Knoten Daten und eine Referenz auf den nächsten Knoten enthält. Knoten sind wie eine Kette verbunden.

### Einfach verkettete Listen

- **Struktur**: Jeder Knoten enthält Daten und eine Referenz auf den nächsten Knoten.

- **Durchlauf**: Kann nur vorwärts vom Kopf bis zum Ende gehen.

- **Kopf-Knoten**: Erster Knoten in der Liste, normalerweise der einzige direkt zugängliche Knoten.

- **End-Knoten**: Letzter Knoten in der Liste, verweist auf `None`.

### Implementierung der verketteten Liste

- **Node-Klasse**: Eine verschachtelte `Node`-Klasse repräsentiert einzelne Knoten. Jeder Knoten enthält Daten und eine Referenz auf den nächsten Knoten.

- **Initialisierung**: Die `head`-Referenz startet als `None`, da die Liste keine Knoten hat. Die `next`-Referenz jedes neuen Knotens startet als `None`, da er noch keinen Nachfolger hat.

- **Längenverfolgung**: Eine Längenvariable hält die Anzahl der Knoten in der Liste fest.

- **`is_empty()`**: Prüft, ob die Liste leer ist, indem überprüft wird, ob `head` `None` ist.

- **Anhängen**: Vom Kopf aus bis zum letzten Knoten traversieren und dann dessen `next`-Referenz auf den neuen Knoten setzen. Ist die Liste leer, wird der neue Knoten zum Kopf.

```python
class LinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None

    def __init__(self):
        self.head = None
        self.length = 0

    def is_empty(self):
        return self.head is None

    def append(self, data):
        new_node = self.Node(data)

        if self.is_empty():
            self.head = new_node
        else:
            current = self.head

            while current.next:
                current = current.next

            current.next = new_node

        self.length += 1
```

### Operationen und Zeitkomplexitäten

- **Einfügen am Anfang**: O(1)

- **Einfügen am Ende**: O(n) – muss bis zum Ende traversieren

- **Einfügen in der Mitte**: O(n) – muss bis zur Position traversieren

- **Löschen vom Anfang**: O(1)

- **Löschen vom Ende**: O(n) – muss den vorherigen Knoten finden

- **Löschen aus der Mitte**: O(n) – muss den Knoten finden

### Einfügen und Löschen

- **Einfügen am Anfang**: Erstellen Sie einen neuen Knoten, setzen Sie dessen `next`-Referenz auf den aktuellen Kopf und aktualisieren Sie den Kopf, damit er auf den neuen Knoten zeigt.

- **Einfügen am Ende**: Traversieren Sie bis zum letzten Knoten und aktualisieren Sie dessen `next`-Referenz, damit sie auf den neuen Knoten zeigt.

- **Einfügen in der Mitte**: Traversieren Sie bis zum Knoten vor der gewünschten Position. Aktualisieren Sie die `next`-Referenz des neuen Knotens, damit sie auf den nächsten Knoten zeigt, und aktualisieren Sie dann die `next`-Referenz des vorherigen Knotens, damit sie auf den neuen Knoten zeigt.

- **Löschen vom Anfang**: Aktualisieren Sie den Kopf, damit er auf den zweiten Knoten zeigt.

- **Löschen vom Ende**: Traversieren Sie bis zum vorletzten Knoten und setzen Sie dessen `next`-Referenz auf `None`.

- **Löschen aus der Mitte**: Finden Sie den Knoten vor dem Zielknoten und aktualisieren Sie dessen `next`-Referenz, um den Zielknoten zu überspringen.

- **Löschen nach Wert**: Verfolgen Sie beim Traversieren den vorherigen Knoten. Ist das Ziel der Kopf, aktualisieren Sie den Kopf direkt. Wird der Wert nicht gefunden, kehren Sie zurück, ohne die Liste oder deren Länge zu ändern. Verringern Sie die Länge nur nach erfolgreichem Entfernen.

### Hilfsspeicher-Komplexitäten

- **Einfügen am Anfang**: O(1) Hilfsspeicher, ohne den Speicher für den neuen Knoten.

- **Einfügen am Ende**: O(1) Hilfsspeicher, ohne den Speicher für den neuen Knoten.

- **Einfügen in der Mitte**: O(1) Hilfsspeicher, ohne den Speicher für den neuen Knoten.

- **Löschen vom Anfang**: O(1) Hilfsspeicher.

- **Löschen vom Ende**: O(1) Hilfsspeicher.

- **Löschen aus der Mitte**: O(1) Hilfsspeicher.

### Doppelt verkettete Listen

- **Struktur**: Jeder Knoten hat Daten und zwei Referenzen: nächsten Knoten und vorherigen Knoten.

- **Durchlauf**: Kann in beide Richtungen gehen.

- **Speicher**: Benötigt mehr Speicher als einfach verkettete Listen wegen der zusätzlichen Referenz.

- **Endreferenz**: Die Pflege einer Referenz auf den letzten Knoten ermöglicht das Durchlaufen in umgekehrter Richtung über die vorherigen Referenzen.

## Hash-Maps und Sets

### Maps und Hash-Maps

- **Abstrakter Datentyp (ADT) vs. Implementierung**: Ein ADT definiert die *Schnittstelle* – welche Operationen eine Datenstruktur unterstützt und wie sie sich logisch verhält. Eine konkrete Implementierung definiert den Mechanismus im Hintergrund und zeigt, *wie* diese Operationen tatsächlich im Speicher ausgeführt werden.

- **Map (ADT)**: Ein abstrakter Datentyp, der eine Sammlung eindeutiger Schlüssel definiert, die auf Werte abgebildet werden. Er legt die Regeln fest, was eine Map tun kann, ohne die interne Speicherung vorzugeben.

- **Hash Map**: Eine konkrete Implementierung des Map-ADT, die eine Hashfunktion verwendet, um Speicherorte in einem zugrundeliegenden Array für schnelle Zugriffe zu berechnen.

### Python-Wörterbücher (Hash Maps)

```python
# Creating dictionaries
my_dictionary = {
    "A": 1,
    "B": 2,
    "C": 3
}

# Alternative creation
my_dictionary = dict(A=1, B=2, C=3)

# Access and modify
value = my_dictionary["A"]  # 1
my_dictionary["A"] = 4      # Update value
del my_dictionary["A"]      # Remove key-value pair

# Check membership
"C" in my_dictionary

# Get keys, values, items
my_dictionary.keys()
my_dictionary.values()
my_dictionary.items()
```

### Zeitkomplexitäten für Hash-Maps

- **Durchschnittlicher Fall**: O(1) für Einfügen, Abrufen, Löschen

- **Schlechtester Fall**: O(n), wenn viele Hash-Kollisionen auftreten

### Hilfsspeicher-Komplexitäten für Hash Maps

- **Einfügen**: O(1) zusätzlicher Speicher für gewöhnliches Einfügen. Größenanpassung kann O(n) zusätzlichen Speicher erfordern.

- **Nachschlagen**: O(1) Hilfsspeicher.

- **Löschen**: O(1) Hilfsspeicher.

### Sets

- **Sets**: Ungeordnete Sammlungen einzigartiger Elemente. Keine Duplikate erlaubt, keine bestimmte Reihenfolge.

- **Set-Elemente**: Sets können Zahlen, Strings und Tuples enthalten, die nur Zahlen und Strings enthalten. Listen, Dictionaries und andere Sets können keine Set-Elemente sein. Ein Tuple, das eine Liste enthält, kann kein Set-Element sein, obwohl das Tuple selbst unveränderlich ist.

```python
# Creating sets
numbers = {1, 2, 3, 4}
empty_set = set()  # Must use set(), not {}

# Add and remove elements
numbers.add(5)
numbers.remove(4)      # Raises KeyError if not found
numbers.discard(4)     # No error if not found

# Remove and return an arbitrary element
numbers.pop()

# Remove all elements
numbers.clear()

# Get the number of elements
len(numbers)
```

### Mengenoperationen

```python
set_a = {1, 2, 3, 4}
set_b = {2, 3, 4, 5, 6}

# Union, intersection, difference, symmetric difference
set_a.union(set_b)                  # or set_a | set_b
set_a.intersection(set_b)           # or set_a & set_b
set_a.difference(set_b)             # or set_a - set_b
set_a.symmetric_difference(set_b)   # or set_a ^ set_b

# Subset and superset checks
set_a.issubset(set_b)
set_a.issuperset(set_b)
set_a.isdisjoint(set_b)

# Membership testing
5 in numbers
```

### Zeitkomplexitäten für Sets

- **Durchschnittlicher Fall**: O(1) für Hinzufügen, Entfernen, Mitgliedschaftstest

- **Schlechtester Fall**: O(n) aufgrund von Hash-Kollisionen

- **Längenabfrage**: O(1) mit `len()`.

### Hilfsspeicher-Komplexitäten für Sets

- **Einfügen**: O(1) zusätzlicher Speicher für gewöhnliches Einfügen. Größenanpassung kann O(n) zusätzlichen Speicher erfordern.

- **Nachschlagen**: O(1) Hilfsspeicher.

- **Löschen**: O(1) Hilfsspeicher.

- **Längenabfrage**: O(1) Hilfsspeicher.

## Hash-Kollisionen

- **Hash-Kollision**: Verschiedene Schlüssel können denselben Hashwert erzeugen. In einer Hashtabelle treten Kollisionen auch auf, wenn verschiedene Hashwerte auf denselben Array-Index abgebildet werden. Einträge, die denselben Index teilen, müssen durch eine Kollisionsauflösungsstrategie behandelt werden.

- **Strategien zur Kollisionsauflösung**:

  - **Verkettung**: Jeder Array-Index zeigt auf eine verkettete Liste, die alle Einträge speichert, die auf denselben Bucket-Index abgebildet werden.

  - **Open Addressing**: Sucht bei einer Kollision nach dem nächsten verfügbaren Array-Index anhand einer vordefinierten Folge.

## Wann welche Datenstruktur verwenden

- **Listen**: Wenn Sie geordneten, indexierten Zugriff benötigen und die Größe nicht im Voraus kennen.

- **Stacks**: Für LIFO-Operationen (Rückgängig-Funktion, Ausdrucksauswertung, Backtracking).

- **Queues**: Für FIFO-Operationen (Aufgabenplanung, Breitensuche).

- **Verkettete Listen**: Wenn häufiges Einfügen/Löschen am Anfang, unbekannte Größe und kein zufälliger Zugriff benötigt wird.

- **Hash Maps**: Für schnelle Schlüssel-Wert-Suchen, Zählen von Vorkommen, Caching.

- **Sets**: Für Einzigartigkeitsprüfungen, mathematische Mengenoperationen, Entfernen von Duplikaten.
