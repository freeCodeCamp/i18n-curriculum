## Utangulizi wa programu ya mabadiliko

- **Maana**: Programu ya mabadiliko ya nguvu ni mbinu ya algoriti inayotatua matatizo magumu kwa kuyagawa kuwa matatizo madogo madogo na kuhifadhi matokeo ili kuepuka mahesabu ya kurudiarudia.
- **Matatizo Yanayojirudia**: Matatizo madogo madogo yanajitokeza mara nyingi wakati wa kutatua tatizo kubwa. Badala ya kuhesabu tena matatizo haya madogo, tunahifadhi suluhisho lao.
- **Muundo Bora wa Ndani**: Suluhisho bora la tatizo lina suluhisho bora za matatizo madogo madogo. Hii ina maana tunaweza kujenga suluhisho bora kwa kuunganisha suluhisho bora za sehemu ndogo.

## Tatizo la Kupanda Ngazi

Mfano wa kawaida wa programu ya mabadiliko ni kuhesabu njia tofauti za kufikia kilele cha ngazi yenye idadi ya hatua chanya `n`, ambapo kila hatua inaweza kupanda hatua 1 au 2:

- **Kurudia kwa Kawaida (Naive Recursion)**: Kwa sababu idadi ya njia za kufikia hatua `n` ni jumla ya njia za kufikia hatua `n - 1` na hatua `n - 2`, suluhisho la moja kwa moja la kurudia linahesabu tena matatizo madogo yanayofanana mara kwa mara. Kwa mfano, kuhesabu hatua ya `5` kunahesabu tena hatua ya `3` mara mbili na hatua ya `2` mara tatu. Hii husababisha ugumu wa wakati wa kiwango cha juu cha `O(2^n)` na nafasi ya `O(n)` kwenye orodha ya wito.

## Suluhisho za programu ya mabadiliko

Programu ya mabadiliko huondoa hesabu za kurudia kupitia mbinu kuu mbili:

- **Kumbukumbu (Mbinu ya Juu-Chini)**: Kumbukumbu huhifadhi matokeo ya wito za kitendakazi katika hifadhi (kama vile kamusi) na hurudisha matokeo yaliyohifadhiwa wakati tatizo dogo lile lile linapotokea tena:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

Kwa hifadhi iliyo wazi mwanzoni, kumbukumbu hupunguza ugumu wa wakati kuwa mstari `O(n)`, ikihitaji nafasi ya `O(n)` kuhifadhi matatizo madogo yaliyohifadhiwa pamoja na orodha ya wito za kurudia.

- **Jedwali (Mbinu ya Chini-Juu)**: Jedwali huondoa kurudia kwa kujenga suluhisho hatua kwa hatua kutoka matatizo madogo kabisa hadi lengo, huku ikihifadhi matokeo ya kati katika orodha:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

Jedwali hufanya kazi kwa wakati wa `O(n)` na hutumia nafasi ya `O(n)` kwa ajili ya orodha, na faida kuu ya kuepuka ukuaji wa orodha ya wito za kurudia.

- **Uboreshaji wa Jedwali kwa Nafasi ya Kudumu**: Kwa sababu kila hatua mpya inategemea tu thamani mbili za awali, jedwali zima linaweza kubadilishwa na vigezo viwili vinavyohifadhi hesabu mbili za mwisho:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

Kutumia kila operesheni ya kihesabu kama wakati wa kudumu na kila hesabu iliyohifadhiwa kama kitengo kimoja cha nafasi, uboreshaji huu unadumisha wakati wa `O(n)` huku ukipunguza ugumu wa nafasi ya ziada kuwa `O(1)`.

## Mfano wa vitendo: Tatizo la kubadilisha sarafu

Tatizo la kubadilisha sarafu ni tatizo la kawaida la uboreshaji linalouliza kuhusu idadi ya chini ya sarafu zinazohitajika kutengeneza kiasi kinacholengwa:

- **Algoriti**: Algoriti hutumia jedwali kwa kuunda safu ya data `dp` yenye ukubwa `amount + 1`, iliyoanzishwa kwa thamani isiyo na kikomo (`float('inf')`) kuwakilisha thamani zisizofikika mwanzoni. Kesi ya msingi ni `dp[0] = 0` kwa sababu sarafu sifuri zinahitajika kutengeneza kiasi cha `0`. Kwa kila kiasi `i` kutoka `1` hadi `amount`, algoriti hupunguza `dp[i - coin] + 1` kwa sarafu zote zinazostahili (`coin <= i`). Ikiwa `dp[amount]` bado ni isiyo na kikomo, kiasi kinacholengwa hakiwezi kutengenezwa, hivyo hurudisha `-1`:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

Kwa sarafu `[1, 3, 4]` na lengo `6`, algoriti huhesabu `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`, ikitoa mchanganyiko bora wa sarafu mbili (`3 + 3`).

- **Ugumu**: Algoriti huhakiki kila sarafu kwa kila kiasi kidogo hadi lengo, na kusababisha ugumu wa wakati wa `O(amount * number_of_coins)` na ugumu wa nafasi ya ziada wa `O(amount)` kwa safu ya data ya DP.

## Matumizi halisi ya programu zinazotumia dynamic programming

- **Uboreshaji wa njia ya data**: Mifumo ya GPS hutumia algoriti za dynamic programming kupata njia fupi zaidi kati ya maeneo.
- **Usindikaji wa maandishi**: Vipengele vya ukaguzi wa tahajia na kukamilisha maandishi mara nyingi hutegemea dynamic programming kuhesabu umbali wa mabadiliko kati ya maneno.
- **Uundaji wa mifano ya kifedha**: Mikakati ya uwekezaji na uboreshaji wa portfolio mara nyingi hutumia mbinu za dynamic programming.
- **Ugawaji wa rasilimali**: Tatizo la knapsack na aina zake huonekana katika upangaji wa ratiba, bajeti, na usimamizi wa rasilimali.
