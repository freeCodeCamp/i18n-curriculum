## Einführung in dynamische Programmierung

- **Definition**: Dynamische Programmierung ist eine algorithmische Technik, die komplexe Probleme löst, indem sie in einfachere Teilprobleme zerlegt und die Ergebnisse speichert, um redundante Berechnungen zu vermeiden.
- **Überlappende Teilprobleme**: Dieselben kleineren Probleme treten mehrfach auf, wenn das größere Problem gelöst wird. Statt diese Teilprobleme wiederholt zu berechnen, speichern wir ihre Lösungen.
- **Optimale Teilstruktur**: Die optimale Lösung des Problems enthält optimale Lösungen seiner Teilprobleme. Das bedeutet, wir können die beste Lösung aufbauen, indem wir die besten Lösungen für kleinere Teile kombinieren.

## Das Treppensteigen-Problem

Eine klassische Veranschaulichung von dynamischer Programmierung ist das Zählen der verschiedenen Möglichkeiten, die Spitze einer Treppe mit einer positiven Anzahl von Stufen `n` zu erreichen, wobei jeder Schritt entweder 1 oder 2 Stufen hochsteigen kann:

- **Naive Rekursion**: Da die Anzahl der Wege zur Stufe `n` die Summe der Wege zur Stufe `n - 1` und zur Stufe `n - 2` ist, berechnet eine direkte rekursive Lösung identische Teilprobleme wiederholt neu. Zum Beispiel wird bei der Berechnung der Stufe `5` die Stufe `3` zweimal und die Stufe `2` dreimal neu berechnet. Dies führt zu einer exponentiellen Zeitkomplexität von `O(2^n)` und einem Platzbedarf von `O(n)` im Aufrufstapel.

## Lösungen mit dynamischer Programmierung

Dynamische Programmierung beseitigt redundante Berechnungen durch zwei Hauptansätze:

- **Memoisierung (Top-Down-Ansatz)**: Memoisierung speichert die Ergebnisse von Funktionsaufrufen in einem Cache (wie einem Wörterbuch) und gibt das zwischengespeicherte Ergebnis zurück, wenn dasselbe Teilproblem erneut auftritt:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

Mit einem anfangs leeren Cache reduziert Memoisierung die Zeitkomplexität auf linear `O(n)` und benötigt `O(n)` Speicherplatz, um die zwischengespeicherten Teilprobleme neben dem rekursiven Aufrufstapel zu speichern.

- **Tabulation (Bottom-Up-Ansatz)**: Tabulation eliminiert die Rekursion, indem die Lösung iterativ von den kleinsten Teilproblemen bis zum Ziel aufgebaut wird und Zwischenergebnisse in einer Liste gespeichert werden:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

Tabulation läuft in `O(n)` Zeit und verwendet `O(n)` Speicherplatz für die Liste, mit dem entscheidenden Vorteil, dass das Wachstum des rekursiven Aufrufstapels vermieden wird.

- **Konstante-Speicher-Tabulationsoptimierung**: Da jeder neue Schritt nur von den vorherigen zwei Werten abhängt, kann die vollständige Tabelle durch zwei Variablen ersetzt werden, die die letzten beiden Zähler speichern:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

Wenn jede arithmetische Operation als konstante Zeit und jeder gespeicherte Zähler als eine Speichereinheit betrachtet wird, behält diese Optimierung die Zeitkomplexität von `O(n)` bei und reduziert die Hilfsspeicherkomplexität auf `O(1)`.

## Praktisches Beispiel: Münzwechselproblem

Das Münzwechselproblem ist ein klassisches Optimierungsproblem, bei dem die minimale Anzahl von Münzen ermittelt werden soll, die benötigt wird, um einen Zielbetrag zu erreichen:

- **Algorithmus**: Der Algorithmus verwendet Tabulation, indem er ein Array `dp` der Größe `amount + 1` erstellt, das mit Unendlichkeit (`float('inf')`) initialisiert wird, um zunächst unerreichbare Werte darzustellen. Der Basisfall ist `dp[0] = 0`, da für den Betrag `0` keine Münzen benötigt werden. Für jeden Betrag `i` von `1` bis `amount` minimiert der Algorithmus `dp[i - coin] + 1` über alle zulässigen Münzwerte (`coin <= i`). Wenn `dp[amount]` weiterhin unendlich bleibt, kann der Zielbetrag nicht gebildet werden, und es wird `-1` zurückgegeben:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

Für die Münzwerte `[1, 3, 4]` und das Ziel `6` berechnet der Algorithmus `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2` und liefert so eine optimale Kombination von zwei Münzen (`3 + 3`).

- **Komplexität**: Der Algorithmus prüft jede Münzdenomination für jeden Teilbetrag bis zum Ziel, was zu einer Zeitkomplexität von `O(amount * number_of_coins)` und einem Hilfsspeicherbedarf von `O(amount)` für das DP-Array führt.

## Anwendungen aus der Praxis mit dynamischer Programmierung

- **Routenoptimierung**: GPS-Systeme verwenden dynamische Programmieralgorithmen, um die kürzesten Wege zwischen Orten zu finden.
- **Textverarbeitung**: Rechtschreibprüfungen und Autovervollständigungsfunktionen basieren oft auf dynamischer Programmierung, um Editierabstände zwischen Wörtern zu berechnen.
- **Finanzmodellierung**: Anlagestrategien und Portfoliooptimierung nutzen häufig Techniken der dynamischen Programmierung.
- **Ressourcenzuweisung**: Das Rucksackproblem und seine Varianten treten bei der Terminplanung, Budgetierung und Ressourcenverwaltung auf.

## Wann dynamische Programmierung verwenden

Sie sollten dynamische Programmierung in den folgenden Fällen in Betracht ziehen:

- Das Problem lässt sich in sich überschneidende Teilprobleme zerlegen.
- Das Problem zeigt eine optimale Teilstruktur.
- Eine naive rekursive Lösung würde wiederholte Berechnungen erfordern.
- Sie müssen die Zeitkomplexität auf Kosten der Speicherkomplexität optimieren.
