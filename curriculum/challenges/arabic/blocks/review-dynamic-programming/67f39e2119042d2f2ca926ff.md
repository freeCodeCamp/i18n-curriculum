## مقدمة في البرمجة الديناميكية

- **التعريف**: البرمجة الديناميكية هي تقنية خوارزمية تحل المشكلات المعقدة بتقسيمها إلى مشكلات فرعية أبسط وتخزين النتائج لتجنب الحسابات المتكررة.
- **المشكلات الفرعية المتداخلة**: تظهر نفس المشكلات الصغيرة عدة مرات عند حل المشكلة الأكبر. بدلًا من إعادة حسابها، نخزن حلولها.
- **الهيكل الأمثل**: الحل الأمثل للمشكلة يحتوي على حلول مثلى لمشكلاتها الفرعية. هذا يعني أننا نبني أفضل حل بجمع أفضل الحلول للأجزاء الأصغر.

## مشكلة تسلق الدرج

مثال كلاسيكي على البرمجة الديناميكية هو حساب الطرق المختلفة للوصول إلى قمة درج يحتوي على عدد موجب من الخطوات `n`، حيث يمكن لكل حركة أن تصعد خطوة واحدة أو خطوتين:

- **التكرار البسيط**: لأن عدد الطرق للوصول إلى الخطوة `n` هو مجموع الطرق للوصول إلى الخطوة `n - 1` والخطوة `n - 2`، فإن الحل التكراري المباشر يعيد حساب نفس المشكلات الفرعية مرارًا وتكرارًا. على سبيل المثال، حساب الخطوة `5` يعيد حساب الخطوة `3` مرتين والخطوة `2` ثلاث مرات. هذا يؤدي إلى تعقيد زمني أسي بحد أعلى `O(2^n)` ومساحة مكدس استدعاء `O(n)`.

## حلول البرمجة الديناميكية

تُزيل البرمجة الديناميكية الحسابات المكررة من خلال نهجين رئيسيين:

- **التخزين المؤقت (النهج من الأعلى إلى الأسفل)**: يخزن التخزين المؤقت نتائج استدعاءات الدوال في مخزن مؤقت (مثل قاموس) ويُرجع النتيجة المخزنة عند مواجهة نفس المشكلة الفرعية مرة أخرى:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

مع وجود مخزن مؤقت فارغ في البداية، يقلل التخزين المؤقت التعقيد الزمني إلى خطي `O(n)`، ويتطلب مساحة `O(n)` لتخزين المشكلات الفرعية المخزنة إلى جانب مكدس الاستدعاء التكراري.

- **الجدولة (النهج من الأسفل إلى الأعلى)**: تلغي الجدولة التكرار من خلال بناء الحل تدريجيًا من أصغر المشكلات الفرعية حتى الهدف، مع تخزين النتائج الوسيطة في قائمة:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

تعمل الجدولة في زمن `O(n)` وتستخدم مساحة `O(n)` للقائمة، مع الميزة الأساسية في تجنب نمو مكدس الاستدعاء التكراري.

- **تحسين الجدولة بمساحة ثابتة**: لأن كل خطوة جديدة تعتمد فقط على القيمتين السابقتين، يمكن استبدال الجدول الكامل بمتغيرين يخزنان آخر عددين:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

مع اعتبار كل عملية حسابية زمنها ثابت وكل عدد مخزن وحدة واحدة من المساحة، يحتفظ هذا التحسين بزمن `O(n)` مع تقليل تعقيد المساحة المساعدة إلى `O(1)`.

## مثال عملي: مشكلة تبديل العملات

مشكلة تبديل العملات هي مشكلة تحسين كلاسيكية تطلب الحد الأدنى من عدد العملات اللازمة لتكوين مبلغ مستهدف:

- **الخوارزمية**: تستخدم الخوارزمية طريقة الجدولة بإنشاء مصفوفة `dp` بحجم `amount + 1`، مهيأة بقيمة اللانهاية (`float('inf')`) لتمثيل القيم التي لا يمكن الوصول إليها في البداية. الحالة الأساسية هي `dp[0] = 0` لأنك لا تحتاج إلى أي عملات لصنع مبلغ `0`. لكل مبلغ `i` من `1` إلى `amount`، تقلل الخوارزمية من قيمة `dp[i - coin] + 1` عبر جميع فئات العملات المؤهلة (`coin <= i`). إذا بقيت قيمة `dp[amount]` تساوي اللانهاية، فهذا يعني أنه لا يمكن تكوين المبلغ المطلوب، لذا تُرجع `-1`:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

لفئات العملات `[1, 3, 4]` والهدف `6`، تحسب الخوارزمية `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`، منتجة تركيبة مثلى من عملتين (`3 + 3`).

- **التعقيد**: تتحقق الخوارزمية من كل فئة عملة لكل مبلغ فرعي حتى الهدف، مما يؤدي إلى تعقيد زمني `O(amount * number_of_coins)` وتعقيد مساحة مساعدة `O(amount)` لمصفوفة البرمجة الديناميكية.

## تطبيقات العالم الحقيقي باستخدام البرمجة الديناميكية

- **تحسين المسارات**: تستخدم أنظمة GPS خوارزميات البرمجة الديناميكية لإيجاد أقصر المسارات بين المواقع.
- **معالجة النصوص**: تعتمد أدوات التدقيق الإملائي والإكمال التلقائي غالبًا على البرمجة الديناميكية لحساب مسافات التحرير بين الكلمات.
- **النمذجة المالية**: تستخدم استراتيجيات الاستثمار وتحسين المحافظ تقنيات البرمجة الديناميكية بشكل متكرر.
- **تخصيص الموارد**: تظهر مشكلة حقيبة الظهر ومتغيراتها في الجدولة والميزانية وإدارة الموارد.
