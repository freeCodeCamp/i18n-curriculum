## Suchalgorithmen

- **Zweck**: Suchalgorithmen ermöglichen es Ihnen, nach einem Ziel in einer Liste von Elementen zu suchen.
- **Arten von Suchalgorithmen**: Zwei gängige Suchalgorithmen sind Linear Search und Binary Search. Das Verständnis ihrer Unterschiede hilft Ihnen zu entscheiden, wann Sie welchen verwenden sollten.

### Lineare Suche

- **Linear Search Algorithmus**: Iteriert durch eine Liste von Elementen und überprüft jedes Element von Anfang an, bis das Ziel gefunden wird.
- **Erfolgreiche Suche**: Wenn das Zielobjekt gefunden wird, wird der Index zurückgegeben, an dem es sich in der Liste befindet.
- **Erfolglos Suche**: Die Vorlesungsimplementierungen geben `-1` zurück, um anzuzeigen, dass das Ziel nicht gefunden wurde. In Python indiziert `-1` auch das letzte Element einer nicht-leeren Liste, daher prüfen Sie, ob das Ergebnis `-1` ist, bevor Sie es als Index verwenden. Andernfalls könnte eine erfolglose Suche versehentlich das letzte Element zurückgeben.
- **Effizienz**: Da Linear Search jedes Element nacheinander überprüft, kann es bei großen Listen ineffizient sein.
- **Zeitkomplexität**: `O(n)`, weil die benötigte Zeit linear mit der Größe der Liste wächst.
- **Speicherkomplexität**: `O(1)`, weil eine konstante Menge zusätzlichen Speichers unabhängig von der Eingabegröße verwendet wird.

### Binäre Suche

- **Binary-Search-Algorithmus**: Ein effizienter Suchalgorithmus, der eine sortierte Liste wiederholt in Hälften teilt, um einen Zielwert zu finden.
- **Voraussetzung für sortierte Eingabe**: Binary Search erfordert, dass die Eingabeliste in aufsteigender Reihenfolge sortiert ist.
- **Initialisierung des Suchbereichs**: Initialisieren Sie `low = 0` als Index des ersten Elements und `high = len(arr) - 1` als Index des letzten Elements. Diese Variablen definieren den eingeschlossenen Bereich, der durchsucht wird.
- **Bedingung für die Fortsetzung der Suche**: Führen Sie die Suche fort, solange `low <= high` gilt. Wenn `low > high` ist, ist der Suchbereich leer, was bedeutet, dass das Ziel nicht gefunden wurde.
- **Berechnung des Mittelpunkts**: Berechnen Sie den mittleren Index mit ganzzahliger Division: `mid = (low + high) // 2`.
- **Vergleich mit dem Zielwert**: Vergleichen Sie den Zielwert mit `arr[mid]`. Wenn sie gleich sind, wurde das Ziel am Index `mid` gefunden.
- **Aktualisierung der unteren Grenze**: Wenn `arr[mid] < target` gilt, muss sich das Ziel, falls es in der Liste existiert, in der rechten Hälfte befinden. Aktualisieren Sie `low = mid + 1`, um den Mittelpunkt und alle Elemente davor auszuschließen.
- **Aktualisierung der oberen Grenze**: Wenn `arr[mid] > target` gilt, muss sich das Ziel, falls es in der Liste existiert, in der linken Hälfte befinden. Aktualisieren Sie `high = mid - 1`, um den Mittelpunkt und alle Elemente danach auszuschließen.
- **Erfolgreiche Suche in der Vorlesung**: Die Vorlesungsimplementierung gibt den Index des Ziels zurück, wenn es gefunden wird.
- **Erfolglos Suche in der Vorlesung**: Die Vorlesungsimplementierung gibt `-1` zurück, wenn der Suchbereich leer wird.
- **Pfadverfolgung im Workshop**: Die Workshop-Implementierung initialisiert eine leere Liste `path_to_target` und fügt bei jeder besuchten Mitte während der Suche den Wert hinzu.
- **Erfolgreiche Suche im Workshop**: Wenn das Ziel gefunden wird, gibt der Workshop ein Tuple zurück, das `path_to_target` und eine Nachricht mit dem Index enthält, an dem das Ziel gefunden wurde.
- **Workshop erfolglose Suche**: Wenn der Suchbereich leer wird, gibt der Workshop eine leere Liste und die Meldung `"Value not found"` zurück.
- **Zeitkomplexität**: `O(log n)`, weil der Suchbereich nach jedem Vergleich ungefähr halbiert wird.
- **Speicherkomplexität**: Die Vorlesungsimplementierung verwendet `O(1)` Hilfsspeicher für Variablen wie `low`, `high` und `mid`. Die Workshop-Implementierung verwendet `O(log n)` Hilfsspeicher, da `path_to_target` die während der Suche besuchten Mittelpunktwerte speichert.

### Wie sich die lineare Suche von der binären Suche unterscheidet

- **Voraussetzungen**: Linear Search benötigt keine sortierte Liste, während Binary Search die Eingabedaten aufsteigend sortiert voraussetzt.
- **Skalierbarkeit**: Binary Search eignet sich besser für große Listen von Elementen als Linear Search.
- **Vergleich der Zeitkomplexität**: Linear Search hat eine Zeitkomplexität von `O(n)`, während Binary Search eine Zeitkomplexität von `O(log n)` hat.

## Sortieralgorithmen und Divide-and-Conquer

- **Divide-and-Conquer**: Eine Technik, um ein Problem in kleinere Teilprobleme zu zerlegen, damit sie leichter zu lösen sind. Rekursion wird oft verwendet, um diesen Ansatz zu implementieren, der häufig in effizienten Sortieralgorithmen wie Merge Sort eingesetzt wird.

### Merge Sort

- **Merge Sort Algorithmus**: Ein Sortieralgorithmus, der dem Divide-and-Conquer-Ansatz folgt.
- **Basisfall**: Listen mit null oder einem Element sind bereits sortiert, daher endet die Rekursion, wenn `len(array) <= 1`.
- **Aufteilen der Liste**: Teilen Sie die Liste in zwei geschnittene Hälften und sortieren Sie jede Hälfte rekursiv.
- **Zusammenführen der Teil-Listen**: Vergleichen Sie die nächsten nicht zusammengeführten Elemente der beiden sortierten Hälften, kopieren Sie das kleinere Element an die nächste Ausgabeposition und erhöhen Sie dessen Index. Sobald eine Hälfte erschöpft ist, kopieren Sie alle verbleibenden Elemente der anderen Hälfte.
- **Workshop-Implementierung**: Der Workshop erstellt geschnittene Hälften und schreibt die zusammengeführten Werte zurück in die ursprüngliche Liste, wobei `sorted_index` nach jedem Schreiben erhöht wird. Das Ändern der ursprünglichen Liste macht dies nicht zu einem In-Place-Sortieralgorithmus, da die geschnittenen Hälften zusätzlichen Speicher benötigen.
- **Zeitkomplexität**: `O(n log n)`, weil die Liste wiederholt in Hälften geteilt wird (`log n` Ebenen) und das Zusammenführen der Elemente auf jeder Ebene `O(n)` Zeit benötigt.
- **Speicherkomplexität**: `O(n)`, weil Merge Sort zusätzlichen Speicher benötigt, um die Teil-Listen zusammenzuführen, und kein In-Place-Sortieralgorithmus ist.
