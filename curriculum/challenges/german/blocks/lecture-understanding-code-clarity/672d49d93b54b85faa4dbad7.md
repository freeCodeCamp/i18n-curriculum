# --description--

So wie ein Punkt (`.`) das Ende eines Satzes im Englischen markieren kann, kann ein Semikolon (`;`) verwendet werden, um das Ende einer Anweisung in JavaScript zu kennzeichnen. Allerdings sind Anweisungen nicht unbedingt dasselbe wie Zeilen im Quellcode. Eine Anweisung kann sich über mehrere Zeilen erstrecken, und eine einzelne Zeile kann mehr als eine Anweisung enthalten.

Zum Beispiel:

```js
let variableOne = 5;
let variableTwo = 10;
```

In diesem Code machen die Semikolons das Ende jeder Anweisung explizit. JavaScript verfügt außerdem über die automatische Semikolon-Einfügung (Automatic Semicolon Insertion, ASI), die es erlaubt, dass diese Deklarationen auch ohne explizite Semikolons gültig bleiben:

```js
let variableOne = 5
let variableTwo = 10
```

In diesem Beispiel erlaubt ASI JavaScript, jede Deklaration als separate Anweisung zu behandeln, obwohl keine Semikolons vorhanden sind. ASI fügt jedoch nicht einfach nach jedem Zeilenumbruch ein Semikolon ein.

Zum Beispiel kann ein Zeilenumbruch nach einer `return`-Anweisung unerwartetes Verhalten verursachen:

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

Hier fügt ASI nach `return` ein Semikolon ein, sodass die Funktion `undefined` zurückgibt statt des Objekts. Wenn das Objekt in derselben Zeile geschrieben wird, wird dieses Verhalten vermieden:

```js
function getValue() {
  return {
    value: 42
  };
}
```

Dies zeigt, warum Zeilenumbrüche und Anweisungsgrenzen nicht immer dasselbe sind.

Semikolons können auch nützlich sein, wenn ein Zeilenumbruch sonst dazu führen könnte, dass zwei Codeabschnitte als ein Ausdruck interpretiert werden. Ein sofort aufgerufener Funktionsausdruck (Immediately Invoked Function Expression, IIFE) ist eine Funktion, die sofort ausgeführt wird, sobald sie definiert ist. Eine Möglichkeit, ein IIFE zu erstellen, besteht darin, eine anonyme Funktion, also eine Funktion ohne Namen, in runde Klammern zu setzen und am Ende `()` hinzuzufügen, um sie aufzurufen. Ein IIFE kann ein Problem verursachen, wenn die vorherige Anweisung nicht mit einem Semikolon endet:

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

Hier fügt JavaScript nach der String-Deklaration kein Semikolon ein, weil die folgende `(` den Initialisierer-Ausdruck fortsetzen kann. JavaScript parst den Initialisierer als Aufruf des Strings `"Hello"`, wobei der Funktionsausdruck als Argument dient. Dies wirft einen `TypeError`, bevor das IIFE ausgeführt werden kann. Ein Semikolon am Ende beendet die Deklaration vor dem IIFE:

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

Das explizite Semikolon hält die Variablendeklaration und das IIFE als separate Anweisungen getrennt.

Semikolons werden in vielen Programmiersprachen verwendet, darunter C, C++ und Java. Die genauen Regeln variieren zwischen den Sprachen, aber sie helfen allgemein dabei, das Ende von Anweisungen zu kennzeichnen.

Ein Compiler übersetzt Quellcode in eine andere Form, wie Maschinencode, Bytecode oder eine Zwischenrepräsentation, abhängig von Sprache und Compiler. Die Kompilierung erzeugt nicht unbedingt eine eigenständige ausführbare Datei.

Die konsequente Verwendung von Semikolons kann Anweisungsgrenzen klarer machen und den Code leichter lesbar und wartbar gestalten.
