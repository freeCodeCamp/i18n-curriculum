# --description--

La gestione degli eventi è una parte essenziale di ogni sito web interattivo.

React offre un modo potente e coerente per gestire gli eventi tramite il suo Synthetic Event System, che è un involucro attorno agli eventi nativi come `click`, `keydown` e `submit` che hai imparato nelle lezioni precedenti.

Questo involucro cross-browser garantisce che gli eventi funzionino allo stesso modo su tutti i browser, evitando incongruenze.

Vediamo come funzionano gli eventi in React così puoi iniziare a usarli nei tuoi progetti.

## Come gli eventi di React differiscono dagli eventi HTML

In React, i gestori di eventi funzionano in modo simile agli eventi nativi del browser, ma con qualche modifica.

Invece di usare nomi di attributi evento in minuscolo come `onclick` e `onsubmit`, React usa camelCase, come `onClick` e `onSubmit`.

Inoltre, invece di usare stringhe per specificare il tipo di evento, React si aspetta una funzione come gestore dell’evento.

La funzione gestore viene passata all’elemento come prop, e il tipo di evento come `onClick` o `onSubmit` viene usato come attributo in JSX.

## Scrivere un gestore di eventi

Ecco un promemoria di come si lavora con un evento click in HTML normale:

```html
<button onclick="alert('Button clicked!')">Click Me</button>
```

Ecco invece come si fa la stessa cosa in React:

```jsx
function handleClick() {
  console.log("Button clicked!");
}

<button onClick={handleClick}>Click Me</button>;
```

In questo esempio, `handleClick` stampa un messaggio nella console quando l’utente clicca il pulsante.

Nota che non servono le parentesi tonde dopo `handleClick` nell’attributo `onClick`, perché stai passando un riferimento alla funzione, non la stai chiamando.

In React, le funzioni gestore di eventi solitamente iniziano con il prefisso `handle` per indicare che si occupano di gestire eventi, come `handleClick` o `handleSubmit`.

## L'oggetto evento sintetico

Quando un’azione dell’utente attiva un evento, React passa un oggetto Synthetic Event al tuo gestore. Questo oggetto si comporta molto come l’oggetto evento nativo in JavaScript vanilla, fornendo proprietà come `type`, `target` e `currentTarget`.

Puoi passare `event` come parametro alla funzione gestore e stamparlo nella console per vedere la sua struttura:

```js
function handleClick(event) {
  console.log(event);
}
```

## Prevenire il comportamento predefinito e la propagazione

Per evitare comportamenti predefiniti come l'aggiornamento del browser durante un evento `onSubmit`, ad esempio, puoi chiamare il metodo `preventDefault()`:

```jsx
function handleSubmit(event) {
  event.preventDefault();
  console.log("Form submitted!");
}

<form onSubmit={handleSubmit}>
  <input type="text" />
  <button>Submit</button>
</form>;
```

Puoi anche fermare la propagazione di un evento verso gli elementi genitori chiamando `event.stopPropagation()`.

## Passare dati ai gestori di eventi

A volte, mentre gestisci casi speciali come funzionalità di eliminazione e modifica, potresti voler passare dati extra a un gestore di eventi. Puoi farlo racchiudendo il gestore in una funzione freccia in linea:

```jsx
function handleDelete(id) {
  console.log("Deleting item:", id);
}

<button onClick={() => handleDelete(1)}>Delete Item</button>;
```

Va bene usare gestori di eventi in linea in React perché React gestisce in modo efficiente i re-render evitando problemi di prestazioni.

In JavaScript vanilla, i gestori di eventi in linea possono causare problemi di prestazioni creando nuove funzioni a ogni render, dato che non esiste un DOM virtuale che ottimizza il processo.
