# --description--

このワークショップでは、タプルを使ってアプリがアップデートを必要としているかどうかをチェックするプログラムを作りながら練習します。

ソフトウェアの各リリースにはバージョン番号が付けられ、リリースを区別してどちらが新しいかを判断できるようになっています。一般的な慣例として、3つの数字をドットで区切った形式 `MAJOR.MINOR.PATCH` が使われます：

- `MAJOR` は、古いコードやファイルが新しいバージョンで動かなくなるかもしれない大きな変更があったときに上がります。
- `MINOR` は、新しい機能が追加されても以前のものと互換性がある場合に上がります。
- `PATCH` は、新機能を追加しない小さな修正、例えばバグ修正があったときに上がります。

`2.1.0` のようなバージョンは、3つの整数のタプルとして保存できます：メジャー、マイナー、パッチの番号です。

`releases` という変数を作成し、以下のバージョンタプルをこの順番で含むタプルを代入してください：

```py
(1, 9, 0), (2, 0, 0), (1, 9, 1), (2, 1, 0),
(2, 1, 1), (2, 2, 0), (1, 9, 2), (2, 2, 1)
```

リリースは公開された順に並んでおり、バージョンの低い順から高い順ではありません。古い `1.9` 系列は、`2.0.0` バージョンが出た後も修正が続けられていました。
