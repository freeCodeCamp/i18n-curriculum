## Algoritmos de búsqueda

- **Propósito**: Los algoritmos de búsqueda te permiten buscar un objetivo dentro de una lista de elementos.
- **Tipos de algoritmos de búsqueda**: Dos algoritmos de búsqueda comunes son la búsqueda lineal y la búsqueda binaria. Entender sus diferencias ayuda a determinar cuándo usar cada uno.

### Búsqueda Lineal

- **Algoritmo de búsqueda lineal**: Itera a través de una lista de elementos, revisando cada elemento desde el principio hasta encontrar el objetivo.
- **Búsqueda exitosa**: Si se encuentra el elemento objetivo, se devuelve el índice donde está ubicado en la lista.
- **Búsqueda no exitosa**: Las implementaciones de la clase devuelven `-1` para indicar que no se encontró el objetivo. En Python, `-1` también indexa el último elemento de una lista no vacía, así que verifica si el resultado es `-1` antes de usarlo como índice. De lo contrario, una búsqueda no exitosa podría recuperar el último elemento por error.
- **Eficiencia**: Como la búsqueda lineal revisa cada elemento secuencialmente, puede ser ineficiente para listas grandes.
- **Complejidad temporal**: `O(n)` porque el tiempo requerido para buscar crece linealmente con el tamaño de la lista.
- **Complejidad espacial**: `O(1)` porque usa una cantidad constante de espacio adicional sin importar el tamaño de la entrada.

### Búsqueda Binaria

- **Algoritmo de búsqueda binaria**: Un algoritmo de búsqueda eficiente que divide repetidamente una lista ordenada en mitades para encontrar un valor objetivo.
- **Requisito de entrada ordenada**: La búsqueda binaria requiere que la lista de entrada esté ordenada en orden ascendente.
- **Inicialización del rango de búsqueda**: Inicializa `low = 0` como el índice del primer elemento y `high = len(arr) - 1` como el índice del último elemento. Estas variables definen el rango inclusivo que se está buscando.
- **Condición para continuar la búsqueda**: Continúa buscando mientras `low <= high`. Si `low > high`, el rango de búsqueda está vacío, lo que significa que no se encontró el objetivo.
- **Cálculo del punto medio**: Calcula el índice medio usando división entera: `mid = (low + high) // 2`.
- **Comparación con el objetivo**: Compara el valor objetivo con `arr[mid]`. Si son iguales, el objetivo se ha encontrado en el índice `mid`.
- **Actualización del límite inferior**: Si `arr[mid] < target`, el objetivo debe estar en la mitad derecha si existe en la lista. Actualiza `low = mid + 1` para excluir el punto medio y todos los elementos anteriores.
- **Actualización del límite superior**: Si `arr[mid] > target`, el objetivo debe estar en la mitad izquierda si existe en la lista. Actualiza `high = mid - 1` para excluir el punto medio y todos los elementos posteriores.
- **Búsqueda exitosa en la clase**: La implementación de la clase devuelve el índice del objetivo cuando se encuentra.
- **Búsqueda fallida en la clase**: La implementación de la clase devuelve `-1` cuando el rango de búsqueda queda vacío.
- **Seguimiento del camino en el taller**: La implementación del taller inicializa una lista vacía `path_to_target` y añade el valor de cada punto medio visitado durante la búsqueda.
- **Búsqueda exitosa en el taller**: Cuando se encuentra el objetivo, el taller devuelve una tupla que contiene `path_to_target` y un mensaje que indica el índice donde se encontró el objetivo.
- **Búsqueda fallida en el taller**: Cuando el rango de búsqueda queda vacío, el taller devuelve una lista vacía y un mensaje de `"Value not found"`.
- **Complejidad temporal**: `O(log n)` porque el rango de búsqueda se reduce aproximadamente a la mitad después de cada comparación.
- **Complejidad espacial**: La implementación de la clase usa espacio auxiliar `O(1)` para variables como `low`, `high` y `mid`. La implementación del taller usa espacio auxiliar `O(log n)` porque `path_to_target` almacena los valores de los puntos medios visitados durante la búsqueda.

### Cómo la búsqueda lineal difiere de la búsqueda binaria

- **Requisitos previos**: La búsqueda lineal no requiere una lista ordenada, mientras que la búsqueda binaria requiere que los datos de entrada estén ordenados en orden ascendente.
- **Escalabilidad**: La búsqueda binaria es más adecuada para listas grandes de elementos en comparación con la búsqueda lineal.
- **Comparación de complejidad temporal**: La búsqueda lineal tiene una complejidad temporal de `O(n)`, mientras que la búsqueda binaria tiene una complejidad temporal de `O(log n)`.

## Algoritmos de ordenamiento y divide y vencerás

- **Divide y vencerás**: Una técnica usada para descomponer un problema en subproblemas más pequeños para que sean más fáciles de resolver. La recursión se usa a menudo para implementar este enfoque, que es común en algoritmos de ordenación eficientes como Merge Sort.

### Ordenamiento por mezcla

- **Algoritmo de Merge Sort**: Un algoritmo de ordenación que sigue el enfoque de divide y vencerás.
- **Caso base**: Las listas con cero o un elemento ya están ordenadas, por lo que la recursión se detiene cuando `len(array) <= 1`.
- **Dividir la lista**: Divide la lista en dos mitades cortadas y ordena recursivamente cada mitad.
- **Fusionar las sublistas**: Compara los siguientes elementos no fusionados de las dos mitades ordenadas, copia el elemento más pequeño en la siguiente posición de salida y avanza su índice. Una vez que una mitad se agota, copia todos los elementos restantes de la otra mitad.
- **Implementación del taller**: El taller crea mitades cortadas y escribe los valores fusionados de nuevo en la lista original, avanzando `sorted_index` después de cada escritura. Modificar la lista original no convierte esto en un algoritmo de ordenación en el lugar porque las mitades cortadas requieren almacenamiento adicional.
- **Complejidad temporal**: `O(n log n)` porque la lista se divide repetidamente en mitades (`log n` niveles), y fusionar los elementos en cada nivel toma tiempo `O(n)`.
- **Complejidad espacial**: `O(n)` porque Merge Sort requiere memoria adicional para fusionar las sublistas y no es un algoritmo de ordenación en el lugar.
