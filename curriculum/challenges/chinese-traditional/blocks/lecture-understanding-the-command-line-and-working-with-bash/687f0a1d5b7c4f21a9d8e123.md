# --description--

讓我們來了解你的系統語言和鍵盤設定如何影響 Bash 和 PostgreSQL 工作坊。

許多程式設計工具期望命令使用標準英文鍵盤字元。在 Bash 和 PostgreSQL 工作坊中，這對於分號（`;`）、引號、斜線和其他特殊字元尤其重要。

如果你的作業系統或鍵盤配置使用非英文語言設定，有些字元可能會與預期不同，這可能導致輸入 SQL 命令或終端機命令時出現令人困惑的錯誤。

為了在進行這些工作坊時獲得最佳體驗，建議在完成課程期間暫時切換到英文（美國）鍵盤配置。當 Bash 或 PostgreSQL 的命令在輸入像 `;` 或 `\` 這類符號時產生意外字元或語法錯誤，這尤其有幫助。

GitHub Codespaces 使用你本地的鍵盤配置，因此在你自己的電腦上更改配置也會影響 Codespaces 中的輸入。

在 Windows 上：

1. 開啟 **設定** > **時間與語言** > **語言與地區**
2. 如果尚未安裝，新增 **English (United States)**
3. 在鍵盤配置下，選擇 **US** 鍵盤
4. 如有需要，將 US 鍵盤配置移至列表頂端

在 macOS 上：

1. 開啟 **系統設定** > **鍵盤** > **輸入來源**
2. 新增 **English (US)** 鍵盤配置
3. 確認 US 配置為作用中的鍵盤

在 Ubuntu、Debian 或 Mint 等 Linux 發行版上：

1. 開啟系統鍵盤設定
2. 新增 **English (US)** 鍵盤配置
3. 如可能，將其移至鍵盤配置列表頂端

某些 Linux 系統也允許從終端機檢查和更改鍵盤配置。首先，檢查你目前的配置：

```bash
setxkbmap -query
```

然後切換到 US 配置：

```bash
setxkbmap us
```

切換配置後，在文字框或終端機中測試以下字元：

```md
; : / \ | ' " $ { } [ ] ( )
```

如果符號顯示正確，表示你的鍵盤配置很可能已正確組態。

某些非英文配置將像 `'` 和 `"` 這類字元視為死鍵，意即它們會等待後續按鍵而非立即輸入。切換到 US 配置後，這些字元應該會立即輸入。如果字元仍無法立即出現，表示你的配置尚未完全切換。

如果你使用非美式實體鍵盤配置，例如 AZERTY、QWERTZ 或區域性 QWERTY 變體，符號鍵可能位於不同的實體位置。在這種情況下，切換到 US 配置後，請使用作業系統的螢幕鍵盤或鍵盤檢視器來尋找像 `;`、`/`、`\`、`|`、`'` 和 `"` 這些鍵。

使用英文（美國）鍵盤配置有助於確保 Bash 和 PostgreSQL 命令在整個工作坊中完全符合預期行為。

完成工作坊後，你可以切換回原本的鍵盤配置。
