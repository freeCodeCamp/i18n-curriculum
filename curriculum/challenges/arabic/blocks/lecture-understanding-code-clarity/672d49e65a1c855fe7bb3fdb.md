# --description--

تُستخدم التعليقات في البرمجة لتوفير سياق إضافي للكود أو لترك ملاحظات لنفسك وللآخرين.

التعليقات هي أسطر أو كتل من النص يتجاهلها محرك JavaScript عند تنفيذ الكود. وجودها فقط لفائدة الأشخاص الذين يقرؤون الكود، سواء كنت أنت أو شخصًا آخر.

يوفر JavaScript طريقتين لإضافة التعليقات إلى كودك: التعليقات ذات السطر الواحد والتعليقات متعددة الأسطر.

يتم إنشاء تعليقات السطر الواحد باستخدام شرطتين مائلتين للأمام (`//`). إليك مثالًا:

```js
// I am a single line comment in JavaScript
```

هذا النوع من التعليقات مناسب للتفسيرات أو التوضيحات القصيرة.

إليك مثالًا من ملفات مشروع منهج freeCodeCamp في العالم الحقيقي:

```js
// This is to allow English to build without having to download the i18n files.
// It fails when trying to resolve the i18n-curriculum path if they don't exist.
const curriculumLocale = process.env.CURRICULUM_LOCALE ?? 'english';
const I18N_CURRICULUM_DIR = path.resolve(
  __dirname,
  curriculumLocale === 'english' ? '.' : 'i18n-curriculum/curriculum'
);
```

لا تقلق بشأن محاولة فهم ما يفعله الكود فعليًا لأنه أكثر تقدمًا مما تعلمته حتى الآن. بدلًا من ذلك، ركز على التعليق الذي تركه المطوِّر. هذا التعليق يوفر سياقًا مهمًا لسبب وجود هذا الكود.

التعليقات مثل هذه مهمة لمن يعملون ضمن فرق لسببين:

1. المطوِّرون الآخرون الذين يعملون على المشروع سيفهمون هدف هذا الكود.

1. تساعد على منع التغييرات أو الحذف غير الضروري دون استشارة الفريق، مما قد يؤدي إلى أخطاء برمجية أو مشاكل.

نوع آخر من التعليقات هو تعليقات متعددة الأسطر. إليك الصيغة النحوية الأساسية:

```js
/*
 I am a multiline comment.
 This is helpful for longer explanations.
*/
```

التعليقات متعددة الأسطر مفيدة عندما تحتاج إلى كتابة أوصاف أو شروحات أو ملاحظات أطول في كودك.

لنلق نظرة أخرى على ملفات مشروع منهج freeCodeCamp لنرى كيف يمكن استخدام التعليقات متعددة الأسطر في العالم الحقيقي.

```js
/* Since there can be more than one way to complete a certification (using the
legacy curriculum or the new one, for instance), we need a certification
field to track which certification this belongs to. */
const dupeCertifications = [
  {
    certification: 'responsive-web-design',
    dupe: '2022/responsive-web-design'
  }
];
const hasDupe = dupeCertifications.find(
  cert => cert.dupe === meta.superBlock
);
```

كما في السابق، تجاهل كل كود JavaScript لأنه يستخدم مفاهيم لم تُدرّس بعد. بدلًا من ذلك، ركز على التعليق الذي تركه المطوِّر.

يمكن لمطوِّر في الفريق، أو حتى مساهم جديد يعمل على المشروع، أن يفهم سبب وجود هذا الجزء من الكود وأن يحصل على السياق الكامل قبل العمل على هذه المساحة من المشروع.

بينما التعليقات مفيدة في البرمجة، من المهم تجنب الإفراط في التعليق. لا تحتاج إلى التعليق على كل سطر من الكود، خاصة إذا كان الكود واضحًا ومفهومًا بذاته.

إليك مثالًا على استخدام التعليقات لشرح ما هو واضح:

```js
// This code uses the const keyword to create a new variable called price.
// We are assigning the number 10 to the price variable.
const price = 10;
```

في هذا الموقف، لا حاجة لإضافة أي تعليقات هنا لأن الكود واضح بذاته. الهدف هو تحسين قابلية القراءة، وليس إرباك الكود بتفسيرات غير ضرورية.

إذا أردت إضافة تعليقات إلى مشاريعك الشخصية أثناء تعلمك البرمجة، فهذا جيد. لكن بمجرد أن تبدأ العمل على مشاريع حقيقية مع مطوِّرين آخرين، من المهم عدم استخدام التعليقات للكود الواضح بذاته.

من المهم أيضًا عدم استخدام التعليقات لتبرير كود معقد أو مربك أو مكتوب بشكل سيئ. في هذه الحالات، من الأفضل إعادة هيكلة الكود أو تغييره حتى يفهمه المطوِّرون الآخرون بشكل أفضل.

التعليقات أدوات قوية لتوثيق كودك وجعله أسهل في الفهم. يجب أن تستخدم التعليقات لتوفير السياق أو لترك ملاحظات لنفسك وللآخرين.
