## مكتبات وأُطُر جافاسكريبت

- تقدم مكتبات وأُطُر جافاسكريبت حلولًا سريعة للمشاكل الشائعة وتسريع التطوير من خلال توفير كود مُسبق البناء.
- تركز المكتبات عادةً على تقديم حلول لمهام محددة، مثل التلاعب بـ DOM، التعامل مع الأحداث، أو إدارة طلبات AJAX.
- من أمثلة مكتبات جافاسكريبت jQuery و React.
- من ناحية أخرى، توفر الأُطُر هيكلًا أكثر تحديدًا لبناء التطبيقات. غالبًا ما تأتي مع مجموعة من القواعد والاصطلاحات التي يجب على المطورين اتباعها.
- من أمثلة الأُطُر Angular و Next.js، وهو إطار عمل ميتا لـ React.
- **التطبيقات ذات الصفحة الواحدة** (SPAs) هي تطبيقات ويب تقوم بتحميل صفحة HTML واحدة وتُحدِّث تلك الصفحة ديناميكيًا أثناء تفاعل المستخدم مع التطبيق دون إعادة تحميل الصفحة بأكملها.
- تستخدم SPAs جافاسكريبت لإدارة حالة التطبيق وعرض المحتوى. غالبًا ما يتم ذلك باستخدام أُطُر توفر أدوات رائعة لبناء واجهات مستخدم معقدة.
- بعض المشاكل المتعلقة بـ SPAs تشمل:

  - تواجه قارئات الشاشة صعوبة مع المحتوى الذي يُحدّث ديناميكيًا.
  - لا يتغير عنوان URL عند تنقل المستخدم داخل التطبيق، مما يصعب حفظ الصفحة، التراجع، أو مشاركة صفحات محددة.
  - قد يكون وقت التحميل الأولي بطيئًا إذا كان التطبيق كبيرًا لأن جميع الموارد يجب تحميلها مقدمًا.

## React

- React هي مكتبة جافاسكريبت شهيرة لبناء واجهات المستخدم وتطبيقات الويب.
- المفهوم الأساسي في React هو إنشاء مكونات واجهة مستخدم قابلة لإعادة الاستخدام يمكنها التحديث والعرض بشكل مستقل عند تغير البيانات.
- تسمح React للمطورين بوصف كيف يجب أن تبدو واجهة المستخدم بناءً على حالة التطبيق. ثم تقوم React بتحديث وعرض المكونات المناسبة عند تغير البيانات أو الحالة.

## مكونات React

- المكوِّنات هي اللبنات الأساسية لتطبيقات React التي تسمح للمطورين بتقسيم واجهات المستخدم المعقدة إلى أجزاء أصغر يمكن إدارتها.
- تُوصف واجهة المستخدم باستخدام JSX، وهو امتداد لصيغة جافاسكريبت يسمح بكتابة كود يشبه HTML داخل جافاسكريبت.
- المكوِّنات هي في الأساس دوال أو أصناف جافاسكريبت تُرجع جزءًا من واجهة المستخدم.

إليك مثال على مكون React بسيط يعرض رسالة ترحيب:

```jsx
function Greeting() {
  const name = 'Anna';
  return <h1>Welcome, {name}!</h1>;
}
```

لاستخدام المكون، يمكنك ببساطة استدعاؤه:
    
```jsx
  <Greeting />
```

## استيراد وتصدير مكونات React

- التصدير يجعل المكون متاحًا لملفات أخرى. الاستيراد يسمح لملف باستخدام مكون تم تصديره من مكان آخر.
- هناك نوعان من التصدير في React: التصدير الافتراضي والتصدير المسمي.

**التصدير الافتراضي**

- يمكن أن يحتوي الملف على تصدير افتراضي واحد فقط. هذا مثالي للملفات التي تحتوي بشكل رئيسي على مكون واحد.
- يمكنك تصدير مكون كتصدير افتراضي هكذا:

```jsx
// City.js
function City() {
  return <p>New York</p>;
}

export default City;
```

- يمكنك أيضًا التصدير في نفس سطر تعريف المكون:

```jsx
export default function City() {
  return <p>New York</p>;
}
```

- لاستيراد تصدير افتراضي، استخدم الكلمة المفتاحية `import` بدون أقواس متعرجة:

```jsx
// App.js
import City from './City';

function App() {
  return (
    <div>
      <h1>My favorite city is:</h1>
      <City />
    </div>
  );
}
```

**التصدير المسمي**

- يسمح التصدير المسمي للملف بمشاركة عدة مكونات. على عكس التصدير الافتراضي، يجب استيرادها باستخدام الاسم الدقيق الذي صدرت به.
- يمكنك تصدير عدة مكونات من نفس الملف هكذا:

```jsx
// Animals.jsx
export function Cat() {
  return <h2>Mr. Whiskers</h2>;
}

export function Dog() {
  return <h2>Fido</h2>;
}
```

- لاستيراد التصديرات المسماة، استخدم الأقواس المتعرجة مع الأسماء المصدرة بالضبط:

```jsx
import { Cat, Dog } from './Animals';
```

- يمكنك إعادة تسمية التصدير المسمي أثناء الاستيراد باستخدام الكلمة المفتاحية `as`:

```jsx
import { Cat as Kitty } from './Animals';
```

**التصدير المختلط بين الافتراضي والمسمي**

- يمكن أن يحتوي الملف على تصدير افتراضي واحد وعدة تصديرات مسماة في نفس الوقت:

```jsx
// Animals.jsx
export default function Cat() {
  return <h2>Mr. Whiskers</h2>;
}

export function Dog() {
  return <h2>Fido</h2>;
}
```

- عند استيراد التصديرات المختلطة، يأتي التصدير الافتراضي أولًا (بدون أقواس)، يليه التصديرات المسماة (داخل الأقواس):

```jsx
import Cat, { Dog } from './Animals';
```

## تمرير الخصائص (props) في مكونات React

- في React، الخصائص (props) هي طريقة لتمرير البيانات من مكون أب إلى مكون ابن. هذه الآلية ضرورية لإنشاء عناصر واجهة مستخدم قابلة لإعادة الاستخدام وديناميكية.
- يمكن أن تكون الخصائص أي قيمة جافاسكريبت. لتمرير الخصائص من الأب إلى الابن، تضيف الخصائص كسمات عند استخدام المكون الابن في JSX الخاص بالأب. إليك مثالًا بسيطًا:

```jsx
// Parent component
function Parent() {
  const name = 'Anna';
  return <Child name={name} />;
}

// Child component
function Child(props) {
  return <h1>Hello, {props.name}!</h1>;
}
```

يمكنك تمرير عدة خصائص باستخدام معامل النشر `(...)`، بعد تحويلها إلى كائن. إليك مثالًا:
    
```jsx
// Parent component
function Parent() {
  const person = {
    name: 'Anna',
    age: 25,
    city: 'New York'
  };
  return <Child {...person} />;
}
```

في هذا الكود، يقوم معامل النشر `{...person}` بتحويل كائن person إلى خصائص فردية تُمرر إلى مكون Child.

## العرض الشرطي في React

- يسمح العرض الشرطي في React بإنشاء واجهات مستخدم ديناميكية. يُستخدم لعرض محتوى مختلف بناءً على شروط أو حالات معينة داخل التطبيق.
- هناك عدة طرق لعرض المحتوى بشكل شرطي في React. إحدى الطرق الشائعة هي استخدام المعامل الثلاثي. إليك مثالًا:

```jsx
function Greeting({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? <h1>Welcome back!</h1> : <h1>Please log in</h1>}
    </div>
  );
}
```

- طريقة أخرى للعرض الشرطي هي استخدام معامل AND المنطقي (`&&`). هذا مفيد عندما تريد عرض المحتوى فقط إذا تحقق شرط معين. إليك مثالًا:

```jsx
function Greeting({ user }) {
  return (
    <div>
      {user && <h1>Welcome, {user.name}!</h1>}
    </div>
  );
}
```

في الكود أعلاه، يتم عرض عنصر `h1` فقط إذا كان كائن المستخدم صحيحًا.

يمكنك أيضًا استخدام جملة `if` مباشرة بهذه الطريقة:

```js
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h1>Welcome back!</h1>;
  }
  return <h1>Please sign in</h1>;
}
```

## عرض القوائم في React

- عرض القوائم في React مهمة شائعة عند بناء واجهات المستخدم.
- يمكن عرض القوائم باستخدام دالة `map()` لمصفوفة JS للتكرار على عناصر المصفوفة وإرجاع مصفوفة جديدة من عناصر JSX.
- على سبيل المثال، إذا كان لديك مصفوفة أسماء تريد عرضها كقائمة، يمكنك القيام بما يلي:

```jsx
function NameList({ names }) {
  return (
    <ul>
      {names.map((name, index) => (
        <li key={`${name}-${index}`}>{name}</li>
      ))}
    </ul>
  );
}
```

- تذكر دائمًا توفير مفتاح فريد لكل عنصر في القائمة لمساعدة React في إدارة التحديثات وأدوار العرض. باستخدام هذه التقنيات، يمكنك إنشاء قوائم مرنة وفعالة وديناميكية في تطبيقات React.

## الأنماط المضمّنة في React

- تسمح الأنماط المضمّنة في React بتطبيق أنماط CSS مباشرة على عناصر JSX باستخدام كائنات جافاسكريبت.
- لتطبيق الأنماط المضمّنة في React، يمكنك استخدام الخاصية style على عناصر JSX. تأخذ الخاصية style كائنًا حيث المفاتيح هي خصائص CSS بصيغة تنسيق سنام الجمل والقيم هي القيم المقابلة. إليك مثالًا:

```js
function Greeting() {
  return (
    <h1
      style={{ color: 'blue', fontSize: '24px', backgroundColor: 'lightgray' }}
    >
      Hello, world!
    </h1>
  );
}

export default Greeting;
```

يمكنك أيضًا استخراج الأنماط إلى كائن منفصل والرجوع إليه في الخاصية `style` بهذه الطريقة:

```jsx
function Greeting() {

  const styles = {
    color: 'blue',
    fontSize: '24px',
    backgroundColor: 'lightgray'
  };

  return <h1 style={styles}>Hello, world!</h1>;
}

export default Greeting;
```

- تدعم الأنماط المضمّنة التخصيص الديناميكي عبر السماح بتطبيق الأنماط بشكل شرطي بناءً على الخصائص أو الحالة. إليك مثالًا على كيفية تطبيق الأنماط بشكل شرطي بناءً على خاصية:

```jsx
function Greeting({ isImportant }) {

  const styles = {
    color: isImportant ? 'red' : 'black',
    fontSize: isImportant ? '24px' : '16px'
  };

  return <h1 style={styles}>Hello, world!</h1>;
}

export default Greeting;
```

- في الكود أعلاه، يتم تعيين أنماط `color` و `fontSize` بشكل شرطي بناءً على خاصية `isImportant`.

## العمل مع الأحداث في React

- **نظام الأحداث التركيبية**: هذه هي طريقة React في التعامل مع الأحداث. يعمل كغلاف حول الأحداث الأصلية مثل أحداث `click` و`keydown` و`submit`. تستخدم معالجات الأحداث في React اصطلاح التسمية بنمط الجمل المجمعة (camel casing). (مثال: `onClick`، `onSubmit`، إلخ)

إليك مثالًا على استخدام الخاصية `onClick` لعنصر `button` في React:

```jsx
function handleClick() {
  console.log("Button clicked!");
}

<button onClick={handleClick}>Click Me</button>;
```

في React، عادةً ما تبدأ دوال معالجات الأحداث بالبادئة `handle` للدلالة على مسؤوليتها عن التعامل مع الأحداث، مثل `handleClick` أو `handleSubmit`.

عندما يُفعّل المستخدم حدثًا، يمرر React كائن حدث تركيبي (Synthetic Event) إلى معالجك. يتصرف هذا الكائن بشكل مشابه لكائن الحدث الأصلي في جافاسكريبت العادية، ويوفر خصائص مثل `type` و`target` و`currentTarget`.

لمنع السلوكيات الافتراضية مثل تحديث المتصفح أثناء حدث `onSubmit`، يمكنك استدعاء الدالة `preventDefault()`:

```jsx
function handleSubmit(event) {
  event.preventDefault();
  console.log("Form submitted!");
}

<form onSubmit={handleSubmit}>
  <input type="text" />
  <button>Submit</button>
</form>;
```

يمكنك أيضًا تغليف دالة المعالجة داخل دالة سهمية هكذا:

```jsx
function handleDelete(id) {
  console.log("Deleting item:", id);
}

<button onClick={() => handleDelete(1)}>Delete Item</button>;
```

## العمل مع الحالة والدالة المساعدة `useState`

- **تعريف الحالة**: في React، الحالة هي كائن يحتوي على بيانات لمكون. عند تحديث الحالة، يُعاد عرض المكون. يعامل React الحالة كغير قابلة للتغيير، مما يعني أنه لا يجب تعديلها مباشرة.
- **خطاف `useState()`**: خطاف `useState` هو دالة تتيح لك إعلان متغيرات الحالة في المكونات الوظيفية. إليك الصيغة الأساسية:

```js
const [stateVariable, setStateFunction] = useState(initialValue);
```

في متغير الحالة لديك ما يلي:

- `stateVariable` يحمل القيمة الحالية للحالة
- `setStateFunction` (دالة التعيين) تحدّث متغير الحالة
- `initialValue` يحدد الحالة الابتدائية

إليك مثالًا كاملاً لمكوِّن `Counter`:

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>{count}</h2>

      <button onClick={() => setCount(count - 1)}>Decrement</button>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

export default Counter;
```

## العرض ومكوِّنات React

- **التعريف**: في React، العرض هو العملية التي تظهر بها المكوِّنات في واجهة المستخدم (UI)، عادةً في المتصفح. تتكون عملية العرض من ثلاث مراحل: التفعيل، العرض، والتثبيت.

تحدث مرحلة التفعيل عندما يكتشف React أن شيئًا ما قد تغيّر وقد تحتاج واجهة المستخدم إلى تحديث. غالبًا ما يكون هذا التغيير بسبب تحديث في الحالة أو الخصائص.

بمجرد حدوث التفعيل، يدخل React مرحلة العرض. هنا، يعيد React تقييم مكوِّناتك ويحدد ما يجب عرضه. للقيام بذلك، يستخدم React نسخة خفيفة من DOM الحقيقي تُسمى DOM الافتراضي. باستخدام DOM الافتراضي، يمكن لـ React بسرعة التحقق مما يحتاج إلى تغيير في المكوِّن.

مرحلة التثبيت هي حيث يأخذ React التغييرات المُعدة من DOM الافتراضي ويطبقها على DOM الحقيقي. بعبارة أخرى، هذه هي المرحلة التي ترى فيها النتيجة النهائية على الشاشة.

## تحديث الكائنات والمصفوفات في الحالة

- **تحديث الكائنات في الحالة**: إذا كنت بحاجة إلى تحديث كائن في الحالة، يجب عليك أولًا إنشاء كائن جديد أو نسخ كائن موجود، ثم تعيين الحالة لذلك الكائن الجديد. يجب اعتبار أي كائن موضوع في الحالة للقراءة فقط. إليك مثالًا على تعيين اسم المستخدم، العمر، والمدينة. تُستخدم دالة `handleChange` لمعالجة تحديثات معلومات المستخدم:

```jsx
import { useState } from "react";

function Profile() {
  const [user, setUser] = useState({ name: "John Doe", age: 31, city: "LA" });

  const handleChange = (e) => {
    const { name, value } = e.target;

    setUser((prevUser) => ({...prevUser, [name]: value}));
  };

  return (
    <div>
      <h1>User Profile</h1>
      <p>Name: {user.name}</p>
      <p>Age: {user.age}</p>
      <p>City: {user.city}</p>

      <h2>Update User Age </h2>
      <input type="number" name="age" value={user.age} onChange={handleChange} />

      <h2>Update User Name </h2>
      <input type="text" name="name" value={user.name} onChange={handleChange} />

      <h2>Update User City </h2>
      <input type="text" name="city" value={user.city} onChange={handleChange} />
    </div>
  );
}

export default Profile;
```

- **تحديث المصفوفات في الحالة**: عند تحديث المصفوفات في الحالة، من المهم عدم تعديل المصفوفة مباشرة باستخدام طرق مثل `push()` أو `pop()`. بدلاً من ذلك، يجب إنشاء مصفوفة جديدة عند تحديث الحالة:

```jsx
const addItem = () => {
  const newItem = {
    id: items.length + 1,
    name: `Item ${items.length + 1}`,
  };

  // Creates a new array
  setItems((prevItems) => [...prevItems, newItem]);
};
```

إذا أردت إزالة عناصر من مصفوفة، يجب استخدام طريقة `filter()`، التي تُرجع مصفوفة جديدة بعد تصفية العناصر التي تريد إزالتها:

```jsx
const removeItem = (id) => {
  setItems((prevItems) => prevItems.filter((item) => item.id !== id));
};
```

## الإشارة إلى القيم باستخدام المراجع (Refs)

- **خاصية `ref`**: يمكنك الوصول إلى عقدة DOM في React باستخدام خاصية `ref`. هنا مثال يوضح استخدام `ref` لتركيز عنصر `input`. تُستخدم خاصية `current` للوصول إلى القيمة الحالية لذلك الـ `ref`:

```jsx
import { useRef } from "react";

const Focus = () => {
  const inputRef = useRef(null);

  const handleFocus = () => {
    if (inputRef.current) {
      inputRef.current.focus();
    }
  };

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Enter text" />
      <button onClick={handleFocus}>Focus Input</button>
    </div>
  );
};

export default Focus;
```

## العمل مع الدالة المساعدة `useEffect`

- **الدالة المساعدة `useEffect()`**: في React، التأثير هو أي شيء يحدث خارج عملية عرض المكوِّن. أي شيء لا يتعامل معه React مباشرة كجزء من عرض واجهة المستخدم. أمثلة شائعة تشمل جلب البيانات، تحديث عنوان تبويب المتصفح، القراءة من أو الكتابة إلى التخزين المحلي للمتصفح، الحصول على موقع المستخدم، وأكثر. هذه العمليات تتفاعل مع العالم الخارجي وتُعرف بالتأثيرات الجانبية. يوفر React الدالة المساعدة `useEffect` لتتعامل مع هذه التأثيرات. تتيح لك `useEffect` تشغيل دالة بعد عرض المكوِّن أو تحديثه.

```js
import { useEffect } from "react";

useEffect(() => {
 // Your side effect logic (usually a function) goes here
}, [dependencies]);
```

تعمل دالة التأثير بعد عرض المكوِّن، بينما يتحكم المعامل الاختياري `dependencies` في توقيت تشغيل التأثير.

لاحظ أن `dependencies` يمكن أن تكون مصفوفة من "القيم التفاعلية" (الحالة، الخصائص، الدوال، المتغيرات، وهكذا)، أو مصفوفة فارغة، أو تُحذف تمامًا. إليك كيف تتحكم كل هذه الخيارات في عمل `useEffect`:

- إذا كانت `dependencies` مصفوفة تحتوي على قيمة تفاعلية واحدة أو أكثر، فسيعمل التأثير كلما تغيرت تلك القيم.

- إذا كانت `dependencies` مصفوفة فارغة، يعمل `useEffect` مرة واحدة فقط عند العرض الأول للمكوِّن.

- إذا حذفت `dependencies`، يعمل التأثير في كل مرة يُعرض أو يُحدّث فيها المكوِّن.

## كيفية إنشاء الدوال المساعدة المخصصة

- **الدوال المساعدة المخصصة**: تتيح لك الدالة المساعدة المخصصة استخراج منطق قابل لإعادة الاستخدام من المكوِّنات، مثل جلب البيانات، إدارة الحالة، التبديل، والتأثيرات الجانبية مثل تتبع حالة الاتصال بالإنترنت. في React، تبدأ جميع الدوال المساعدة المدمجة بالكلمة `use`، لذا يجب أن تتبع دالتك المساعدة المخصصة نفس الاصطلاح.

إليك مثالًا على إنشاء دالة مساعدة `useDebounce`:

```jsx
function useDebounce(value, delay) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const handler = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => {
      clearTimeout(handler);
    };
  }, [value, delay]);

  return debouncedValue;
}

export { useDebounce };
```

## العمل مع النماذج في React

- **المدخلات المُتحكم بها**: هذا عندما تخزن قيمة حقل الإدخال في الحالة وتُحدّثها عبر أحداث `onChange`. هذا يمنحك تحكمًا كاملاً في بيانات النموذج ويسمح بالتحقق الفوري والعرض الشرطي.

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  const handleChange = (e) => {
    setName(e.target.value);
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(name);
  };

  return (
    <>
      <form onSubmit={handleSubmit}>
        <label htmlFor="name">Your name</label> <br />
        <input value={name} id="name" onChange={handleChange} type="text" />
        <button type="submit">Submit</button>
      </form>
    </>
  );
}

export default App;
```

- **المدخلات غير المُتحكم بها**: بدلاً من التعامل مع المدخلات عبر الخطاف `useState`، تحتفظ المدخلات غير المُتحكم بها في HTML بحالتها الداخلية بمساعدة DOM. وبما أن DOM يتحكم في قيم الإدخال، تحتاج إلى جلب قيم حقول الإدخال باستخدام `ref`.

```jsx
import { useRef } from "react";

function App() {
 const nameRef = useRef();

 const handleSubmit = (e) => {
   e.preventDefault();
   console.log(nameRef.current.value);
 };

 return (
   <form onSubmit={handleSubmit}>
     <label htmlFor="name">Your</label>{" "}
     <input type="text" ref={nameRef} id="name" />
     <button type="submit">Submit</button>
   </form>
 );
}

export default App;
```

## العمل مع الخطاف `useActionState`

- **إجراءات الخادم**: هي دوال تُنفذ على الخادم للسماح بمعالجة النموذج مباشرة على الخادم دون الحاجة إلى نقاط نهاية API. إليك مثالًا من تطبيق Next.js:

```js
"use server";

async function submitForm(formData) {
 const name = formData.get("name");
 return { message: `Hello, ${name}!` };
}
```

تُشير التوجيهة `"use server"` إلى أن الدالة هي إجراء على الخادم.

- **الخطاف `useActionState`**: يُحدّث هذا الخطاف الحالة بناءً على نتيجة إرسال النموذج. إليك الصيغة الأساسية للخطاف `useActionState`:

```js
const [state, action, isPending] = useActionState(actionFunction, initialState, permalink);
```

- `state` هي الحالة الحالية التي تُرجعها الإجراء.
- `action` هي الدالة التي تُشغّل إجراء الخادم.
- `isPending` هي قيمة منطقية تشير إلى ما إذا كان الإجراء قيد التنفيذ أم لا.
- معلمة `actionFunction` هي إجراء الخادم نفسه.
- `initialState` هي المعلمة التي تمثل نقطة البداية للحالة قبل تشغيل الإجراء.
- `permalink` هي سلسلة اختيارية تحتوي على عنوان URL الفريد للصفحة التي يُعدّلها النموذج.

## جلب البيانات في React

- **خيارات جلب البيانات**: هناك طرق عديدة لجلب البيانات في React. يمكنك استخدام Fetch API الأصلي، أو أدوات طرف ثالث مثل Axios أو SWR.
- **متغيرات الحالة الشائعة عند جلب البيانات**: بغض النظر عن الطريقة التي تختارها لجلب البيانات في React، هناك بعض متغيرات الحالة التي تحتاج إلى تتبعها. أولها البيانات نفسها. الثاني يتتبع ما إذا كانت البيانات لا تزال تُجلب. الثالث هو متغير حالة يلتقط أي أخطاء قد تحدث أثناء عملية جلب البيانات.

```js
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);
```

بما أن جلب البيانات هو تأثير جانبي، من الأفضل استخدام `Fetch API` داخل الخطاف `useEffect`.

```js
useEffect(() => {
  const fetchData = async () => {
    try {
      const res = await fetch("https://jsonplaceholder.typicode.com/posts");
      
      if (!res.ok) {
        throw new Error("Network response was not ok");
      }

      const data = await res.json();
      setData(data);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  };

  fetchData();
}, []);
```

بعد ذلك يمكنك عرض رسالة تحميل إذا لم تكتمل عملية جلب البيانات، أو رسالة خطأ إذا حدث خطأ أثناء الجلب، أو عرض النتائج.

```jsx
if (loading) {
  return <p>Loading...</p>;
}

if (error) {
  return <p>{error.message}</p>;
}

return (
  <ul>
    {data.map((post) => (
      <li key={post.id}>{post.title}</li>
    ))}
  </ul>
);
```

إذا أردت استخدام Axios، تحتاج إلى تثبيته واستيراده:

```bash

```

```js

```

```js
      setLoading(false);
```

## العمل مع الخطاف `useOptimistic`

- **الخطاف `useOptimistic`**: يُستخدم هذا الخطاف للحفاظ على تجاوب واجهات المستخدم أثناء انتظار اكتمال إجراء غير متزامن في الخلفية. يساعد في إدارة "التحديثات المتفائلة" في الواجهة، وهي استراتيجية تقدم تحديثات فورية للواجهة بناءً على النتيجة المتوقعة لإجراء، مثل انتظار استجابة الخادم.

إليك الصيغة الأساسية:

```js
const [optimisticState, addOptimistic] = useOptimistic(actualState, updateFunction);
```

- `optimisticState` هي الحالة المؤقتة التي تُحدّث فورًا لتحسين تجربة المستخدم.
- `addOptimistic` هي الدالة التي تطبق التحديث المتفائل قبل تغيّر الحالة الفعلي.
- `actualState` هي القيمة الحقيقية للحالة الناتجة عن نتيجة إجراء، مثل جلب بيانات من خادم.
- `updateFunction` هي الدالة التي تحدد كيف يجب تحديث الحالة المتفائلة عند استدعائها.

إليك مثالًا على استخدام الخطاف `useOptimistic` في مكوّن `TaskList`:

```js
"use client";

import { useOptimistic } from "react";

export default function TaskList({ tasks, addTask }) {
  const [optimisticTasks, addOptimisticTask] = useOptimistic(
    tasks,
    (state, newTask) => [...state, { text: newTask, pending: true }]
  );

  async function handleSubmit(e) {
    e.preventDefault();
    const formData = new FormData(e.target);

    addOptimisticTask(formData.get("task"));

    addTask(formData);
    e.target.reset();
  }

  return <>{/* UI */}</>;
}
```

- **`startTransition`**: يُستخدم هذا لتقديم جزء من الواجهة وتحديد تحديث الحالة كتحول غير عاجل. يسمح هذا للواجهة بأن تبقى متجاوبة أثناء التحديثات المكلفة. إليك الصيغة الأساسية:

```js
startTransition(action)
```

يقوم `action` بتحديث الحالة أو تشغيل بعض المنطق المرتبط بالتحول. هذا يضمن عدم حجب تحديثات الواجهة العاجلة (مثل الكتابة أو النقر).

## العمل مع الخطاف `useMemo`

- **التخزين المؤقت (Memoization)**: هي تقنية تحسين تُخزّن نتائج استدعاءات الدوال المكلفة بناءً على معلمات محددة. عند تقديم نفس المعلمات مرة أخرى، تُعاد النتيجة المخزنة بدلاً من إعادة حساب الدالة.
- **الخطاف `useMemo`**: يُستخدم هذا الخطاف لتخزين القيم المحسوبة مؤقتًا. إليك مثالًا لتخزين نتيجة فرز مصفوفة كبيرة. ستُنفذ الدالة `expensiveSortFunction` فقط عندما تتغير `largeArray`:

```js
const memoizedSortedArray = useMemo(
  () => expensiveSortFunction(largeArray),
  [largeArray]
);
```

```js
const handleClick = useCallback(() => {
 // code goes here
}, [dependency]);
``` 

- **`React.memo`**: يُستخدم هذا لتخزين مكوّن مؤقتًا لمنع إعادة عرضه غير الضرورية عندما لا تتغير خاصيته.

```js
const MemoizedComponent = React.memo(({ prop }) => {
 return (

     {/* Presentation */}
   </>
 )
});
``` 

## أدوات إدارة التبعيات

- **تعريف التبعية**: في البرمجيات، التبعية هي عندما يعتمد مكوّن أو وحدة في تطبيق على آخر ليعمل بشكل صحيح. التبعيات شائعة في التطبيقات لأنها تسمح للمطوّرين باستخدام دوال أو أدوات مُعدة مسبقًا من قبل الآخرين. التبعيتان الأساسيتان لمشروع React هما حزمتا `react` و `react-dom`:

```json

  "react-dom": "^18.3.1"
}
```

- **تعريف مدير الحزم**: لإدارة تبعيات البرمجيات في مشروع، تحتاج إلى استخدام مدير حزم. مدير الحزم هو أداة تُستخدم للتثبيت، التحديث، وإزالة التبعيات. العديد من لغات البرمجة الشهيرة مثل جافاسكريبت، بايثون، روبي وجافا تستخدم مديري حزم. من مديري الحزم الشائعة لجافاسكريبت npm و Yarn و pnpm.
- **ملف `package.json`**: هو ملف إعداد رئيسي في المشاريع يحتوي على بيانات وصفية عن مشروعك، بما في ذلك اسمه، الإصدار، والتبعيات. كما يحدد السكربتات، معلومات الترخيص، وإعدادات أخرى تساعد في إدارة المشروع وتبعياته.
- **ملف `package-lock.json`**: هذا الملف يُثبت الإصدارات الدقيقة لكل الحزم التي يستخدمها مشروعك. عند تحديث حزمة، يتم تحديث الإصدارات الجديدة في ملف القفل أيضًا.
- **مجلد `node_modules`**: يحتوي هذا المجلد على الكود الفعلي للتبعيات المدرجة في ملف `package.json`، بما في ذلك التبعيات المباشرة لمشروعك وأي تبعيات لتلك التبعيات.

## React Router

- **مقدمة**: React Router هي مكتبة طرف ثالث تسمح لك بإضافة التوجيه إلى تطبيقات React. للبدء، تحتاج إلى تثبيت React Router في مشروع React موجود كما يلي:

```bash
npm i react-router
```

ثم داخل ملف `main.jsx` أو `index.jsx`، تحتاج إلى إعداد هيكل المسارات كما يلي:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter, Routes, Route } from "react-router";
import App from "./App.jsx";

import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<App />} />
      </Routes>
    </BrowserRouter>
  </StrictMode>
);
```

تُستخدم الخاصيتان `path` و `element` لربط عنوان URL بمكوّنات الواجهة. في هذه الحالة، نُعد مسارًا للصفحة الرئيسية يشير إلى المكوّن `App`.

- **إعداد عدة عروض ومسارات**: من الشائع في التطبيقات الكبيرة إعداد عدة عروض ومسارات كما يلي:

```jsx
<Routes>
  <Route index element={<Home />} />
  <Route path="about" element={<About />} />

  <Route path="products">
    <Route index element={<ProductsHome />} />
    <Route path=":category" element={<Category />} />
    <Route path=":category/:productId" element={<ProductDetail />} />
    <Route path="trending" element={<Trending />} />
  </Route>
</Routes>
```

الخاصية `index` في هذه الأمثلة تمثل المسار الافتراضي لجزء معين من المسار. لذا، سيُعرض مكوّن `Home` عند المسار الجذري `/` بينما يُعرض مكوّن `ProductsHome` عند المسار `/products`.

- **تداخل المسارات**: يمكنك تداخل المسارات داخل مسارات أخرى، مما يؤدي إلى إلحاق مسار الطفل بمسار الأب.

```jsx
<Route path="products">
  <Route path="trending" element={<Trending />} />
</Route>
```

في المثال أعلاه، سيكون مسار المنتجات الرائجة هو products/trending.

- **الأجزاء الديناميكية**: الجزء الديناميكي هو حيث يكون أي جزء من مسار URL ديناميكيًا.

```jsx
<Route path=":category" element={<Category />} />
```

في هذا المثال لدينا جزء ديناميكي يسمى `category`. عندما ينتقل المستخدم إلى عنوان URL مثل products/brass-instruments، يتغير العرض إلى مكوّن `Category` ويمكنك جلب البيانات المناسبة ديناميكيًا بناءً على الجزء.

- **الخطاف `useParams`**: يُستخدم هذا الخطاف للوصول إلى المعلمات الديناميكية من مسار URL.

```js
import { useParams } from "react-router";

export default function Category() {
  let params = useParams();
   {/* Accessing the category param: params.category */}
   {/* rest of code goes here */}
}
```

```js
}
```

- **تحسين الصور في Next.js**: يوسع مكوّن `Image` عنصر HTML الأصلي `img` ويسمح بتحميل الصفحات بشكل أسرع وتحسين حجم الصور. هذا يعني أن الصور ستُحمّل فقط عند دخولها إطار العرض، وسيقدم مكوّن `Image` الصور بالحجم المناسب تلقائيًا لكل جهاز.

```jsx
import Image from "next/image";

export default function Page() {
  return (
    <Image src="link-to-image-goes-here" alt="descriptive-title-goes-here" />
  );
}
``` 

## تمرير الخصائص (Prop Drilling)

- **تعريف**: تمرير الخصائص هو عملية تمرير الخصائص من مكوّن أب إلى مكوّنات فرعية متداخلة بعمق، حتى عندما لا تحتاج بعض المكوّنات الفرعية إلى هذه الخصائص.

## إدارة الحالة

- **واجهة برمجة التطبيقات للسياق (Context API)**: يشير السياق إلى عندما يجعل مكوّن أب المعلومات متاحة للمكوّنات الفرعية دون الحاجة لتمريرها صراحة عبر الخصائص. تُستخدم `createContext` لإنشاء كائن سياق يمثل السياق الذي ستقرأه المكوّنات الأخرى. يُستخدم `Provider` لتوفير قيم السياق للمكوّنات الفرعية.

```js
import { useState, createContext } from "react";

const CounterContext = createContext();

const CounterProvider = ({ children }) => {
  const [count, setCount] = useState(0);

  return (
    <CounterContext.Provider value={{ count, setCount }}>
      {children}
    </CounterContext.Provider>
  );
};

export { CounterContext, CounterProvider };
```

- **Redux**: يدير Redux الحالة عبر توفير مخزن مركزي وتحكم صارم في تحديثات الحالة. يستخدم نمطًا متوقعًا مع الإجراءات، المخفضات، والبرمجيات الوسيطة. الإجراءات هي حمولة معلومات ترسل بيانات من تطبيقك إلى مخزن Redux، غالبًا ما تُشغّل بواسطة تفاعلات المستخدم. المخفضات هي دوال تحدد كيف يجب أن تتغير الحالة استجابة لتلك الإجراءات، مع ضمان تحديث الحالة بطريقة غير قابلة للتغيير. البرمجيات الوسيطة تعمل كجسر بين إرسال الإجراءات والمخفض، مما يسمح لك بتوسيع وظائف Redux (مثل التسجيل، التعامل مع العمليات غير المتزامنة) دون تعديل التدفق الأساسي.

- **Zustand**: حل إدارة الحالة هذا مثالي للتطبيقات الصغيرة إلى المتوسطة. يعمل باستخدام الخطاف `useStore` للوصول إلى الحالة مباشرة في المكوّنات والصفحات. هذا يتيح لك تعديل والوصول إلى البيانات دون الحاجة إلى إجراءات، مخفضات، أو مزود.

## تصحيح مكوّنات React باستخدام أدوات مطوّر React

- **أدوات مطوِّر React**: هي امتداد للمتصفح يمكنك استخدامه في Chrome و Firefox و Edge لفحص مكوِّنات React وتحديد مشاكل الأداء. بالنسبة لـ Safari، تحتاج إلى تثبيت حزمة npm المسماة `react-devtools`. بعد تثبيت أدوات React DevTools وفتح تطبيق React في المتصفح، افتح أدوات مطوِّر المتصفح للوصول إلى علامتي التبويب الإضافيتين المخصصتين لتصحيح React – المكوِّنات وProfiler.
- **علامة تبويب المكوِّنات**: تعرض هذه العلامة كل مكوِّن في شكل شجرة. يمكنك في هذه العلامة:
  - عرض تسلسل المكوِّنات في التطبيق
  - فحص وتعديل الخصائص (props)، الحالات (states)، وقيم السياق (context) في الوقت الحقيقي
  - فحص الكود المصدري لكل مكوِّن محدد
  - تسجيل بيانات المكوِّن في وحدة التحكم
  - فحص عناصر DOM الخاصة بالمكوِّن
- **علامة تبويب Profiler**: تساعدك هذه العلامة على تحليل أداء المكوِّنات. يمكنك تسجيل أداء المكوِّنات لتحديد عمليات إعادة العرض غير الضرورية، عرض مدة الالتزام، ومن ثم تحسين المكوِّنات البطيئة.

## مكوّنات خادم React

- **تعريف**: مكوّنات خادم React هي مكوّنات React تُعرض حصريًا على الخادم، وترسل فقط HTML النهائي إلى العميل. هذا يعني أن تلك المكوّنات يمكنها الوصول مباشرة إلى موارد الخادم وتقليل كمية جافاسكريبت المرسلة إلى المتصفح بشكل كبير.

## الفروقات بين الأداء الحقيقي والأداء المدرك

- **الأداء المدرك**: هو كيف يدرك المستخدمون أداء الموقع. هو تقييمهم من حيث الاستجابة والموثوقية. هذا قياس ذاتي، لذا يصعب تحديده بدقة، لكنه مهم جدًا لأن تجربة المستخدم تحدد نجاح أو فشل الموقع.
- **الأداء الحقيقي**: هو الأداء الموضوعي والقابل للقياس للموقع. يُقاس باستخدام مؤشرات مثل وقت تحميل الصفحة، وقت استجابة الخادم، ووقت العرض. تتأثر هذه القياسات بعوامل متعددة متعلقة بالشبكة والكود نفسه.

## تقنيات لتحسين الأداء المدرك

- **التحميل الكسول**: هذه التقنية تقلل وقت التحميل الأولي قدر الإمكان بتحميل الموارد غير الأساسية في الخلفية.
- **تقليل تأخيرات الخطوط**: إذا كان موقعك يحتوي على خطوط مخصصة، يجب محاولة تقليل تأخيرات تحميل الخطوط، لأن ذلك قد يؤدي إلى وميض أو عرض الخط البديل أثناء تحميل الخط المخصص. اقتراح لذلك هو استخدام خط بديل مشابه للخط المخصص، حتى يكون التغيير أكثر سلاسة إذا حدث ذلك.
- **استخدام مؤشرات التحميل**: عرض مؤشر تحميل لعملية طويلة بمجرد نقر المستخدم على عنصر يساعد المستخدم على الشعور بالاتصال والمشاركة مع العملية، مما يجعل وقت الانتظار يبدو أقصر.

## مفاهيم الأداء الأساسية

- **ترتيب المصدر**: يشير إلى طريقة تنظيم عناصر HTML في الوثيقة. هذا يحدد ما يتم تحميله أولًا ويمكن أن يؤثر بشكل كبير على الأداء وإمكانية الوصول.

بعض أفضل الممارسات لترتيب المصدر تشمل:

- وضع المحتوى الحرج مثل العناوين، والتنقل، أو النص الرئيسي في مكان أعلى في هيكل HTML.
- تأجيل السكربتات غير الأساسية مثل تلك الخاصة بالتحليلات أو الأدوات الخارجية، حتى لا تعيق العرض.
- استخدام التحسين التدريجي، لضمان عمل التجربة الأساسية حتى قبل تحميل الأنماط والسكربتات. التحسين التدريجي هو طريقة لبناء المواقع والتطبيقات على أساس جعل الصفحة تعمل بـ HTML أولًا.

إليك مثالًا على ترتيب مصدر جيد، باستخدام أفضل الممارسات التي استعرضناها:

```html
<h1>Welcome to FastSite!</h1>
<p>Critical information loads first.</p>
<script src="slow-script.js" defer></script>
```

- **مسار العرض الحرج**: هو تسلسل الخطوات التي يتبعها المتصفح لتحويل الكود إلى بكسلات على الشاشة.
- **زمن الاستجابة**: هو الوقت الذي يستغرقه الطلب للسفر بين المتصفح والخادم. بمعنى آخر، زمن استجابة مرتفع يعني صفحات بطيئة.

بعض الطرق لتقليل زمن الاستجابة تشمل:

- استخدام شبكات توصيل المحتوى (CDNs) لخدمة الملفات من مواقع أقرب.
- تفعيل الضغط باستخدام أدوات مثل Gzip لتقليل حجم الملفات.
- تحسين الصور واستخدام التحميل الكسول.

```html
<img src="placeholder.jpg" data-src="real-image.jpg" loading="lazy">
```

## تحسين INP

- **التعريف**: INP (Interaction to Next Paint) يقيس استجابة الصفحة بشكل عام عبر قياس الوقت من تفاعل المستخدم، مثل النقر أو الضغط على مفتاح، حتى التحديث التالي لعرض المتصفح. INP أقل يعني صفحة أكثر استجابة.

إليك بعض الطرق لتحسين INP:

- تقليل عمل الخيط الرئيسي بتقسيم مهام جافاسكريبت الطويلة.
- استخدام `requestIdleCallback()` للسكربتات غير الحرجة. هذا يضع دالة في قائمة الانتظار ليتم استدعاؤها خلال فترات خمول المتصفح.
- تأجيل أو تحميل الكسول للأصول الثقيلة التي تم ذكرها سابقًا.
- تحسين معالجات الأحداث. إذا كانت هذه المعالجات تعمل بشكل متكرر جدًا أو تقوم بعمليات ثقيلة، فإنها تبطئ الصفحة وتزيد INP. الحل هو استخدام تقنية debouncing. debouncing تضمن أن الدالة تعمل فقط بعد توقف المستخدم عن الكتابة لفترة قصيرة - مثلاً 300 مللي ثانية. هذا يمنع الحسابات غير الضرورية ويحسن الأداء.

## كيف يعمل العرض في المتصفح

- **كيف يعمل العرض**: أولًا يحلل المتصفح HTML ويبني DOM. بعد ذلك يعالج المتصفح CSS، ويبني نموذج كائن CSS أو CSSOM. هذا هيكل شجري آخر يحدد كيف يجب تنسيق العناصر. أخيرًا، يرسم المتصفح البكسلات على الشاشة، معروضًا كل عنصر بناءً على الأنماط والتخطيط المحسوب. في الصفحات المعقدة، قد يشمل ذلك طبقات متعددة تُركب معًا لتشكيل المخرجات البصرية النهائية.

## كيف يؤثر الأداء على الاستدامة

- **معلومات خلفية**: الإنترنت يمثل حوالي 2% من انبعاثات الكربون العالمية — وهو نفس نسبة صناعة الطيران! كل بايت يُنقل يحتاج إلى كهرباء، من مراكز البيانات إلى أجهزة المستخدمين. الملفات الكبيرة والسكربتات غير الفعالة تعني استهلاك طاقة أكبر. الموقع عالي الأداء ليس أسرع فقط، بل يقلل أيضًا من المعالجة غير الضرورية واستهلاك الطاقة.

## طرق لتقليل أوقات تحميل الصفحات

- **تحسين أصول الوسائط**: الصور والفيديوهات الكبيرة هي من الأسباب الشائعة لبطء التحميل. بتحسين هذه الأصول، يمكنك تسريع موقعك بشكل كبير. يشمل ذلك ضغط الصور، واستخدام صيغ حديثة مثل WebP، واستخدام التحميل الكسول للأصول.
- **الاستفادة من التخزين المؤقت للمتصفح**: التخزين المؤقت يسمح للمتصفحات بحفظ أجزاء من موقعك محليًا، مما يقلل أوقات التحميل للزوار العائدين.
- **تصغير وضغط الملفات**: تقليل حجم ملفاتك يؤدي إلى تنزيلات أسرع. يشمل ذلك تقليل حجم الملفات المنقولة وتصغير ملفات CSS وJavaScript.

## تحسين "الوقت حتى الاستخدام"

- **التعريف**: "الوقت حتى الاستخدام" هو الفترة من طلب المستخدم لصفحة حتى يتمكن من التفاعل معها بشكل فعّال. لتحسين "الوقت حتى الاستخدام" يمكنك استخدام التحميل الكسول للأصول أو تقليل الموارد التي تعيق العرض.

## المقاييس الرئيسية لقياس الأداء

- **الطلاء الأول للمحتوى أو FCP**: يقيس مدى سرعة ظهور أول قطعة محتوى — نص أو صورة — على الشاشة. يُعتبر FCP جيدًا إذا كان أقل من 1.8 ثانية، وضعيفًا إذا تجاوز 3 ثوانٍ. يمكنك التحقق من FCP باستخدام أدوات المطوِّر في Chrome عبر تبويب الأداء.
- **إجمالي وقت الحظر**: يظهر مدة حظر الخيط الرئيسي بسبب مهام جافاسكريبت الثقيلة. إذا كان إجمالي وقت الحظر (TBT) مرتفعًا، يعاني المستخدمون من تفاعلات بطيئة. لتحسين TBT، قسم المهام الطويلة وأجل السكربتات غير الضرورية.
- **معدل الارتداد**: هو نسبة الزوار الذين يغادرون دون تفاعل. إذا كان موقعك يعاني من معدل ارتداد مرتفع، قد يكون السبب بطء الصفحة.
- **المستخدمون الفريدون**: هذا المقياس يتتبع عدد الزوار الفرديين لموقعك. لعرض معدل الارتداد والمستخدمين الفريدين، يمكنك استخدام Google Analytics. سيمكنك ذلك من مراقبة هذه المقاييس وتحسين التفاعل.

## أدوات قياس الأداء الشائعة

- **أدوات المطوِّر في Chrome**: هي أداة مدمجة داخل Google Chrome تتيح لك تحليل وتصحيح الأداء في الوقت الحقيقي. تعرض أدوات المطوِّر أوقات التحميل، واستخدام وحدة المعالجة المركزية، وتأخيرات العرض. مفيدة بشكل خاص لقياس الطلاء الأول للمحتوى (FCP)، وهو مدى سرعة رؤية المستخدم لأول محتوى مرئي. إذا شعرت بأن موقعك بطيء، ستساعدك أدوات المطوِّر على تحديد نقاط الاختناق.
- **Lighthouse**: أداة آلية تفحص الأداء، وتحسين محركات البحث، وإمكانية الوصول.
- **WebPageTest**: تتيح لك اختبار كيفية تحميل موقعك من مواقع وأجهزة مختلفة. توفر تفصيلًا دقيقًا لمؤشر السرعة، وإجمالي وقت الحظر، وغيرها من مقاييس الأداء الرئيسية. إذا أردت معرفة كيف يختبر المستخدمون الحقيقيون موقعك عالميًا، WebPageTest هي الأداة المناسبة.
- **PageSpeed Insights**: تحلل موقعك وتقترح تحسينات سريعة لكل من الجوال وسطح المكتب. تخبرك بما يبطئ موقعك وتعطي توصيات محددة مثل تحسين الصور، وإزالة السكربتات التي تعيق العرض، وتقليل أوقات استجابة الخادم. PageSpeed Insights طريقة سريعة وسهلة لمعرفة كيف ترى Google أداء موقعك.
- **مراقبة المستخدم الحقيقي**: أدوات RUM تتتبع سلوك المستخدم الفعلي، وتظهر كيف يختبر الزوار الحقيقيون موقعك. من أشهر أدوات RUM Google Analytics التي تتتبع أوقات تحميل الصفحات ومعدلات الارتداد، وNew Relic أو Datadog التي تراقب مشاكل الأداء في الوقت الحقيقي. إذا أردت بيانات من المستخدمين الفعليين، أدوات RUM ضرورية.

## العمل مع واجهات برمجة تطبيقات الأداء على الويب

- **تعريف**: تتيح واجهات برمجة التطبيقات الخاصة بالأداء (Performance Web APIs) للمطورين تتبع مدى كفاءة تحميل صفحة الويب واستجابتها مباشرة في الكود. تسمح هذه الواجهات بقياس أوقات تحميل الصفحة، تتبع تأخيرات العرض والتفاعل، وتحليل وقت تنفيذ جافاسكريبت.
- **`performance.now()`**: توفر هذه الواجهة طوابع زمنية عالية الدقة (بالملي ثانية) لقياس مدة تحميل أجزاء مختلفة من موقعك.

```js
const start = performance.now();  
// Run some code here  
const end = performance.now();  

console.log(`Execution time: ${end - start}ms`);
```

- **واجهة توقيت الأداء**: تعطي هذه الواجهة تفصيلًا لكل مرحلة من مراحل تحميل الصفحة، من بحث DNS إلى `DOMContentLoaded`.

```js
const timing = performance.timing;  

const pageLoadTime = timing.loadEventEnd - timing.navigationStart;  
console.log(`Page load time: ${pageLoadTime}ms`);
```

- **`PerformanceObserver`**: تستمع هذه الواجهة لأحداث الأداء مثل تحولات التخطيط، والمهام الطويلة، وتفاعلات المستخدم.

```js
const observer = new PerformanceObserver((list) => {  
  list.getEntries().forEach((entry) => {  
    console.log(`Long task detected: ${entry.duration}ms`);  
  });  
});  

observer.observe({ type: "longtask", buffered: true });
```

## تقنيات لتحسين أداء CSS

- **رسوم CSS المتحركة**: تحريك بعض خصائص CSS، مثل الأبعاد، والموقع، والتخطيط، يطلق عملية تسمى "إعادة التدفق"، حيث يعيد المتصفح حساب موقع وهندسة بعض العناصر في الصفحة. هذا يتطلب إعادة رسم، وهي عملية مكلفة حسابيًا. لذلك، يُنصح بتقليل عدد الرسوم المتحركة في CSS قدر الإمكان أو على الأقل إعطاء المستخدم خيار تشغيلها أو إيقافها.

## تقنيات لتحسين أداء جافاسكريبت

- **تقسيم الكود**: تقسيم كود جافاسكريبت إلى وحدات تؤدي مهام حرجة وغير حرجة مفيد أيضًا. بهذه الطريقة، يمكنك تحميل الوحدات الحرجة مسبقًا بأسرع وقت وتأجيل الوحدات غير الحرجة لعرض الصفحة بأسرع ما يمكن.
- **التلاعب بـ DOM**: يشير التلاعب بـ DOM إلى عملية تغيير محتوى الصفحة ديناميكيًا باستخدام جافاسكريبت من خلال التفاعل مع نموذج كائن المستند (DOM). التلاعب بـ DOM مكلف حسابيًا. تقليل كمية التلاعب بـ DOM في كود جافاسكريبت يحسن الأداء.

## أُطُر عمل CSS

- **أُطُر CSS**: يمكن لأُطُر CSS تسريع سير عملك، خلق نمط بصري موحد عبر الموقع، جعل التصميم متناسقًا عبر متصفحات متعددة، وتنظيم كود CSS الخاص بك بشكل أفضل.
- **أُطُر CSS الشهيرة**: من أشهر أُطُر CSS هي Tailwind CSS، Bootstrap، Materialize، و Foundation.
- **العيوب المحتملة**:
  - قد تتعارض CSS المقدمة من الإطار مع CSS المخصص لديك.
  - قد يبدو موقعك مشابهًا لمواقع أخرى تستخدم نفس الإطار.
  - الأُطُر الكبيرة قد تسبب مشاكل في الأداء.

## نوعان من أُطُر عمل CSS

- **أُطُر عمل CSS ذات الأولوية للأدوات (Utility-first)**: هذه الأُطُر تحتوي على أصناف صغيرة لأغراض محددة، مثل تعيين الهامش، أو الحشو، أو لون الخلفية. يمكنك تعيين هذه الأصناف الصغيرة مباشرة إلى عناصر HTML حسب الحاجة. يُصنف Tailwind CSS كإطار عمل CSS من نوع Utility-first.

إليك مثالًا على استخدام Tailwind CSS لتنسيق زر.

```html
<button class="bg-blue-500 text-white font-bold py-2 px-4 rounded-full hover:bg-blue-700">
  Button
</button>
```

- **أُطُر عمل CSS القائمة على المكوِّنات**: هذه الأُطُر تحتوي على مكوِّنات مُعدة مسبقًا بأنماط محددة يمكنك إضافتها إلى موقعك. المكوِّنات متاحة في الوثائق الرسمية لإطار العمل، ويمكنك نسخها ولصقها في مشروعك. يُصنف Bootstrap كإطار عمل CSS قائم على المكوِّنات.

إليك مثالًا على استخدام Bootstrap لإنشاء مجموعة قائمة. بدلاً من تطبيق أصناف صغيرة على عناصر HTML الخاصة بك، ستضيف المكوِّن بالكامل، بما في ذلك الهيكل HTML.

```html
<div class="card" style="width: 25rem;">
  <ul class="list-group list-group-flush">
    <li class="list-group-item">HTML</li>
    <li class="list-group-item">CSS</li>
    <li class="list-group-item">JavaScript</li>
  </ul>
</div>
```

## Tailwind CSS

Tailwind هو إطار عمل CSS من نوع Utility-first. بدلاً من كتابة قواعد CSS مخصصة، تبني تصميماتك بدمج أصناف أدوات صغيرة مباشرة في HTML الخاص بك.

### أدوات التصميم المتجاوب

يستخدم Tailwind بادئات مثل `sm:`, `md:`, و `lg:` لتطبيق الأنماط عند أحجام شاشة مختلفة.

```html
<div class="w-full md:w-1/2 lg:flex-row">
  Responsive layout
</div>
```

### أدوات Flexbox

أصناف مثل `flex`, `flex-col`, `justify-around`, و `items-center` تسهل إنشاء تخطيطات مرنة.

```html
<div class="flex flex-col md:flex-row justify-around items-center">
  <p>Column on small screens</p>
  <p>Row on medium and larger screens</p>
</div>
```

### أدوات الشبكة (Grid)

يشمل Tailwind أدوات لـ CSS Grid، مثل `grid`, `grid-cols-1`, و `md:grid-cols-3`.

```html
<div class="grid grid-cols-1 md:grid-cols-3 gap-8">
  <div class="bg-gray-100 p-4">Column 1</div>
  <div class="bg-gray-100 p-4">Column 2</div>
  <div class="bg-gray-100 p-4">Column 3</div>
</div>
```

### أدوات التباعد

أدوات مثل `mt-8`, `mx-auto`, `p-4`, و `gap-4` تساعد في إنشاء تباعد متناسق دون كتابة CSS.

```html
<div class="mt-8 p-4 bg-indigo-600 text-white">
  Spaced content
</div>
```

### أدوات الطباعة

أدوات مثل `uppercase`, `font-bold`, `font-semibold`, و `text-4xl` تتحكم في مظهر النص.

يمكنك تعيين أحجام الخطوط التي تتكيف عند نقاط التوقف، مثل `text-3xl` و `md:text-5xl`.

```html
<h1 class="text-3xl md:text-5xl font-semibold text-center">
  Responsive Heading
</h1>
```

### الألوان وحالات التحويم

يوفر Tailwind لوحة ألوان واسعة، مثل `text-red-700`, `bg-indigo-600`, و `bg-gray-100`.

أصناف مثل `hover:bg-pink-600` تجعل التأثيرات التفاعلية بسيطة.

```html
<a href="#" class="bg-pink-500 hover:bg-pink-600 text-white px-4 py-2 rounded-md">
  Hover Me
</a>
```

### الحدود، الحلقات، والتأثيرات

- **الحدود**: `border-2 border-red-300` تضيف حدودًا بسماكة وألوان محددة.
- **الحلقات**: `ring-1 ring-gray-300` تخلق تأثيرات تشبه الإطار تُستخدم غالبًا للتركيز أو البطاقات.
- **الزوايا المستديرة والتكبير**: أصناف مثل `rounded-md`, `rounded-xl`, و `scale-105` تضيف لمسة نهائية.

```html
<div class="p-6 rounded-xl ring-2 ring-fuchsia-500 scale-105">
  Highlighted card
</div>
```

### التدرجات

يدعم Tailwind أدوات التدرجات اللونية مثل `bg-gradient-to-r from-fuchsia-500 to-indigo-600`.

```html
<div class="p-4 text-white bg-gradient-to-r from-fuchsia-500 to-indigo-600">
  Gradient background
</div>
```

## معالجات CSS المسبقة

- **مُعالج CSS مسبق**: هو أداة توسع CSS القياسي. يقوم بترجمة الكود بصيغة موسعة إلى ملف CSS أصلي. يساعد في كتابة CSS أنظف، قابل لإعادة الاستخدام، أقل تكرارًا، وقابل للتوسع للمشاريع المعقدة.
- **الميزات**: بعض الميزات التي توفرها معالجات CSS المسبقة تشمل المتغيرات، الخلائط، التداخل، ووراثة المحددات.
- **معالجات CSS المسبقة الشهيرة**: من أشهرها Sass، Less، و Stylus.
- **العيوب المحتملة**:
  - ترجمة قواعد CSS إلى CSS قياسي قد تسبب عبئًا إضافيًا.
  - قد يكون الكود المترجم صعب التصحيح.

## Sass

- **Sass**: هو واحد من أشهر معالجات CSS المسبقة. Sass تعني "أوراق الأنماط الرائعة نحويًا".
- **الميزات المدعومة في Sass**: يدعم Sass ميزات مثل المتغيرات، قواعد CSS المتداخلة، الوحدات، الخلائط، الوراثة، والمشغلين للعمليات الرياضية الأساسية.

## نوعان من الصيغ المدعومة في Sass

- **صيغة SCSS**: SCSS (Sassy CSS) توسع الصيغة الأساسية لـ CSS. هي الصيغة الأكثر استخدامًا في Sass. ملفات SCSS تحمل الامتداد `.scss`.

هنا مثال على تعريف واستخدام متغير في SCSS.

```scss
$primary-color: #3498eb;

header {
  background-color: $primary-color;
}
```

- **الصيغة المتداخلة (Indented syntax)**: كانت الصيغة المتداخلة هي الصيغة الأصلية لـ Sass وتعرف أيضًا باسم "صيغة Sass".

هنا مثال على تعريف واستخدام متغير في الصيغة المتداخلة.

```sass
$primary-color: #3498eb

header
  background-color: $primary-color
```

### الخلائط (Mixins)

- **الخلائط (Mixins)**: تسمح لك الخلائط بتجميع عدة خصائص CSS وقيمها تحت اسم واحد وإعادة استخدام ذلك الكتلة من كود CSS في جميع أنحاء ملف الأنماط الخاص بك.

هنا مثال على تعريف خليط في صيغة SCSS. في هذه الحالة، الخليط يسمى `center-flex`. يحتوي على ثلاث خصائص CSS لمركزة العناصر باستخدام flexbox.

```scss
@mixin center-flex {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

هنا مثال على استخدام الخليط الذي عرّفته.

```scss
section {
  @include center-flex;
  height: 500px;
  background-color: #3289a8;
}
```

## الاختبار اليدوي والآلي

- **الاختبار اليدوي**: في الاختبار اليدوي، يقوم المختبر بفحص كل جزء من التطبيق يدويًا واختبار الميزات المختلفة للتأكد من أنها تعمل بشكل صحيح. إذا تم اكتشاف أي أخطاء برمجية أثناء الاختبار، يقوم المختبر بإبلاغ فريق البرمجيات ليتم إصلاحها.
- **الاختبار الآلي**: في الاختبار الآلي، يمكنك أتمتة اختباراتك بكتابة برنامج منفصل يتحقق مما إذا كان التطبيق يتصرف كما هو متوقع.

## اختبار الوحدة

- **اختبار الوحدة**: في اختبار الوحدة، تختبر كل دالة للتأكد من أن كل شيء يعمل كما هو متوقع. يمكن لاختبارات الوحدة أن تكون أيضًا شكلًا من أشكال التوثيق لتطبيقك لأنها تمثل السلوك المتوقع لكودك.
- **مبدأ المسؤولية الواحدة**: يوصي هذا المبدأ بالحفاظ على كل دالة صغيرة ومسؤولة عن شيء واحد.
- **أُطُر اختبار جافاسكريبت الشائعة**: تشمل Jest، Mocha، و Vitest. Jest هو إطار اختبار شائع لاختبارات الوحدة.

إليك مثالًا على اختبارات الوحدة باستخدام Jest.

أولًا، يمكنك إنشاء دالة مسؤولة عن إرجاع سلسلة نصية جديدة بتنسيق معين:

```javascript
export function getFormattedWord(str) {
  if (!str) return '';
  return str.charAt(0).toUpperCase() + str.slice(1);
}
```

في ملف منفصل باسم `getFormattedWord.test.js`، يمكنك كتابة بعض الاختبارات للتحقق من أن الدالة تعمل كما هو متوقع. سيبدو ملف `getFormattedWord.test.js` كالتالي:

```javascript
import { getFormattedWord } from "./getFormattedWord.js";
import { test, expect } from "jest";

test('capitalizes the first letter of a word', () => {
  expect(getFormattedWord('hello')).toBe('Hello');
});
```

- **دالة `expect`**: تُستخدم دالة `expect` لاختبار قيمة.
- **Matcher**: Matcher هي دالة تتحقق مما إذا كانت القيمة تتصرف كما هو متوقع. في المثال أعلاه، الـ matcher هو `toBe()`. لدى Jest مجموعة متنوعة من matchers.

لاستخدام Jest، تحتاج أولًا إلى تثبيت حزمة `jest` باستخدام `npm i jest`. ستحتاج أيضًا إلى إضافة سكربت إلى ملف `package.json` مثل هذا:

```js
"scripts": {
  "test": "jest"
},
```

بعدها، يمكنك تشغيل الأمر `npm run test` لتشغيل اختباراتك.

## دورة حياة تطوير البرمجيات

- **مراحل مختلفة من دورة حياة تطوير البرمجيات**:
  - **مرحلة التخطيط**: يجمع فريق التطوير متطلبات العمل المقترح من أصحاب المصلحة.
  - **مرحلة التصميم**: يقوم فريق البرمجيات بتفصيل المتطلبات ويقرر أفضل الطرق للحلول.
  - **مرحلة التنفيذ**: يقوم فريق البرمجيات بتقسيم المتطلبات إلى مهام قابلة للإدارة وينفذها.
  - **مرحلة الاختبار**: تشمل الاختبار اليدوي والآلي للعمل الجديد. أحيانًا يختبر الفريق التطبيق طوال مرحلة التطوير بأكملها لاكتشاف وإصلاح أي مشاكل تظهر.
  - **مرحلة التشغيل**: ينشر الفريق التغييرات الجديدة إلى بيئة البناء أو الاختبار.
  - **مرحلة الصيانة**: تشمل إصلاح أي مشاكل تظهر من العملاء في التطبيق الإنتاجي.

- **نماذج مختلفة لدورة حياة تطوير البرمجيات**:
  - **نموذج الشلال**: نموذج الشلال يتطلب إكمال كل مرحلة من دورة الحياة قبل بدء المرحلة التالية.
  - **نموذج أجايل**: يركز نموذج أجايل على التطوير التكراري بتقسيم العمل إلى دفعات قصيرة (sprints).

## تطوير قائم على الاختبار (BDD) وتطوير مدفوع بالاختبار (TDD)

- **TDD**: تطوير مدفوع بالاختبار هو منهجية تركز على كتابة الاختبارات أولًا. كتابة الاختبارات قبل بناء الميزات توفر تغذية راجعة فورية للمطورين أثناء عملية التطوير.
- **BDD**: تطوير قائم على السلوك هو نهج يربط سلسلة من الاختبارات بأهداف العمل. يجب كتابة سيناريوهات الاختبار في BDD بلغة يفهمها الفنيون وغير الفنيين. مثال على هذه الصيغة هو Gherkin.
- **أطر اختبار BDD**: أمثلة على أطر اختبار BDD تشمل Cucumber وJBehave وSpecFlow.

## التحققات في اختبار الوحدة

- **التحقق (Assertion)**: تُستخدم التحققات لاختبار أن الكود يتصرف كما هو متوقع.
- **مكتبات التحقق**: Chai هي مكتبة تحقق شائعة الاستخدام. مكتبات تحقق جافاسكريبت أخرى شائعة هي `should.js` و `expect.js`.

إليك مثالًا على تحقق باستخدام Chai يتأكد من أن قيمة الإرجاع من دالة `addThreeAndFour` تساوي الرقم 7:

```js
assert.equal(addThreeAndFour(), 7);
```

- **أفضل الممارسات**: بغض النظر عن مكتبة التحقق التي تستخدمها، يجب كتابة رسائل تحقق وفشل واضحة تساعدك على فهم أي الاختبارات تفشل ولماذا.

## المحاكاة، التزييف، والتثبيت

- **المحاكاة**: المحاكاة هي عملية استبدال البيانات الحقيقية ببيانات زائفة تحاكي سلوك المكونات الحقيقية. على سبيل المثال، يمكنك محاكاة استجابة API في الاختبار بدلاً من إجراء استدعاءات API مستمرة لجلب البيانات.
- **التثبيت**: التثبيتات هي كائنات تُرجع استجابات محددة مسبقًا أو بيانات وهمية لسلوك متوقع في التطبيق. على سبيل المثال، يمكنك تثبيت سلوك اتصال قاعدة بيانات في اختباراتك دون الاعتماد على اتصال قاعدة بيانات حقيقي.
- **التزييف**: التزييفات هي نسخ مبسطة من المكونات الحقيقية بدون التعقيد أو التأثيرات الجانبية. على سبيل المثال، يمكنك تزييف قاعدة بيانات بتخزين البيانات في الذاكرة بدلاً من التفاعل مع قاعدة البيانات الحقيقية. هذا يسمح بمحاكاة عمليات قاعدة البيانات في الذاكرة، مما يكون أسرع بكثير من التعامل مع قاعدة البيانات الحقيقية.

## الاختبار الوظيفي

- **الاختبار الوظيفي**: يتحقق الاختبار الوظيفي مما إذا كانت ميزات ووظائف التطبيق تعمل كما هو متوقع. الهدف من الاختبار الوظيفي هو اختبار النظام ككل مقابل سيناريوهات متعددة.
- **الاختبار غير الوظيفي**: يركز الاختبار غير الوظيفي على أشياء مثل الأداء والموثوقية.
- **اختبار الدخان**: اختبار الدخان هو فحص أولي للنظام للتحقق من وجود مشاكل أساسية أو حرجة قبل بدء اختبار أكثر شمولًا.

## اختبار من النهاية إلى النهاية

- **اختبار من النهاية إلى النهاية**: اختبار من النهاية إلى النهاية، أو E2E، يختبر سيناريوهات العالم الحقيقي من منظور المستخدم. تساعد اختبارات النهاية إلى النهاية على ضمان أن التطبيق يتصرف بشكل صحيح ومتوقع للمستخدمين. مع ذلك، إعدادها وتصميمها وصيانتها يستغرق وقتًا.
- **أطر اختبار من النهاية إلى النهاية**: Playwright هو إطار اختبار من النهاية إلى النهاية شائع طورته Microsoft. أمثلة أخرى لأدوات اختبار من النهاية إلى النهاية تشمل Cypress وSelenium وPuppeteer.

هنا مثال لاختبارات نهاية إلى نهاية (E2E) من قاعدة كود freeCodeCamp باستخدام Playwright. سيعمل الخطاف `beforeEach` قبل كل اختبار. تتحقق الاختبارات من أن المتبرع لديه رابط داعم في شريط القائمة، بالإضافة إلى حدود خاصة مصممة حول الصورة الرمزية الخاصة به:

```js
test.beforeEach(async ({ page }) => {
  execSync("node ./tools/scripts/seed/seed-demo-user --set-true isDonating");
  await page.goto("/donate");
});

...

test("The menu should have a supporters link", async ({ page }) => {
  const menuButton = page.getByTestId("header-menu-button");
  const menu = page.getByTestId("header-menu");

  await expect(menuButton).toBeVisible();
  await menuButton.click();

  await expect(menu).toBeVisible();

  await expect(page.getByRole("link", { name: "Supporters" })).toBeVisible();
});

test("The Avatar should have a special border for donors", async ({ page }) => {
  const container = page.locator(".avatar-container");
  await expect(container).toHaveClass("avatar-container gold-border");
});
```

## اختبار سهولة الاستخدام

- **اختبار سهولة الاستخدام**: اختبار سهولة الاستخدام هو عندما يتفاعل المستخدمون الحقيقيون مع التطبيق لاكتشاف ما إذا كانت هناك أي مشاكل في التصميم أو تجربة المستخدم أو الوظائف في التطبيق. يركز اختبار سهولة الاستخدام على مدى سهولة استخدام التطبيق من قبل المستخدمين.
- **أربعة أنواع شائعة من اختبار سهولة الاستخدام**:
  - **استكشافي**: يتضمن اختبار سهولة الاستخدام الاستكشافي تفاعل المستخدمين مع الميزات المختلفة للتطبيق لفهم كيفية عملها بشكل أفضل.
  - **مقارن**: هو مقارنة تجربة المستخدم في تطبيقك مع تطبيقات مشابهة في السوق.
  - **تقييمي**: دراسة مدى سهولة استخدام التطبيق.
  - **تحققي**: تحديد أي مشاكل كبيرة قد تمنع المستخدم من استخدام التطبيق بفعالية.
- **أدوات اختبار سهولة الاستخدام**: أمثلة على الأدوات تشمل Loop11 وMaze وUserbrain وUserTesting وUXTweak.

## اختبار التوافق

- **اختبار التوافق**: الهدف من اختبار التوافق هو التأكد من أن تطبيقك يعمل في بيئات حوسبة مختلفة.
- **أنواع مختلفة من اختبار التوافق**:
  - **التوافق مع الإصدارات السابقة**: يشير إلى أن البرنامج متوافق مع الإصدارات الأقدم.
  - **التوافق مع الإصدارات المستقبلية**: يشير إلى أن البرنامج والأنظمة ستعمل مع الإصدارات المستقبلية.
  - **التوافق مع الأجهزة**: قدرة البرنامج على العمل بشكل صحيح في تكوينات أجهزة مختلفة.
  - **التوافق مع أنظمة التشغيل**: قدرة البرنامج على العمل على أنظمة تشغيل مختلفة مثل macOS وWindows وتوزيعات Linux مثل Ubuntu وFedora.
  - **التوافق مع الشبكة**: يعني أن البرنامج يمكنه العمل في ظروف شبكة مختلفة مثل سرعات الشبكة المختلفة، البروتوكولات، إعدادات الأمان، وغيرها.
  - **التوافق مع المتصفحات**: يعني أن تطبيق الويب يمكنه العمل بشكل متسق عبر متصفحات مختلفة مثل Google Chrome وSafari وFirefox.
  - **التوافق مع الأجهزة المحمولة**: من المهم التأكد من أن تطبيقاتك البرمجية تعمل على مجموعة متنوعة من أجهزة Android وiOS، بما في ذلك الهواتف والأجهزة اللوحية.

## اختبار الأداء

- **اختبار الأداء**: في اختبار الأداء، تختبر سرعة التطبيق، استجابته، قابليته للتوسع، واستقراره تحت أعباء عمل مختلفة. الهدف هو حل أي عنق زجاجة في الأداء.
- **أنواع مختلفة من اختبار الأداء**:
  - **اختبار التحميل**: يحدد كيف يتصرف النظام أثناء أوقات الحمل العادي والذروة.
  - **اختبار الضغط**: تختبر التطبيق تحت أعباء قصوى لترى كيف يستجيب النظام للحمل العالي.
  - **اختبار التحمل (اختبار النقع)**: نوع من اختبار التحميل حيث تختبر النظام بحمل مرتفع لفترة طويلة.
  - **اختبار الارتفاع المفاجئ**: حيث تزيد وتنقص الأحمال بشكل كبير وتحلل ردود فعل النظام على التغييرات.
  - **اختبار نقطة الانهيار (اختبار السعة)**: حيث تزيد الحمل ببطء مع الوقت حتى يبدأ النظام في الفشل أو التدهور.

## اختبار الأمان

- **اختبار الأمان**: يساعد اختبار الأمان في تحديد الثغرات والضعف.
- **مبادئ الأمان**:
  - **السرية**: تحمي من تسريب المعلومات الحساسة إلى مستلمين غير مقصودين.
  - **النزاهة**: تمنع المستخدمين الخبيثين من تعديل معلومات المستخدم.
  - **التوثيق**: تتحقق من هوية المستخدم لضمان السماح له باستخدام النظام.
  - **التفويض**: هي عملية تحديد الإجراءات التي يُسمح للمستخدمين المُوثَّقين بأدائها أو الأجزاء التي يمكنهم الوصول إليها.
  - **التوفر**: تضمن توفر المعلومات والخدمات للمستخدمين المصرح لهم عند الحاجة.
  - **عدم التنصل**: تضمن أن كلًا من المرسل والمستلم لديهما إثبات التسليم والتحقق من هوية المرسل. تحمي من إنكار المرسل لإرسال المعلومات.
- **التهديدات الأمنية الشائعة**:
  - **البرمجة عبر المواقع (XSS)**: تحدث عندما يحقن المهاجمون سكربتات خبيثة في صفحة ويب ثم ينفذونها في سياق متصفح الضحية.
  - **حقن SQL**: يسمح للمستخدمين الخبيثين بحقن كود خبيث في قاعدة البيانات.
  - **هجوم حجب الخدمة (DoS)**: عندما يفيض المستخدمون الخبيثون موقعًا بعدد كبير من الطلبات أو الحركة، مما يبطئ الخادم أو يتسبب في تعطل الموقع، فيصبح غير متاح للمستخدمين.
- **فئات أدوات اختبار الأمان**:
  - **اختبار أمان التطبيقات الثابت (SAST)**: تقيم هذه الأدوات الكود المصدري للتطبيق لتحديد الثغرات الأمنية.
  - **اختبار أمان التطبيقات الديناميكي (DAST)**: تتفاعل هذه الأدوات مع واجهة التطبيق الأمامية لاكتشاف نقاط الضعف الأمنية المحتملة. لا تمتلك أدوات DAST وصولًا إلى الكود المصدري.
- **اختبار الاختراق (pentest)**: هو نوع من اختبار الأمان يتضمن إنشاء هجمات إلكترونية محاكاة على التطبيق لتحديد أي ثغرات في النظام.

## اختبار A/B

- **اختبار A/B**: يتضمن اختبار A/B مقارنة نسختين من صفحة أو تطبيق ودراسة أي نسخة تؤدي أداءً أفضل. يُعرف أيضًا باسم اختبار الدلو أو التقسيم. يسمح اختبار A/B باتخاذ قرارات أكثر اعتمادًا على البيانات وتحسين تجربة المستخدم باستمرار.
- **أدوات اختبار A/B**: أمثلة على الأدوات المستخدمة لاختبار A/B تشمل GrowthBook وLaunchDarkly.

## اختبار ألفا وبيتا

بعد الانتهاء من التطوير الأولي واختبار البرمجيات، من المهم اختبار التطبيق بواسطة مختبرين ومستخدمين حقيقيين. هنا يأتي دور اختبار ألفا وبيتا.

- **اختبار ألفا**: يتم اختبار ألفا بواسطة مجموعة مختارة من المختبرين الذين يفحصون التطبيق للتأكد من عدم وجود أخطاء قبل إصداره في السوق. اختبار ألفا هو جزء من اختبار القبول ويستخدم تقنيات اختبار الصندوق الأبيض والأسود.
- **اختبار بيتا**: اختبار بيتا هو عندما يُتاح التطبيق للمستخدمين الحقيقيين. يمكن للمستخدمين التفاعل مع التطبيق وتقديم الملاحظات. اختبار بيتا هو أيضًا شكل من أشكال اختبار قبول المستخدم.
- **اختبار القبول**: يضمن اختبار القبول أن تطبيق البرمجيات يلبي متطلبات العمل واحتياجات المستخدمين قبل إصداره.
- **اختبار الصندوق الأسود**: يركز فقط على السلوك المتوقع للتطبيق.
- **اختبار الصندوق الأبيض**: يتضمن معرفة المختبر بالمكونات الداخلية وإجراء اختبارات عليها.

## اختبار الانحدار

- **الارتداد (Regression)**: يشير إلى الحالات التي تكسر فيها التغييرات الجديدة الوظائف القائمة عن غير قصد.
- **اختبار الارتداد**: يساعد في اكتشاف مشاكل الارتداد. في اختبار الارتداد، تعيد تشغيل اختبارات وظيفية على أجزاء من تطبيقك للتأكد من أن كل شيء لا يزال يعمل كما هو متوقع.
- **أدوات اختبار الارتداد**: تشمل Puppeteer، Playwright، Selenium، و Cypress.
- **تقنيات اختبار الارتداد**:
  - **اختبار الارتداد للوحدة**: حيث يكون لديك قائمة بالعناصر التي يجب اختبارها في كل مرة يتم فيها تنفيذ تغييرات أو إصلاحات كبيرة في التطبيق.
  - **اختبار الارتداد الجزئي**: يتضمن نهجًا مستهدفًا لضمان أن التغييرات الجديدة لم تكسر جوانب محددة من التطبيق.
  - **اختبار الارتداد الكامل**: يشغل اختبارات على جميع الوظائف في قاعدة الكود. هذا هو الخيار الأكثر استهلاكًا للوقت والأكثر تفصيلًا.
- **إعادة الاختبار**: تُستخدم للتحقق من المشكلات المعروفة والتأكد من حلها. بالمقابل، يبحث اختبار الارتداد عن مشكلات غير معروفة قد تكون حدثت بسبب تغييرات حديثة في قاعدة الكود.

## ما هو TypeScript

- **JavaScript**: جافاسكريبت لغة ذات نوع ديناميكي. هذا يعني أن المتغيرات يمكن أن تستقبل أي قيم أثناء وقت التشغيل. التحدي في لغة ذات نوع ديناميكي هو أن غياب أمان النوع قد يُدخل أخطاء.

على سبيل المثال، حتى لو كانت دالتك في جافاسكريبت تتوقع مصفوفة، يمكنك مع ذلك استدعاؤها برقم:

```javascript
const getRandomValue = (array) => {
  return array[Math.floor(Math.random() * array.length)];
}

console.log(getRandomValue(10));
```

الناتج في الـ`console` للمثال أعلاه سيكون `undefined`.

- **TypeScript**: توسع TypeScript لغة جافاسكريبت لتشمل الكتابة الثابتة، مما يساعد في اكتشاف الأخطاء الناتجة عن عدم تطابق الأنواع قبل تشغيل الكود.

على سبيل المثال، يمكنك تعريف نوع للمعلمة `array` كما يلي:

```typescript
const getRandomValue = (array: string[]) => {
  return array[Math.floor(Math.random() * array.length)];
}
```

تعريف النوع هذا يخبر TypeScript أن المعلمة `array` يجب أن تكون مصفوفة من سلاسل نصية. ثم، عندما تستدعي `getRandomValue` وتمرر لها رقمًا، تحصل على خطأ يُسمى خطأ المترجم.

- **المُجمِّع (Compiler)**: تحتاج أولًا إلى تجميع كود TypeScript إلى جافاسكريبت عادية. عند تشغيل المُجمِّع، يقوم TypeScript بتقييم كودك ويرجع خطأً لأي مشاكل في عدم تطابق الأنواع.

## أنواع البيانات في TypeScript

- **أنواع البيانات الأولية في TypeScript**: لأنواع البيانات الأولية `string`، `null`، `undefined`، `number`، `boolean`، و`bigint`، يقدم TypeScript الكلمات المفتاحية المناسبة للنوع.

```typescript
let str: string = "Naomi";
let num: number = 42;
let bool: boolean = true;
let nope: null = null;
let nada: undefined = undefined;
```

- **مصفوفة**: يمكنك تعريف مصفوفة من نوع محدد باستخدام صيغتين مختلفتين.

```typescript
const arrOne: string[] = ["Naomi"];
const arrTwo: Array<string> = ["Camperchan"];
```

- **الكائنات**: يمكنك تعريف الهيكل الدقيق لكائن.

```typescript
const obj: { a: string, b: number } = { a: "Naomi", b: 42 };
```

إذا أردت كائنًا بأي مفاتيح، لكن يجب أن تكون كل القيم سلاسل نصية، هناك طريقتان لتعريفه:

```typescript
const objOne: Record<string, string> = {};
const objTwo: { [key: string]: string } = {};
```

- **أنواع أخرى مفيدة في TypeScript**:
  - **`any`**: `any` تشير إلى أن القيمة يمكن أن تكون من أي نوع. تخبر المترجم بالتوقف عن الاهتمام بنوع ذلك المتغير.
  - **`unknown`**: `unknown` تخبر TypeScript بأنك تهتم بنوع القيمة، لكنك لا تعرف ما هو فعليًا. يُفضل استخدام `unknown` على `any`.
  - **`void`**: هذا نوع خاص تستخدمه عادة عند تعريف الدوال. الدوال التي لا تُرجع قيمة تستخدم نوع إرجاع `void`.
  - **`never`**: يمثل نوعًا لن يوجد أبدًا.

- **الكلمة المفتاحية `type`**: هذه الكلمة تشبه `const`، لكن بدلًا من إعلان متغير، يمكنك إعلان نوع.

مفيدة لإعلان أنواع مخصصة مثل أنواع الاتحاد أو الأنواع التي تشمل قيمًا محددة فقط:

```typescript
type stringOrNumber = string | number;
type bot = "camperchan" | "camperbot" | "naomi";
```

- **`interface`**: الواجهات تشبه الأصناف للأنواع. يمكنها تنفيذ أو توسيع واجهات أخرى، وهي أنواع كائنات بشكل خاص، وعادة ما تُفضل إلا إذا كنت تحتاج ميزة محددة تقدمها إعلان `type`.

```typescript
interface wowie {
  zowie: boolean;
  method: () => void;
}
```

- **تعريف نوع الإرجاع**: يمكنك أيضًا تعريف _نوع الإرجاع_ للدالة.

المثال أدناه يحدد قيمة الإرجاع كسلسلة نصية. إذا حاولت إرجاع أي شيء آخر، سيعطي TypeScript خطأ مترجم.

```typescript
const getRandomValue = (array: string[]): string => {
  return array[Math.floor(Math.random() * array.length)];
}
```

## الأنواع العامة (Generics)

- **تعريف النوع العام**: يمكنك تعريف نوع عام والإشارة إليه في دالتك. يمكن اعتباره معلمة خاصة تقدمها للدالة للتحكم في سلوك تعريف نوع الدالة.

إليك مثالًا لتعريف نوع عام لدالة:

```typescript
const getRandomValue = <T>(array: T[]): T => {
  return array[Math.floor(Math.random() * array.length)];
}
const val = getRandomValue([1, 2, 4])
```

الصيغة `<T>` تخبر TypeScript بأنك تعرف نوعًا عامًا اسمه `T` للدالة. `T` اسم شائع للأنواع العامة، لكن يمكنك استخدام أي اسم.

ثم تخبر TypeScript أن المعلمة `array` هي مصفوفة من القيم التي تطابق النوع العام، وأن القيمة المرجعة هي عنصر واحد من نفس النوع.

- **تحديد معلمة النوع في استدعاء الدالة**: يمكنك تمرير معلمة نوع لاستدعاء دالة باستخدام أقواس زاوية بين اسم الدالة ومعلماتها.

إليك مثالًا لتمرير معلمة نوع لاستدعاء دالة:

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

هذا يخبر TypeScript أن العنصر الذي تتوقع العثور عليه سيكون عنصر إدخال.

## تضييق النوع (Type Narrowing)

- **التضييق بالتحقق من الحقيقة**: في المثال أدناه، تحصل على خطأ مترجم عند محاولة الوصول إلى خاصية `value` لـ`email` لأن `email` _قد_ تكون `null`.

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

يمكنك استخدام شرط للتأكد من أن `email` هي _حقيقية_ قبل الوصول إلى الخاصية:

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
if (email) {
  console.log(email.value);
}
```

يمكن أن تعمل فحوصات الحقيقة أيضًا في الاتجاه العكسي:

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
if (!email) {
  throw new ReferenceError("Could not find email element!")
}
console.log(email.value);
```

رمي خطأ ينهي التنفيذ المنطقي لهذا الكود، مما يعني أنه عند الوصول إلى استدعاء `console.log()`، يعرف TypeScript أن `email` _لا يمكن_ أن تكون `null`.

- **التسلسل الاختياري**: التسلسل الاختياري `?.` هو أيضًا شكل من أشكال تضييق النوع، على نفس المبدأ بأن الوصول إلى الخاصية لا يمكن أن يحدث إذا كانت قيمة `email` هي `null`.

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email?.value);
```

- **عامل `typeof`**: يمكنك استخدام شرط للتحقق من نوع المتغير باستخدام عامل `typeof`.

```typescript
const myVal = Math.random() > 0.5 ? 222 : "222";
if (typeof myVal === "number") {
  console.log(myVal / 10);
}
```

- **الكلمة المفتاحية `instanceof`**: إذا كان الكائن من صنف، يمكنك استخدام الكلمة المفتاحية `instanceof` لتضييق النوع.

```typescript
const email = document.querySelector("#email");

if (email instanceof HTMLInputElement) {
    console.log(email.value);
}
```

- **التحويل (Casting)**: عندما لا يستطيع TypeScript تحديد نوع القيمة تلقائيًا، مثل نتيجة دالة `request.json()` في المثال أدناه، ستحصل على خطأ مترجم. إحدى الطرق لحل ذلك هي تحويل النوع، لكن هذا يضعف قدرة TypeScript على اكتشاف الأخطاء المحتملة.

```typescript
interface User {
    name: string;
    age: number;
}

const printAge = (user: User) => 
  console.log(`${user.name} is ${user.age} years old!`)

const request = await fetch("url")
const myUser = await request.json() as User;
printAge(myUser);
```

- **حارس النوع (Type Guard)**: بدلًا من تحويل النوع، يمكنك كتابة حارس نوع:

```typescript
interface User {
    name: string;
    age: number;
}

const isValidUser = (user: unknown): user is User => {
  return !!user && 
    typeof user === "object" &&
    "name" in user &&
    "age" in user;
}
```

الصيغة `user is User` تشير إلى أن دالتك تُرجع قيمة منطقية، وعندما تكون صحيحة تعني أن قيمة `user` تفي بواجهة `User`.

## ملف `tsconfig`

- **`tsconfig.json`**: إعدادات مترجم TypeScript موجودة في ملف `tsconfig.json` في الدليل الجذري لمشروعك.

```json
{
  "compilerOptions": {
    "rootDir": "./src",
    "outDir": "./prod",
    "lib": ["ES2023"],
    "target": "ES2023",
    "module": "ES2022",
    "moduleResolution": "Node",
    "esModuleInterop": true,
    "skipLibCheck": true,
    "strict": true
  },
  "exclude": ["test/"]
}
```

إليك وصفًا لخيارات المترجم المستخدمة في المثال أعلاه:

- **`compilerOptions`**: خاصية `compilerOptions` هي المكان الذي تتحكم فيه بكيفية تصرف مُجمِّع TypeScript.
- **`rootDir` و `outDir`**: تحدد `rootDir` و `outDir` المجلد الذي يحتوي على ملفات المصدر، والمجلد الذي يجب أن يحتوي على كود جافاسكريبت المترجم.
- **`lib`**: تحدد خاصية `lib` تعريفات الأنواع التي يستخدمها المُجمِّع، وتسمح لك بتضمين دعم لإصدارات ES محددة، و DOM، وأكثر.
- **`module` و `moduleResolution`**: تعمل `module` و `moduleResolution` معًا لإدارة كيفية استخدام حزمتك للوحدات - إما CommonJS أو ECMAScript.
- **`esModuleInterop`**: يسمح `esModuleInterop` بتشغيل أكثر سلاسة بين CommonJS و ES modules من خلال إنشاء كائنات مساحة أسماء تلقائيًا للاستيراد.
- **`skipLibCheck`**: خيار `skipLibCheck` يتخطى التحقق من ملفات `.d.ts` التي لا يتم الإشارة إليها بواسطة الاستيرادات في كودك.
- **`strict`**: يُفعِّل العلم `strict` عدة فحوصات، مثل ضمان التعامل الصحيح مع الأنواع القابلة لأن تكون null وتحذير عند الرجوع إلى `any`.
- **`exclude`**: خاصية `exclude` على المستوى الأعلى تخبر المُجمِّع بتجاهل ملفات TypeScript هذه أثناء الترجمة.
