## Pythonの一般的なエラー

- **`SyntaxError`**: コードがPythonの構文ルールに従っていない場合にPythonが発生させるエラーです。例えば、`print("Hello there"` というコードは、閉じカッコが抜けているため、`SyntaxError: '(' was never closed` というメッセージの構文エラーになります。
- **`NameError`**: 定義していない変数や関数にアクセスしようとすると、Pythonは `NameError` を発生させます。例えば、コード内に `print(username)` という行があるのに、先に `username` 変数を定義していない場合、`NameError: name 'username' is not defined` というメッセージの名前エラーが表示されます。
- **`TypeError`**: 不適切な型のオブジェクトに対して操作や関数を適用したときにPythonが発生させるエラーです。例えば、文字列と数値を足そうとすると、`TypeError: can only concatenate str (not "int") to str` というエラーになります。
- **`IndexError`**: リストや、タプル・文字列などのシーケンスに存在しないインデックスにアクセスすると `IndexError` が発生します。例えば、`Hello world` という文字列では、最後の文字のインデックスは `10` です。`greet = "hello world"; print(greet[11])` のようにアクセスすると、`IndexError: string index out of range` というメッセージのエラーが表示されます。
- **`AttributeError`**: その型のオブジェクトに存在しないメソッドやプロパティを使おうとすると、Pythonはこのエラーを発生させます。例えば、`"hello".append("!")` のように文字列に対して `.append()` を呼び出すと、`AttributeError: 'str' object has no attribute 'append'` というメッセージのエラーになります。

## Pythonの良いデバッグ技術

- **`print` 関数の使用**: デバッグ中にコードのさまざまな箇所に `print()` 文を挿入すると、変数の値やコードの流れを確認できます。
- **Pythonの組み込みデバッガー（`pdb`）の使用**: Python標準ライブラリの一部である `pdb` モジュールを使うとデバッグができます。`pdb.set_trace()` を呼び出すと実行が一時停止し、対話型プロンプトが開きます。`help` でコマンド一覧、`whatis` で式の型を調べ、`continue`（別名 `cont` や `c`）でプログラムの実行を再開できます。
- **IDEのデバッグツールの活用**: PyCharmやVS Codeなどの統合開発環境やコードエディターは視覚的なデバッグツールを提供します。例えばVS Codeでは以下の機能があります：
  - **ブレークポイント**: エディターのガターをクリックすると、実行を一時停止するブレークポイント（赤い点）を設定できます。
  - **変数の検査とデバッグコンソール**: 変数にカーソルを合わせたり、変数パネルを見たりして現在の値を確認でき、デバッグコンソールで式を対話的に評価できます。
  - **ステップ操作**:
    - **続行 (<kbd>F5</kbd>)**: 次のブレークポイントまで実行を再開します。
    - **ステップオーバー (<kbd>F10</kbd>)**: 現在の行を実行し、関数呼び出しの中には入らず次の行に進みます。
    - **ステップイン (<kbd>F11</kbd>)**: 呼び出された関数の中に入り、その行をステップ実行します。
    - **ステップアウト (<kbd>Shift</kbd> + <kbd>F11</kbd>)**: 現在の関数の実行を終えて呼び出し元に戻ります。

## 例外処理

- **`try...except`**: 例外が発生する可能性のあるコードブロックを実行するために使います。`try` ブロックはエラーが起こるかもしれない部分で、`except` ブロックは指定した例外が発生したときに実行されます。例を示します：

  ```py
  try:
    print(22 / 0)
  except ZeroDivisionError:
    print('You can\'t divide by zero!')
    # You can't divide by zero!
  ```

  複数の `except` ブロックを連結して、より多くの例外タイプを処理できます。

  ```py
  try:
    number = int(input('Enter a number: '))
    print(22 / number)
  except ZeroDivisionError:
    print('You cannot divide by zero!')
    # You cannot divide by zero! prints when you enter 0
  except ValueError:
    print('Please enter a valid number!')
    # Please enter a valid number! prints when you don't enter an integer
  ```

  複数の例外タイプをタプルでまとめて、1つの `except` 節で捕捉することもできます：

  ```py
  try:
    number = int(input('Enter a number: '))
    result = 10 / number
  except (ValueError, ZeroDivisionError) as e:
    print(f'Error occurred: {e}')
  ```

- **`else` と `finally`**: これらのブロックは `try...except` を拡張します。例外が発生しなければ `else` ブロックが実行されます。`finally` ブロックはエラーの有無にかかわらず常に実行されます。

  ```py
  try:
    result = 100 / 4
  except ZeroDivisionError:
    print('You cannot divide by zero!') # This will not run
  else:
    print(f'Result is {result}') # Result is 25.0
  finally:
    print('Execution complete!') # Execution complete!
  ```

- **例外オブジェクト**: 例外そのものにアクセスしてデバッグやエラーメッセージの直接出力に使えます。例外オブジェクトにアクセスするには `as` キーワードを使います。例：

  ```py
  try:
      value = int('This will raise an error')
  except ValueError as e:
      print(f'Caught an error: {e}')
      # Caught an error: invalid literal for int() with base 10: 'This will raise an error'
  ```

- **`raise` 文**: 例外を手動で発生させるために使います。特定の条件が満たされたときに例外をスローできます：

  ```py
  def divide(a, b):
      if b == 0:
          raise ZeroDivisionError('You cannot divide by zero')
      return a / b
  ```

  `except` ブロック内で引数なしの `raise` を使うと、現在処理中の例外を再スローします。これにより、エラーのログを取ったりクリーンアップを行いながら、例外を呼び出し元に伝播できます：

  ```py
  def process_data(data):
      try:
          result = int(data)
          return result * 2
      except ValueError:
          print('Logging: Invalid data received')
          raise
  ```

- **`assert` 文**: `assert` 文はデバッグ中に仮定をチェックし、条件が偽の場合に `AssertionError` を発生させます。Python は最適化モード（`-O`）で実行するとアサーションを削除するため、常に実行する必要がある重要な入力バリデーションにはアサーションを使わないでください。必要なチェックには明示的な条件と `raise` を使うことをお勧めします。

## 例外の通知

- **カスタム例外**: `raise` 文は `Exception` を継承して独自の例外クラスを作成するときにも役立ちます。これにより、ドメイン固有のロジックやメッセージを持つエラーをスローできます：

  ```py
  class InvalidCredentialsError(Exception):
      def __init__(self, message="Invalid username or password"):
          self.message = message
          super().__init__(self.message)

  def login(username, password):
      stored_username = "admin"
      stored_password = "password123"
      
      if username != stored_username or password != stored_password:
          raise InvalidCredentialsError()
      
      return f"Welcome, {username}!"
  ```

  `InvalidCredentialsError` 例外を使った `login` 関数の利用例は以下の通りです：

  ```py
  # failed login attempt
  try:
      message = login("user", "wrongpassword")
  except InvalidCredentialsError as e:
      print(f"Login failed: {e}")
  else:
      print(message)

  # successful login attempt
  try:
      message = login("admin", "password123")
  except InvalidCredentialsError as e:
      # This block is not executed because the login was successful
      print(f"Login failed: {e}")
  else:
      # The else block runs if the 'try' block completes without an exception
      print(message)
  ```

- **例外のチェーン**: `raise` 文は `from` キーワードと組み合わせて例外をチェーンできます。`from None` は元の例外コンテキストをトレースバックから隠し、`from e` は元の例外を原因として明示的に記録します：

  ```py
  def parse_config(filename):
      try:
          with open(filename, 'r') as file:
              data = file.read()
              return int(data)
      except FileNotFoundError:
          raise ValueError('Configuration file is missing') from None
      except ValueError as e:
          raise ValueError('Invalid configuration format') from e

  config = parse_config('config.txt')
  ```
