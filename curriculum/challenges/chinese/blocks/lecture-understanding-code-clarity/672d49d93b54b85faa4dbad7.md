# --description--

就像句号（`.`）可以标记英文句子的结束一样，分号（`;`）可以用来标记 JavaScript 中语句的结束。然而，语句不一定等同于源代码的行。一个语句可以跨越多行，而一行代码中也可以包含多个语句。

例如：

```js
let variableOne = 5;
let variableTwo = 10;
```

在这段代码中，分号明确标示了每个语句的结束。JavaScript 还有自动分号插入（ASI），它允许这些声明在没有显式分号的情况下仍然有效：

```js
let variableOne = 5
let variableTwo = 10
```

在这个例子中，ASI 允许 JavaScript 将每个声明视为独立的语句，尽管没有分号。然而，ASI 并不是在每个换行处简单地插入分号。

例如，`return` 语句后的换行可能导致意外行为：

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

这里，ASI 在 `return` 后插入了分号，因此函数返回了 `undefined` 而不是对象。将对象写在同一行可以避免这种行为：

```js
function getValue() {
  return {
    value: 42
  };
}
```

这说明了为什么换行和语句边界并不总是相同的。

当换行可能导致两段代码被解释为一个表达式时，分号也很有用。立即调用函数表达式（IIFE）是指定义后立即运行的函数。创建 IIFE 的一种方法是将匿名函数（没有名字的函数）用括号包裹起来，并在末尾加上 `()` 来调用它。当前述语句没有以分号结尾时，IIFE 可能会引发问题：

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

这里，JavaScript 没有在字符串声明后插入分号，因为后面的 `(` 可以继续初始化表达式。JavaScript 将初始化表达式解析为对字符串 `"Hello"` 的调用，并将函数表达式作为参数。这会在 IIFE 运行前抛出 `TypeError`。添加分号可以在 IIFE 之前结束声明：

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

显式分号使变量声明和 IIFE 成为独立的语句。

分号在许多编程语言中都有使用，包括 C、C++ 和 Java。它们的具体规则因语言而异，但通常用于指示语句的结束。

编译器根据语言和编译器的不同，将源代码翻译成另一种形式，如机器码、字节码或中间表示。编译不一定会生成独立的可执行文件。

一致地使用分号可以使语句边界更清晰，让代码更易于阅读和维护。
