### --question--

#### --text--

Wie ist die Beziehung zwischen einer API und einem Webservice?

#### --distractors--

Jede API ist ein Webservice, aber nicht jeder Webservice ist eine API.

---

APIs und Webservices sind identische Konzepte.

---

Webservices funktionieren nur mit REST, während APIs mehrere Protokolle unterstützen.

#### --answer--

Jeder Webservice ist eine API, aber nicht jede API ist ein Webservice.

### --question--

#### --text--

Welche der folgenden Aussagen trifft auf SOAP im Vergleich zu REST zu?

#### --distractors--

SOAP verwendet JSON und ist flexibler als REST, was es ideal für moderne Anwendungen macht.

---

SOAP ist heute der am weitesten verbreitete Webservice-Typ und hat REST in den meisten Systemen ersetzt.

---

SOAP unterstützt mehrere Antwortformate, einschließlich Klartext, JSON und Binärdaten.

#### --answer--

SOAP verwendet nur XML und ist in Unternehmenssystemen üblich, die strengere Standards und Sicherheit benötigen.

### --question--

#### --text--

Was bedeutet Zustandslosigkeit in einer REST-Architektur?

#### --distractors--

Der Server speichert die Sitzungsdaten des Clients zwischen den Anfragen.

---

Der Client behält keinen eigenen Zustand über Anfragen hinweg.

---

REST beschränkt alle Anfragen auf Leseoperationen.

#### --answer--

Der Server speichert keine Erinnerung an vorherige Anfragen.

### --question--

#### --text--

Was ist ein wesentlicher Vorteil von Microservices gegenüber einem Monolithen?

#### --distractors--

Einfacheres Debugging und weniger Netzwerkaufrufe zwischen den Services.

---

Eine einzige gemeinsame Codebasis, zu der alle Teams beitragen.

---

Einfacheres Infrastrukturmanagement über alle Services hinweg.

#### --answer--

Schnellere Entwicklung, bessere Fehlerisolation und die Möglichkeit, pro Service unterschiedliche Sprachen zu verwenden.

### --question--

#### --text--

Welche der folgenden Herausforderungen gibt es bei der Einführung einer Microservices-Architektur?

#### --distractors--

Eine einzelne, gemeinsame Codebasis, die Änderungen leicht koordinierbar macht.

---

Weniger Netzwerkaufrufe sind zwischen den Komponenten erforderlich.

---

Das Debuggen wird einfacher, da der gesamte Code in einem Prozess läuft.

#### --answer--

Das Debuggen wird komplexer, und es gibt mehr Netzwerk-Overhead zwischen den Services.
