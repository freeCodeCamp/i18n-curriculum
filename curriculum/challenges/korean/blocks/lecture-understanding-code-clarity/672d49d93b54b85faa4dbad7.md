# --description--

영어에서 마침표(`.`)가 문장의 끝을 표시하듯, JavaScript에서는 세미콜론(`;`)이 문장의 끝을 표시하는 데 사용될 수 있습니다. 하지만 문장은 반드시 소스 코드의 한 줄과 같지 않습니다. 문장은 여러 줄에 걸칠 수 있고, 한 줄에 여러 문장이 포함될 수도 있습니다.

예를 들어:

```js
let variableOne = 5;
let variableTwo = 10;
```

이 코드에서 세미콜론은 각 문장의 끝을 명확하게 만듭니다. JavaScript에는 명시적인 세미콜론 없이도 이 선언들이 유효하도록 하는 자동 세미콜론 삽입(ASI) 기능도 있습니다:

```js
let variableOne = 5
let variableTwo = 10
```

이 예제에서 ASI는 세미콜론이 없어도 각 선언을 별도의 문장으로 처리하도록 JavaScript가 허용합니다. 하지만 ASI가 단순히 모든 줄 바꿈 뒤에 세미콜론을 삽입하는 것은 아닙니다.

예를 들어, `return` 문 뒤에 줄 바꿈이 있으면 예상치 못한 동작이 발생할 수 있습니다:

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

여기서 ASI는 `return` 뒤에 세미콜론을 삽입하여 함수가 객체 대신 `undefined`를 반환하게 만듭니다. 객체를 같은 줄에 작성하면 이런 동작을 피할 수 있습니다:

```js
function getValue() {
  return {
    value: 42
  };
}
```

이것은 줄 바꿈과 문장 경계가 항상 같은 것이 아님을 보여줍니다.

세미콜론은 줄 바꿈 때문에 두 개의 코드 조각이 하나의 표현식으로 해석될 수 있을 때도 유용합니다. 즉시 실행 함수 표현식(IIFE)은 정의되자마자 실행되는 함수입니다. IIFE를 만드는 한 가지 방법은 이름 없는 함수인 익명 함수를 소괄호로 감싸고 끝에 `()`를 붙여 호출하는 것입니다. 앞선 문장이 세미콜론으로 끝나지 않으면 IIFE가 문제를 일으킬 수 있습니다:

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

여기서 JavaScript는 문자열 선언 뒤에 세미콜론을 삽입하지 않는데, 그 이유는 다음 `(`가 초기화 표현식을 계속할 수 있기 때문입니다. JavaScript는 초기화를 문자열 `"Hello"`에 대한 호출로 파싱하며, 함수 표현식을 인수로 해석합니다. 이로 인해 IIFE가 실행되기 전에 `TypeError`가 발생합니다. 세미콜론을 추가하면 IIFE 앞에서 선언이 종료됩니다:

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

명시적인 세미콜론은 변수 선언과 IIFE를 별개의 문장으로 유지합니다.

세미콜론은 C, C++, Java를 포함한 많은 프로그래밍 언어에서 사용됩니다. 각 언어마다 정확한 규칙은 다르지만, 일반적으로 문장의 끝을 표시하는 데 도움을 줍니다.

컴파일러는 언어와 컴파일러에 따라 소스 코드를 기계어, 바이트코드, 중간 표현 등 다른 형태로 변환합니다. 컴파일이 반드시 독립 실행형 실행 파일을 생성하는 것은 아닙니다.

세미콜론을 일관되게 사용하면 문장 경계가 더 명확해지고 코드를 읽고 유지 관리하기 쉬워집니다.
