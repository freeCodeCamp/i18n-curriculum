## Arrays

- **Arrays estáticos**: têm tamanho fixo determinado na inicialização. Os elementos são armazenados em locais de memória adjacentes, o que torna o acesso muito eficiente. O tamanho não pode ser alterado enquanto o programa está em execução.

- **Arrays dinâmicos**: podem crescer ou diminuir automaticamente enquanto o programa está em execução. Quando o array está cheio, seus elementos são copiados para um novo array maior. O novo tamanho é escolhido para que essas cópias caras aconteçam com menos frequência.

- **Arrays estáticos em Python**: Python não inclui arrays estáticos tradicionais como estruturas de dados embutidas. Outras linguagens, como Java, os suportam.

### Listas em Python (arrays dinâmicos)

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### Complexidades de tempo para arrays dinâmicos

- **Acesso**: O(1)
- **Inserir no final**: O(1) se houver espaço disponível, O(n) quando é necessário redimensionar
- **Inserir no meio**: O(n) porque os elementos depois precisam ser realocados

### Escolhendo entre arrays estáticos e dinâmicos

- **Arrays estáticos**: quando você sabe o número de elementos antecipadamente e precisa acessá-los frequentemente.
- **Arrays dinâmicos**: quando o número de elementos é desconhecido ou muda com o tempo, ou quando você vai inserir e deletar elementos com frequência.

## Pilhas

- **Pilhas**: estrutura de dados Last-In, First-Out (LIFO). Pilhas têm duas extremidades, topo e base. Elementos são adicionados e removidos apenas do topo.

- **Operação push**: adicionar um elemento ao topo da pilha. Ao usar uma lista Python, isso leva tempo O(1) se houver espaço disponível, ou O(n) quando é necessário redimensionar.

- **Operação pop**: remover um elemento do topo da pilha. Complexidade de tempo: O(1). Complexidade de espaço: O(1).

```python
# Using a Python list as a stack, where the end of the list is the top
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operation
top_element = stack.pop()  # Returns 3
```

## Filas

- **Filas**: estrutura de dados First-In, First-Out (FIFO). Filas têm duas extremidades, frente e trás. Elementos são adicionados na trás e removidos da frente.

- **Operação enqueue**: adicionar um elemento na trás da fila. Ao usar uma lista Python, isso leva tempo O(1) se houver espaço disponível, ou O(n) quando é necessário redimensionar.

- **Operação dequeue**: remover um elemento da frente da fila. O próximo elemento na fila se torna a nova frente. Complexidade de tempo: O(1). Complexidade de espaço: O(1).

```python
# Using a Python list as a queue, where the start of the list is the front
queue = []

# Enqueue operations
queue.append(1)
queue.append(2)
queue.append(3)

# Front element
front_element = queue[0]  # 1

# Dequeue operation
front_element = queue.pop(0)  # Returns 1
```

- **Nota**: remover o primeiro elemento de uma lista Python com `.pop(0)` realoca todos os elementos restantes, então leva tempo O(n).

## Listas ligadas

- **Listas ligadas**: estrutura de dados linear onde cada nó armazena dados e uma referência para o próximo nó. Os nós estão conectados como uma corrente. Listas ligadas não têm tamanho fixo e podem crescer ou diminuir atualizando as conexões entre os nós.

- **Usos comuns**: implementar outras estruturas de dados, como pilhas, filas e deques, e algoritmos de grafos como busca em profundidade e busca em largura.

### Listas ligadas simples

- **Estrutura**: cada nó armazena dados e uma referência para o próximo nó.
- **Percurso**: só pode avançar, da cabeça para a cauda.
- **Nó cabeça**: primeiro nó da lista, geralmente o único nó acessível diretamente. O percurso começa aqui.
- **Nó cauda**: último nó da lista. Sua referência para o próximo nó é `None`, que marca o fim da lista.

#### Inserindo nós

- **Inserir no início**: O(1) - conecta o novo nó à antiga cabeça e o torna a nova cabeça
- **Inserir no final**: O(n) - é preciso percorrer até o fim, depois conectar a cauda ao novo nó
- **Inserir no meio**: O(n) - é preciso percorrer até a posição, depois conectar o nó anterior ao novo nó e o novo nó ao próximo
- **Complexidade de espaço**: O(1) - apenas o novo nó é criado

#### Removendo nós

- **Remover do início**: O(1) - torna o próximo nó a nova cabeça
- **Remover do meio**: O(n) - é preciso percorrer até o nó, depois conectar o nó anterior ao próximo, formando uma "ponte" sobre o nó removido
- **Remover do fim**: O(n) - é preciso percorrer até o fim, depois remover a conexão do nó anterior, tornando-o a nova cauda
- **Complexidade de espaço**: O(1) - não é necessária memória adicional

### Listas duplamente ligadas

- **Estrutura**: cada nó armazena dados e duas referências: uma para o próximo nó e outra para o nó anterior.
- **Percurso**: pode se mover em ambas as direções.
- **Referência da cauda**: é comum manter uma referência para o nó cauda na própria lista. Isso permite adicionar nós no final em tempo O(1), sem percorrer a lista, e iniciar um percurso a partir do fim.
- **Inserção e remoção**: funcionam da mesma forma que em listas ligadas simples, mas duas referências por nó precisam ser atualizadas.
- **Memória**: requer mais memória que listas ligadas simples porque cada nó armazena duas referências em vez de uma.

## Quando usar cada estrutura de dados

- **Arrays estáticos**: quando o número de elementos é conhecido antecipadamente e é necessário acesso rápido e frequente
- **Arrays dinâmicos (listas)**: quando você precisa de acesso ordenado e indexado e não sabe o tamanho antecipadamente
- **Pilhas**: quando o último elemento adicionado deve ser o primeiro a ser removido (LIFO)
- **Filas**: quando os elementos devem ser processados na ordem em que foram adicionados (FIFO)
- **Listas ligadas simples**: quando o tamanho muda com frequência e você geralmente insere e remove no início
- **Listas ligadas duplas**: quando você precisa percorrer em ambas as direções ou adicionar elementos no final de forma eficiente, e a memória extra por nó é aceitável
