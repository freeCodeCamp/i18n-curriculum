# --description--

システム言語とキーボード設定が Bash と PostgreSQL ワークショップにどのように影響するかを学びましょう。

多くのプログラミングツールは、コマンドに標準的な英語キーボードの文字を使うことを期待しています。Bash と PostgreSQL のワークショップでは、特にセミコロン（`;`）、引用符、スラッシュ、その他の特殊文字のような記号が重要です。

もしオペレーティングシステムやキーボードレイアウトが英語以外の言語設定を使っている場合、一部の文字が予想と異なる動作をすることがあります。これにより、SQL コマンドやターミナルコマンドの入力時に混乱するエラーが発生することがあります。

これらのワークショップを進める際に最適な体験を得るために、コースを完了する間は一時的に英語（米国）キーボードレイアウトに切り替えることをお勧めします。特に Bash や PostgreSQL のコマンドで、`;` や `\` のような記号を入力したときに予期しない文字や構文エラーが発生する場合に役立ちます。

GitHub Codespaces はローカルのキーボードレイアウトを使用するため、自分のコンピューターでレイアウトを変更すると Codespaces 内の入力にも影響します。

Windows の場合：

1. **設定** > **時刻と言語** > **言語と地域** を開く
2. **English (United States)** がインストールされていなければ追加する
3. キーボードレイアウトの下で **US** キーボードを選択する
4. 必要に応じて US キーボードレイアウトをリストの一番上に移動する

macOS の場合：

1. **システム設定** > **キーボード** > **入力ソース** を開く
2. **English (US)** キーボードレイアウトを追加する
3. US レイアウトがアクティブなキーボードとして選択されていることを確認する

Ubuntu、Debian、Mint などの Linux ディストリビューションの場合：

1. システムのキーボード設定を開く
2. **English (US)** キーボードレイアウトを追加する
3. 可能であればキーボードレイアウトリストの一番上に移動する

一部の Linux システムでは、ターミナルからキーボードレイアウトの確認や変更も可能です。まず、現在のレイアウトを確認してください：

```bash
setxkbmap -query
```

次に US レイアウトに切り替えます：

```bash
setxkbmap us
```

レイアウトを切り替えた後、テキストボックスやターミナルで以下の文字をテストしてください：

```md
; : / \ | ' " $ { } [ ] ( )
```

記号が正しく表示されれば、キーボードレイアウトは適切に設定されている可能性が高いです。

一部の英語以外のレイアウトでは、`'` や `"` のような文字がデッドキーとして扱われ、すぐに入力されずに次のキー入力を待つことがあります。US レイアウトに切り替えた後は、これらの文字はすぐに入力されるはずです。もし文字がすぐに表示されない場合は、レイアウトが完全に切り替わっていないサインです。

AZERTY、QWERTZ、または地域ごとのQWERTYなど、US以外の物理キーボードレイアウトを使っている場合、記号キーが異なる位置に配置されていることがあります。その場合は、USレイアウトに切り替えた後、オペレーティングシステムのオンスクリーンキーボードやキーボードビューアーを使って、`;`、`/`、`\`、`|`、`'`、`"` などのキーの位置を確認してください。

英語（US）キーボードレイアウトを使うことで、ワークショップ中の Bash と PostgreSQL のコマンドが期待通りに動作することを確実にできます。

ワークショップが終わったら、元のキーボードレイアウトに戻すことができます。
