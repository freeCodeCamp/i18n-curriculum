## 동적 프로그래밍 소개

- **정의**: 동적 프로그래밍은 복잡한 문제를 더 단순한 하위 문제로 나누고 결과를 저장해 중복 계산을 피하는 알고리즘 기법입니다.
- **중복 하위 문제**: 큰 문제를 풀 때 동일한 작은 문제가 여러 번 나타납니다. 이 하위 문제를 반복 계산하는 대신 결과를 저장합니다.
- **최적 부분 구조**: 문제의 최적 해는 하위 문제들의 최적 해를 포함합니다. 즉, 작은 부분 문제들의 최적 해를 결합해 최적 해를 만들 수 있습니다.

## 계단 오르기 문제

동적 프로그래밍의 고전적인 예는 양수 `n` 단계의 계단 꼭대기에 도달하는 서로 다른 방법의 수를 세는 것으로, 각 이동은 1단계 또는 2단계씩 오를 수 있습니다:

- **단순 재귀**: 계단 `n`에 도달하는 방법의 수가 `n - 1`단계와 `n - 2`단계에 도달하는 방법의 합이기 때문에, 직접적인 재귀 해결법은 동일한 하위 문제를 반복해서 다시 계산합니다. 예를 들어, `5`단계를 계산할 때 `3`단계를 두 번, `2`단계를 세 번 다시 계산합니다. 이로 인해 지수적인 `O(2^n)` 시간 복잡도와 `O(n)` 호출 스택 공간이 발생합니다.

## 동적 프로그래밍 해법

동적 프로그래밍은 두 가지 주요 방법으로 중복 계산을 제거합니다:

- **메모이제이션 (탑다운 방식)**: 메모이제이션은 함수 호출 결과를 캐시(예: 딕셔너리)에 저장하고 동일한 하위 문제가 다시 나타나면 저장된 결과를 반환합니다:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

처음에 빈 캐시를 사용하면 메모이제이션은 시간 복잡도를 선형 `O(n)`으로 줄이고, 재귀 호출 스택과 함께 캐시된 하위 문제를 저장하는 데 `O(n)` 공간이 필요합니다.

- **테이블화 (바텀업 방식)**: 테이블화는 재귀를 없애고 가장 작은 하위 문제부터 목표까지 반복적으로 해결책을 구축하며 중간 결과를 리스트에 저장합니다:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

테이블화는 `O(n)` 시간에 실행되고 리스트에 `O(n)` 공간을 사용하며, 재귀 호출 스택 증가를 피하는 것이 주요 장점입니다.

- **상수 공간 테이블화 최적화**: 각 새로운 단계가 이전 두 값에만 의존하기 때문에 전체 표를 마지막 두 개의 값을 저장하는 두 변수로 대체할 수 있습니다:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

각 산술 연산을 상수 시간으로, 저장된 각 값을 한 단위 공간으로 간주하면 이 최적화는 `O(n)` 시간은 유지하면서 보조 공간 복잡도를 `O(1)`로 줄입니다.

## 실전 예제: 동전 교환 문제

동전 교환 문제는 목표 금액을 만들기 위해 필요한 최소 동전 개수를 묻는 고전적인 최적화 문제입니다:

- **알고리즘**: 이 알고리즘은 크기가 `amount + 1`인 배열 `dp`를 생성하고, 처음에는 도달할 수 없는 값을 나타내기 위해 `float('inf')`로 초기화합니다. 기본값은 `dp[0] = 0`인데, 이는 `0` 금액을 만들기 위해서는 동전이 하나도 필요하지 않기 때문입니다. 각 금액 `i`에 대해 `1`부터 `amount`까지, 알고리즘은 가능한 모든 동전 종류 중에서 (`coin <= i`) `dp[i - coin] + 1` 값을 최소로 만듭니다. 만약 `dp[amount]`가 여전히 무한대라면, 목표 금액을 만들 수 없으므로 `-1`을 반환합니다.

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

동전 종류가 `[1, 3, 4]`이고 목표가 `6`일 때, 알고리즘은 `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`를 계산하여 두 개의 동전(`3 + 3`)으로 최적 조합을 만듭니다.

- **복잡도**: 알고리즘은 목표까지 모든 하위 금액에 대해 각 동전 종류를 검사하므로 시간 복잡도는 `O(amount * number_of_coins)`이고, DP 배열을 위한 보조 공간 복잡도는 `O(amount)`입니다.

## 동적 프로그래밍을 활용한 실제 애플리케이션

- **라우트 최적화**: GPS 시스템은 동적 프로그래밍 알고리즘을 사용해 위치 간 최단 경로를 찾습니다.
- **텍스트 처리**: 맞춤법 검사기와 자동 완성 기능은 단어 간 편집 거리를 계산할 때 동적 프로그래밍에 의존하는 경우가 많습니다.
- **금융 모델링**: 투자 전략과 포트폴리오 최적화에 동적 프로그래밍 기법이 자주 활용됩니다.
- **자원 할당**: 배낭 문제와 그 변형은 일정 관리, 예산 편성, 자원 관리에 나타납니다.
