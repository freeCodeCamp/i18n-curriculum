## オブジェクト指向プログラミングとは何ですか？

- **オブジェクト指向プログラミング**: 開発者がコード内のすべてを現実世界のオブジェクトのように扱うプログラミングスタイルです。一般的にOOPと呼ばれます。コードを効果的に整理・管理するための4つの重要な原則は、**カプセル化**、**継承**、**ポリモーフィズム**、および**抽象化**です。
- **クラス**: オブジェクトを作成するための設計図です。クラスから作成されたすべてのオブジェクトは、データを定義する属性とオブジェクトの振る舞いを決定するメソッドを持っています。

## カプセル化とは何ですか？

- **カプセル化**: オブジェクトの属性とメソッドを一つの単位にまとめることです。オブジェクトの内部状態を、ドアのように振る舞う公開されたメソッドや属性の背後に隠せます。そのドアの向こうには、データの変更方法やアクセス権を制御するプライベートな属性やメソッドがあります。
- **カプセル化の例**: 財布の残高を管理したい場合、入金や出金は許可しますが、残高自体を誰かに勝手に変更されるのは避けたいでしょう。

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **属性にシングルアンダースコアとダブルアンダースコアを付ける違い**: 属性やメソッドにシングルアンダースコアを付けるのは内部利用を意図していることを示す慣例です。これはあくまで慣例であり、Pythonはクラス外からのアクセスを制限しません。ダブルアンダースコアを付けると名前修飾（ネームマンリング）が発生し、`__balance`は`_Wallet__balance`に名前が変わります。これによりサブクラスでの偶発的な名前衝突を避けられますが、外部からのアクセスが不可能になるわけではありません：

```py
print(account._Wallet__balance) # 500
```

## ゲッターとセッターとは？

- **ゲッターとセッター**: クラスの属性へのアクセスや変更を制御するメソッドです。ゲッターで値を取得し、セッターで値を設定します。
- **プロパティ**: ゲッターとセッターをつなぎ、データへのアクセスを可能にします。値の取得、設定、削除時に裏で追加の処理を実行します。
- **なぜメソッドではなくプロパティを使うのか**: プロパティは読みやすさとコードの簡潔さのためにメソッドの代わりに使われます。丸括弧なしで通常の属性のようにドット記法で値にアクセスできます。
- **デコレーター**: 元のコードを変更せずに他の関数やクラスを修飾またはラップする関数です。関数やクラス定義の直前に`@decorator_name`を置いて適用します。例えば、メソッドの上に`@property`デコレーターを置くと、そのメソッドはプロパティになり、内部的にメソッドを呼び出しつつ属性のようにアクセスできます。
- **ゲッターの作成**: ゲッターを作るには`@property`デコレーターを使います。以下は円の半径を取得するゲッターの例です：

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **セッターの作成**: 半径を設定するセッターを作るには、同じ名前の別のメソッドを定義し、その上に`@<property_name>.setter`を付けます。

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Pythonのゲッターとセッターの扱い**: ゲッターとセッターを定義すると、通常の属性アクセス構文を使うたびにPythonが自動的に呼び出します。

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

セッター内でプロパティ名に代入すると`RecursionError`が発生するため避けてください。

- **デリーター**: セッターとゲッターで値を設定・取得した後、`deleter`で削除方法を制御できます。デリーターはプロパティに対して`del`文を使ったときにカスタム処理を実行します。デリーターを作るには`@<property_name>.deleter`デコレータを使います。

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## 継承とは？コードの再利用を促進する仕組み

- **継承**: 子クラスが親クラスの属性やメソッドを利用する仕組みです。継承はコードの再利用を促し、明確な階層構造を提供し、すべてを書き直さずに振る舞いをカスタマイズできます。継承を実装するには、子クラスが親クラスの名前を受け取ります。

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **単一継承と多重継承**: 子クラスが1つの親からプロパティやメソッドを継承する場合は**単一継承**と呼びます。複数の親から継承する場合は**多重継承**です。以下は多重継承の構文例です。

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **`super()`関数**: クラスがメソッドを独自に実装または拡張している場合に、親クラスのメソッドを重複せずに**呼び出す**ための関数です。

## ポリモーフィズムとは？コードの再利用を促進する仕組み

- **ポリモーフィズム**: 異なるクラスが同じメソッド名を使い、呼び出されたときにそれぞれ異なる実装を行うOOPの原則です。構文は以下の通りです。

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **継承に基づくポリモーフィズム**: 親クラスがメソッドを用意し、子クラスがそれを自分用に変えて使います。

## ネームマンリングとは何で、どのように機能するのか？

- **ネームマンリング**: Pythonがダブルアンダースコアで始まる属性名を内部的にクラス名を接頭辞として付けて名前を変更するプロセスです。例えば`__attribute`は`_ClassName__attribute`になります。
- **ネームマンリングの目的**: ネームマンリングの主な目的は、継承を使う際に属性やメソッドの偶発的な上書きを防ぐことです。以下のコード例でより理解しやすくなります：

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## 抽象化とは？複雑なシステムを整理する助け

- **抽象化**: オブジェクトやシステムの複雑な実装の詳細を隠し、必要な機能だけを示すプログラミングの概念です。Pythonや他のプログラミング言語では、抽象化により複雑なシステムが簡素化され、再利用性が高まります。
- **抽象化の例**: 日常生活の良い例は、車のエンジンやブレーキの仕組みを知らなくても、ハンドル、ペダル、シフターだけで操作できることです。
- **Pythonでの抽象化の実装方法**: 普通の関数やクラスで実装の詳細をシンプルなインターフェースの背後に隠すことで抽象化を作れます。より正式なインターフェースには、Pythonの`abc`モジュールが`ABC`ヘルパークラスと`@abstractmethod`デコレーターを提供します。抽象基底クラスは具体的なサブクラスが提供すべき共通のメソッドやプロパティを定義します。
- **抽象メソッドの定義方法**: 抽象メソッドは`@abstractmethod`で定義します。クラスはすべての抽象メソッドを具体的に実装または継承している場合にのみインスタンス化できます。抽象メソッドを未実装のままにしたサブクラスは抽象クラスのままです。抽象メソッドはデフォルト実装を持つこともでき、サブクラスは`super()`で呼び出せます。`ABC`を継承しただけではインスタンス化はブロックされません：`ABC()`や抽象メソッドを持たないサブクラスはインスタンス化可能です。抽象化の基本構文は以下の通りです：

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## オブジェクトの表現

- **`__repr__`メソッド**: オブジェクトの文字列表現を返す特別なメソッドです。理想的には、その文字列はオブジェクトを作成するためのコードのように見えます。例えば、`Employee('Charlie', 'developer')`は`Employee('Charlie', 'developer')`として表現されるべきです。
- **`repr()`関数**: `repr()`をオブジェクトに呼び出すと、Pythonはそのオブジェクトの`__repr__`メソッドを内部的に呼び出します。文字列の場合、`repr()`は引用符を付け、必要な文字をエスケープします：

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **`!r`変換**: f文字列内で式の後に`!r`を付けると、その式に`repr()`が適用されます。`__repr__`内で`!r`を使うと、値に引用符やバックスラッシュが含まれていても表現が有効なままになるため、手動で値を引用符で囲むより安全です：

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## ドキュメンテーション文字列と型チェック

- **ドキュメンテーション文字列（ドックストリング）**: クラスや関数の最初の文として置かれる文字列で、それを文書化します。通常は三重の二重引用符で囲まれます：

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()`と`type()`の違い**: `isinstance(obj, ClassName)`は`obj`が`ClassName`またはそのサブクラスのインスタンスであれば`True`を返します。これは継承チェーン全体を考慮するためです。特定のクラスかどうかだけを調べるには`type(obj)`を比較してください：

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## 追加情報を持つカスタム例外

- **例外にコンテキストを保存する**: カスタム例外はメッセージとともに追加データを受け取れます。`super().__init__(message)`を呼ぶと組み込みの`Exception`クラスがメッセージを保存・表示し、その後追加データを属性として保存できます。例外をキャッチしたときにその属性を読み取ってデバッグに役立てられます：

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## 型ヒント

- **型ヒント**: 変数、パラメータ、または戻り値がどのデータ型であるべきかを他の開発者に示すための任意の注釈です。Pythonは実行時にこれを強制しません。
- **パラメータと戻り値の型ヒント**: パラメータ名の後にコロンを付けて型ヒントを追加し、パラメータリストの後に `-> return_type` を付けて戻り値の型ヒントを追加します。`__init__` は戻り値が必ず `None` でなければならない初期化メソッドなので、その戻り値の型ヒントは `None` です。

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **カスタムクラスとリストの型指定**: 自分のクラスを型ヒントとして使えます。また、`list[ClassName]`はそのクラスのオブジェクトを含むリストを指定します：

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
