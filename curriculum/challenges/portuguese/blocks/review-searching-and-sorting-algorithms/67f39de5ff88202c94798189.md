## Algoritmos de Busca

- **Propósito**: Algoritmos de busca permitem que você busque um alvo dentro de uma lista de itens.
- **Tipos de algoritmos de busca**: Dois algoritmos de busca comuns são a busca linear e a busca binária. Entender as diferenças entre eles ajuda a determinar quando usar cada um.

### Busca Linear

- **Algoritmo de busca linear**: Itera por uma lista de itens, verificando cada item desde o início até encontrar o alvo.
- **Busca bem-sucedida**: Se o item alvo for encontrado, retorna o índice onde ele está localizado na lista.
- **Busca mal-sucedida**: As implementações da palestra retornam `-1` para indicar que o alvo não foi encontrado. Em Python, `-1` também indexa o último elemento de uma lista não vazia, então verifique se o resultado é `-1` antes de usá-lo como índice. Caso contrário, uma busca mal-sucedida poderia recuperar o último elemento por engano.
- **Eficiência**: Como a busca linear verifica cada item sequencialmente, pode ser ineficiente para listas grandes.
- **Complexidade de tempo**: `O(n)` porque o tempo necessário para buscar cresce linearmente com o tamanho da lista.
- **Complexidade de espaço**: `O(1)` porque usa uma quantidade constante de espaço adicional independentemente do tamanho da entrada.

### Busca Binária

- **Algoritmo de busca binária**: Um algoritmo de busca eficiente que divide repetidamente uma lista ordenada em metades para encontrar um valor alvo.
- **Pré-requisito de entrada ordenada**: A busca binária exige que a lista de entrada esteja ordenada em ordem crescente.
- **Inicialização do intervalo de busca**: Inicialize `low = 0` como o índice do primeiro elemento e `high = len(arr) - 1` como o índice do último elemento. Essas variáveis definem o intervalo inclusivo que está sendo buscado.
- **Condição para continuar a busca**: Continue buscando enquanto `low <= high`. Se `low > high`, o intervalo de busca está vazio, o que significa que o alvo não foi encontrado.
- **Cálculo do ponto médio**: Calcule o índice do meio usando divisão inteira: `mid = (low + high) // 2`.
- **Comparação com o alvo**: Compare o valor do alvo com `arr[mid]`. Se forem iguais, o alvo foi encontrado no índice `mid`.
- **Atualização do limite inferior**: Se `arr[mid] < target`, o alvo deve estar na metade direita, se existir na lista. Atualize `low = mid + 1` para excluir o ponto médio e todos os elementos antes dele.
- **Atualização do limite superior**: Se `arr[mid] > target`, o alvo deve estar na metade esquerda, se existir na lista. Atualize `high = mid - 1` para excluir o ponto médio e todos os elementos depois dele.
- **Busca bem-sucedida na palestra**: A implementação da palestra retorna o índice do alvo quando ele é encontrado.
- **Busca malsucedida na palestra**: A implementação da palestra retorna `-1` quando o intervalo de busca fica vazio.
- **Rastreamento do caminho na oficina**: A implementação da oficina inicializa uma lista vazia `path_to_target` e adiciona o valor de cada ponto médio visitado durante a busca.
- **Busca bem-sucedida na oficina**: Quando o alvo é encontrado, a oficina retorna uma tupla contendo `path_to_target` e uma mensagem indicando o índice onde o alvo foi encontrado.
- **Busca malsucedida na oficina**: Quando o intervalo de busca fica vazio, a oficina retorna uma lista vazia e uma mensagem `"Value not found"`.
- **Complexidade de tempo**: `O(log n)` porque o intervalo de busca é aproximadamente reduzido pela metade a cada comparação.
- **Complexidade de espaço**: A implementação da palestra usa espaço auxiliar `O(1)` para variáveis como `low`, `high` e `mid`. A implementação da oficina usa espaço auxiliar `O(log n)` porque `path_to_target` armazena os valores dos pontos médios visitados durante a busca.

### Como a Busca Linear Difere da Busca Binária

- **Pré-requisitos**: A busca linear não exige uma lista ordenada, enquanto a busca binária exige que os dados de entrada estejam ordenados em ordem crescente.
- **Escalabilidade**: A busca binária é mais adequada para listas grandes de itens em comparação com a busca linear.
- **Comparação de complexidade de tempo**: A busca linear tem complexidade de tempo `O(n)`, enquanto a busca binária tem complexidade de tempo `O(log n)`.

## Algoritmos de Ordenação e Dividir-e-Conquistar

- **Dividir para conquistar**: Uma técnica usada para dividir um problema em subproblemas menores para que sejam mais fáceis de resolver. A recursão é frequentemente usada para implementar essa abordagem, que é comum em algoritmos eficientes de ordenação como o merge sort.

### Ordenação por Merge

- **Algoritmo merge sort**: Um algoritmo de ordenação que segue a abordagem dividir para conquistar.
- **Caso base**: Listas com zero ou um elemento já estão ordenadas, então a recursão para quando `len(array) <= 1`.
- **Dividindo a lista**: Divida a lista em duas metades fatiadas e ordene recursivamente cada metade.
- **Mesclando as sublistas**: Compare os próximos elementos não mesclados das duas metades ordenadas, copie o elemento menor para a próxima posição de saída e avance seu índice. Quando uma metade acabar, copie todos os elementos restantes da outra metade.
- **Implementação da oficina**: A oficina cria metades fatiadas e escreve os valores mesclados de volta na lista original, avançando `sorted_index` após cada escrita. Modificar a lista original não torna esse um algoritmo de ordenação in-place porque as metades fatiadas exigem armazenamento adicional.
- **Complexidade de tempo**: `O(n log n)` porque a lista é repetidamente dividida em metades (`log n` níveis), e mesclar os elementos em cada nível leva tempo `O(n)`.
- **Complexidade de espaço**: `O(n)` porque o merge sort requer memória adicional para mesclar as sublistas e não é um algoritmo de ordenação in-place.
