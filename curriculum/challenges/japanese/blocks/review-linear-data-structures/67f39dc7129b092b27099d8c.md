## 配列

- **静的配列**: 初期化時に決まったサイズを持ちます。要素は隣接するメモリ領域に格納されるため、アクセスが非常に効率的です。プログラム実行中にサイズを変更することはできません。

- **動的配列**: プログラム実行中に自動的にサイズが増減します。配列が満杯になると、その要素は新しいより大きな配列にコピーされます。新しいサイズは、この高コストなコピーが頻繁に起こらないように選ばれます。

- **Pythonの静的配列**: Pythonには伝統的な静的配列は組み込みのデータ構造として含まれていません。Javaのような他の言語ではサポートされています。

### Pythonのリスト（動的配列）

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### 動的配列の時間計算量

- **アクセス**: O(1)
- **末尾への挿入**: 空きがあればO(1)、サイズ変更が必要な場合はO(n)
- **途中への挿入**: 挿入後の要素を移動させる必要があるためO(n)

### 静的配列と動的配列の選び方

- **静的配列**: 要素数が事前に分かっていて頻繁にアクセスする場合。
- **動的配列**: 要素数が不明または変動し、頻繁に挿入や削除を行う場合。

## スタック

- **スタック**: 後入れ先出し（LIFO）のデータ構造です。スタックには上端と下端があり、要素は上端からのみ追加・削除されます。

- **プッシュ操作**: スタックの上端に要素を追加します。Pythonのリストを使う場合、空きがあればO(1)、サイズ変更が必要な場合はO(n)かかります。

- **ポップ操作**: スタックの上端から要素を削除します。時間計算量はO(1)、空間計算量もO(1)です。

```python
# Using a Python list as a stack, where the end of the list is the top
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operation
top_element = stack.pop()  # Returns 3
```

## キュー

- **キュー**: 先入れ先出し（FIFO）のデータ構造です。キューには前端と後端があり、要素は後端に追加され、前端から削除されます。

- **エンキュー操作**: キューの後端に要素を追加します。Pythonのリストを使う場合、空きがあればO(1)、サイズ変更が必要な場合はO(n)かかります。

- **デキュー操作**: キューの前端から要素を削除します。次の要素が新しい前端になります。時間計算量はO(1)、空間計算量もO(1)です。

```python
# Using a Python list as a queue, where the start of the list is the front
queue = []

# Enqueue operations
queue.append(1)
queue.append(2)
queue.append(3)

# Front element
front_element = queue[0]  # 1

# Dequeue operation
front_element = queue.pop(0)  # Returns 1
```

- **注意**: Pythonのリストで`.pop(0)`を使って最初の要素を削除すると、残りの要素すべてが移動されるためO(n)かかります。

## 連結リスト

- **連結リスト**: 各ノードがデータと次のノードへの参照を持つ線形データ構造です。ノードは鎖のように繋がっています。連結リストは固定サイズがなく、ノード間の接続を更新することで増減できます。

- **主な用途**: スタック、キュー、デックなど他のデータ構造の実装や、深さ優先探索や幅優先探索のようなグラフアルゴリズムに使われます。

### 単方向連結リスト

- **構造**: 各ノードはデータと次のノードへの1つの参照を持ちます。
- **走査**: 頭から尾へ一方向にしか進めません。
- **頭ノード**: リストの最初のノードで、通常は唯一直接アクセスできるノードです。走査はここから始まります。
- **尾ノード**: リストの最後のノードです。次のノードへの参照が`None`で、リストの終わりを示します。

#### ノードの挿入

- **先頭への挿入**: O(1) - 新しいノードを古い頭に繋ぎ、新しい頭にします
- **末尾への挿入**: O(n) - 末尾まで走査し、尾を新しいノードに繋ぎます
- **途中への挿入**: O(n) - 挿入位置まで走査し、前のノードを新しいノードに、新しいノードを次のノードに繋ぎます
- **空間計算量**: O(1) - 新しいノードだけが作成されます

#### ノードの削除

- **先頭からの削除**: O(1) - 次のノードを新しい頭にします
- **途中からの削除**: O(n) - 削除するノードまで走査し、前のノードを次のノードに繋ぎ、削除ノードを飛び越えます
- **末尾からの削除**: O(n) - 末尾まで走査し、前のノードの接続を外して新しい尾にします
- **空間計算量**: O(1) - 追加のメモリは不要です

### 双方向連結リスト

- **構造**: 各ノードはデータと2つの参照を持ちます：次のノードと前のノードへの参照です。
- **走査**: 双方向に移動できます。
- **尾の参照**: リスト自体に尾ノードへの参照を保持することが一般的です。これにより、リストを走査せずに末尾にO(1)でノードを追加でき、末尾からの走査も可能です。
- **挿入と削除**: 単方向連結リストと同様ですが、各ノードの2つの参照を更新する必要があります。
- **メモリ**: 各ノードが2つの参照を持つため、単方向連結リストより多くのメモリを必要とします。

## それぞれのデータ構造の使いどころ

- **静的配列**: 要素数が事前に分かっていて、高速で頻繁なアクセスが必要な場合
- **動的配列（リスト）**: 順序付きでインデックスアクセスが必要で、サイズが事前に分からない場合
- **スタック**: 最後に追加した要素を最初に取り出したい場合（LIFO）
- **キュー**: 追加された順に要素を処理したい場合（FIFO）
- **単方向連結リスト**: サイズが頻繁に変わり、主に先頭での挿入と削除を行う場合
- **双方向連結リスト**: 双方向に走査したり、末尾に効率的に要素を追加したい場合で、ノードごとの追加メモリが許容できる場合
