## Algoritmos e notação big O

- **Algoritmos**: um conjunto de instruções claras e sem ambiguidades para resolver um problema ou realizar uma tarefa. Algoritmos devem terminar em um número finito de passos e cada passo deve ser preciso e sem ambiguidades.

- **Notação Big O**: Descreve um limite superior assintótico no uso de recursos de um algoritmo conforme o tamanho da entrada aumenta. Big O mede essa tendência geral de escalonamento separadamente de você estar analisando o melhor, a média ou o pior caso, ignorando fatores constantes e termos menores.

### Complexidades de tempo comuns

- **O(1) - tempo constante**: o algoritmo leva o mesmo tempo independentemente do tamanho da entrada.

```python
def check_even_or_odd(number):
    if number % 2 == 0:
        return 'Even'
    else:
        return 'Odd'
```

- **O(log n) - Tempo logarítmico**: Um limite superior no tempo de execução que cresce no máximo de forma logarítmica com o tamanho da entrada. Quando o limite é exato, o algoritmo roda em tempo logarítmico. Isso ocorre comumente quando o tamanho do problema é repetidamente reduzido por uma fração constante, como na busca binária.

- **O(n) - Tempo linear**: Um limite superior no tempo de execução que cresce no máximo linearmente com o tamanho da entrada. Quando o limite é exato, o tempo de execução cresce proporcionalmente ao tamanho da entrada.

```python
for grade in grades:
    print(grade)
```

- **O(n log n) - Tempo log-linear**: Comum em ordenações eficientes do tipo dividir para conquistar. Merge Sort tem complexidade de pior caso O(n log n). Quick Sort tem complexidade média O(n log n), mas seu pior caso é O(n²).

- **O(n²) - Tempo quadrático**: Um limite superior no tempo de execução que cresce no máximo quadraticamente com o tamanho da entrada. Quando o limite é exato, o tempo de execução cresce proporcionalmente ao quadrado do tamanho da entrada. Isso ocorre em loops aninhados onde cada loop executa n iterações.

```python
for i in range(n):
    for j in range(n):
        print("Hello, World!")
```

- **O(2ⁿ) - Tempo exponencial**: Um limite superior exponencial no tempo de execução. Quando o limite é exato, a taxa de crescimento é proporcional a 2ⁿ, que dobra sempre que n aumenta em um.

- **O(n!) - Tempo fatorial**: Um limite superior fatorial no tempo de execução. Quando o limite é exato, a taxa de crescimento é proporcional a n!, o número de permutações de n itens distintos.

### Complexidade de espaço

- **O(1) - Espaço constante**: O uso de memória é limitado por uma constante independente do tamanho da entrada.

- **O(n) - Espaço linear**: O uso de memória cresce no máximo linearmente com o tamanho da entrada. Quando o limite é exato, o uso de memória cresce proporcionalmente ao tamanho da entrada.

- **O(n²) - Espaço quadrático**: O uso de memória cresce no máximo quadraticamente com o tamanho da entrada. Quando o limite é exato, o uso de memória cresce proporcionalmente ao quadrado do tamanho da entrada.

- **O(2ⁿ) - Espaço exponencial**: Um limite superior exponencial no uso de memória. Quando o limite é exato, o uso de memória cresce proporcionalmente a 2ⁿ.

- **O(n!) - Espaço fatorial**: Um limite superior fatorial no uso de memória. Quando o limite é exato, o uso de memória cresce proporcionalmente a n!.

## Técnicas de resolução de problemas

- **Entendendo o problema**: Leia a declaração do problema várias vezes. Identifique a entrada, a saída esperada e como transformar a entrada na saída.

- **Seleção de algoritmo e estrutura de dados**: Compare algoritmos alternativos pelos seus requisitos de tempo e espaço, e escolha estruturas de dados adequadas ao problema.

- **Pseudocódigo**: Descrição de alto nível da lógica do algoritmo que é independente de linguagem, usando linguagem comum misturada com construções de programação como `IF`, `ELSE`, `FOR` e `WHILE`.

```md
GET original_string
SET reversed_string = ""

FOR EACH character IN original_string:
    ADD character TO THE BEGINNING OF reversed_string

DISPLAY reversed_string
```

- **Implementação**: Escreva código limpo, legível e modular baseado no seu plano de pseudocódigo. Use ferramentas embutidas apropriadas para tarefas comuns.

- **Casos extremos**: Entradas específicas e válidas que ocorrem nos limites do que um algoritmo deve tratar. Sempre considere e teste casos extremos.

- **Testes e refinamento**: Teste seu código com os exemplos fornecidos e casos de borda. Depure erros, verifique os resultados e refine a solução para melhorar clareza ou eficiência.

## Arrays

- **Arrays estáticos**: Têm tamanho fixo definido na criação, com elementos armazenados em memória contígua. Esse layout adjacente permite acesso indexado rápido em tempo constante (O(1)). Escolha um array estático quando o número máximo de itens for estritamente conhecido antecipadamente.

- **Arrays dinâmicos**: Podem crescer ou diminuir automaticamente durante a execução do programa. Quando ficam sem espaço, lidam com redimensionamento internamente alocando um bloco maior de memória e copiando os elementos existentes.

**Nota:** Python não possui um array estático embutido tradicional. As listas Python são arrays dinâmicos.

### Listas em Python (arrays dinâmicos)

```python
numbers = [3, 4, 5, 6]

# Access elements
numbers[0]  # 3

# Update elements
numbers[2] = 16

# Add elements
numbers.append(7)
numbers.insert(3, 15)  # Insert at specific index

# Remove elements
numbers.pop(2)  # Remove at specific index
numbers.pop()   # Remove last element
```

### Complexidades de tempo para arrays dinâmicos

- **Acesso**: O(1)

- **Inserir no fim**: O(1) em média, O(n) quando é necessário redimensionar

- **Inserir no meio**: O(n)

- **Excluir**: O(n) para meio, O(1) para fim

## Pilhas

- **Pilhas**: estrutura de dados Last-In, First-Out (LIFO). Elementos são adicionados e removidos apenas do topo.

- **Operação push**: Adicionar um elemento ao topo da pilha. Para a implementação com lista Python abaixo, um push comum leva tempo O(1) e espaço adicional O(1). Um push que requer redimensionamento pode levar tempo O(n) e espaço adicional O(n).

- **Operação pop**: Remover um elemento do topo da pilha. A complexidade de tempo é tipicamente O(1), e o espaço adicional requerido geralmente é O(1).

```python
# Using Python list as stack
stack = []

# Push operations
stack.append(1)
stack.append(2)
stack.append(3)

# Pop operations
top_element = stack.pop()  # Returns 3
```

## Filas

- **Filas**: Estrutura de dados FIFO (primeiro a entrar, primeiro a sair) onde elementos são adicionados na parte de trás e removidos da frente.

- **Operação enqueue**: Adicionar um elemento na parte de trás da fila. Complexidade de tempo: O(1), complexidade de espaço: O(1).

- **Operação dequeue**: Remover um elemento da frente da fila. Complexidade de tempo: O(1), complexidade de espaço: O(1).

## Listas ligadas

- **Listas ligadas**: Estrutura de dados linear onde cada nó contém dados e uma referência para o próximo nó. Os nós estão conectados como uma corrente.

### Listas ligadas simples

- **Estrutura**: Cada nó tem dados e uma referência para o próximo nó.

- **Percurso**: Só pode avançar do início ao fim.

- **Nó cabeça**: Primeiro nó da lista, geralmente o único nó acessível diretamente.

- **Nó cauda**: Último nó da lista, aponta para `None`.

### Implementação de lista ligada

- **Classe Node**: Uma classe `Node` aninhada representa nós individuais. Cada nó contém dados e uma referência para o próximo nó.

- **Inicialização**: A referência `head` começa como `None` porque a lista não tem nós. A referência `next` de cada novo nó começa como `None` porque ainda não tem sucessor.

- **Rastreamento de comprimento**: Uma variável de comprimento mantém o número de nós na lista.

- **`is_empty()`**: Verifica se a lista está vazia checando se `head` é `None`.

- **Adicionar no fim**: Percorra a lista a partir da cabeça até o último nó, então atualize sua referência `next` para apontar para o novo nó. Se a lista estiver vazia, o novo nó se torna a cabeça.

```python
class LinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None

    def __init__(self):
        self.head = None
        self.length = 0

    def is_empty(self):
        return self.head is None

    def append(self, data):
        new_node = self.Node(data)

        if self.is_empty():
            self.head = new_node
        else:
            current = self.head

            while current.next:
                current = current.next

            current.next = new_node

        self.length += 1
```

### Operações e complexidades de tempo

- **Inserir no início**: O(1)

- **Inserir no fim**: O(n) - é necessário percorrer até o fim

- **Inserir no meio**: O(n) - é necessário percorrer até a posição

- **Excluir do início**: O(1)

- **Excluir do fim**: O(n) - é necessário percorrer para encontrar o nó anterior

- **Excluir do meio**: O(n) - é necessário percorrer para encontrar o nó

### Inserção e exclusão

- **Inserção no início**: Crie um novo nó, defina sua referência `next` para a cabeça atual e atualize a cabeça para apontar para o novo nó.

- **Inserção no fim**: Percorra até o último nó e atualize sua referência `next` para apontar para o novo nó.

- **Inserção no meio**: Percorra até o nó antes da posição desejada. Atualize a referência `next` do novo nó para apontar para o próximo nó, depois atualize a referência `next` do nó anterior para apontar para o novo nó.

- **Exclusão do início**: Atualize a cabeça para apontar para o segundo nó.

- **Exclusão do fim**: Percorra até o penúltimo nó e atualize sua referência `next` para `None`.

- **Exclusão do meio**: Encontre o nó antes do nó alvo e atualize sua referência `next` para pular o nó alvo.

- **Remover por valor**: Acompanhe o nó anterior enquanto percorre. Se o alvo for a cabeça, atualize a cabeça diretamente. Se o valor não for encontrado, retorne sem modificar a lista ou seu comprimento. Decremente o comprimento somente após uma remoção bem-sucedida.

### Complexidades de espaço auxiliar

- **Inserção no início**: Espaço auxiliar O(1), excluindo o armazenamento necessário para o novo nó.

- **Inserção no fim**: Espaço auxiliar O(1), excluindo o armazenamento necessário para o novo nó.

- **Inserção no meio**: Espaço auxiliar O(1), excluindo o armazenamento necessário para o novo nó.

- **Exclusão do início**: Espaço auxiliar O(1).

- **Exclusão do fim**: Espaço auxiliar O(1).

- **Exclusão do meio**: Espaço auxiliar O(1).

### Listas duplamente ligadas

- **Estrutura**: Cada nó tem dados e duas referências: próximo nó e nó anterior.

- **Percurso**: Pode mover-se em ambas as direções.

- **Memória**: Requer mais memória que listas ligadas simples devido à referência extra.

- **Referência à cauda**: Manter uma referência ao último nó permite percurso reverso usando referências anteriores.

## Mapas hash e conjuntos

### Maps e mapas hash

- **Tipo abstrato de dados (ADT) vs. implementação**: Um ADT define a *interface* — especificando quais operações uma estrutura de dados suporta e como ela se comporta logicamente. Uma implementação concreta define o mecanismo backend, mostrando *como* essas operações são realmente construídas e executadas na memória.

- **Map (ADT)**: Um tipo abstrato de dados que define uma coleção de chaves únicas mapeadas para valores. Define as regras do que um map pode fazer sem ditar seu armazenamento interno.

- **Hash Map**: Uma implementação concreta do Map ADT que usa uma função hash para calcular locais de armazenamento em um array subjacente para buscas rápidas.

### Dicionários Python (mapas hash)

```python
# Creating dictionaries
my_dictionary = {
    "A": 1,
    "B": 2,
    "C": 3
}

# Alternative creation
my_dictionary = dict(A=1, B=2, C=3)

# Access and modify
value = my_dictionary["A"]  # 1
my_dictionary["A"] = 4      # Update value
del my_dictionary["A"]      # Remove key-value pair

# Check membership
"C" in my_dictionary

# Get keys, values, items
my_dictionary.keys()
my_dictionary.values()
my_dictionary.items()
```

### Complexidades de tempo para mapas hash

- **Caso médio**: O(1) para inserir, obter, excluir

- **Pior caso**: O(n) quando ocorrem muitas colisões de hash

### Complexidades de espaço auxiliar para hash maps

- **Inserção**: Espaço adicional O(1) para inserção comum. Redimensionamento pode requerer espaço adicional O(n).

- **Busca**: Espaço auxiliar O(1).

- **Exclusão**: Espaço auxiliar O(1).

### Conjuntos

- **Conjuntos**: Coleções não ordenadas de elementos únicos. Não permitem duplicatas, nem mantêm ordem específica.

- **Elementos de sets**: Sets podem conter números, strings e tuplas contendo apenas números e strings. Listas, dicionários e outros sets não podem ser elementos de sets. Uma tupla contendo uma lista não pode ser elemento de set, mesmo que a tupla em si seja imutável.

```python
# Creating sets
numbers = {1, 2, 3, 4}
empty_set = set()  # Must use set(), not {}

# Add and remove elements
numbers.add(5)
numbers.remove(4)      # Raises KeyError if not found
numbers.discard(4)     # No error if not found

# Remove and return an arbitrary element
numbers.pop()

# Remove all elements
numbers.clear()

# Get the number of elements
len(numbers)
```

### Operações com conjuntos

```python
set_a = {1, 2, 3, 4}
set_b = {2, 3, 4, 5, 6}

# Union, intersection, difference, symmetric difference
set_a.union(set_b)                  # or set_a | set_b
set_a.intersection(set_b)           # or set_a & set_b
set_a.difference(set_b)             # or set_a - set_b
set_a.symmetric_difference(set_b)   # or set_a ^ set_b

# Subset and superset checks
set_a.issubset(set_b)
set_a.issuperset(set_b)
set_a.isdisjoint(set_b)

# Membership testing
5 in numbers
```

### Complexidades de tempo para conjuntos

- **Caso médio**: O(1) para adicionar, remover, testar associação

- **Pior caso**: O(n) devido a colisões de hash

- **Consulta de comprimento**: O(1) usando `len()`.

### Complexidades de espaço auxiliar para sets

- **Inserção**: Espaço adicional O(1) para inserção comum. Redimensionamento pode requerer espaço adicional O(n).

- **Busca**: Espaço auxiliar O(1).

- **Exclusão**: Espaço auxiliar O(1).

- **Consulta de comprimento**: Espaço auxiliar O(1).

## Colisões de Hash

- **Colisão de hash**: Chaves diferentes podem produzir o mesmo valor de hash. Em uma tabela hash, colisões também ocorrem quando valores de hash diferentes mapeiam para o mesmo índice do array. Entradas que compartilham um índice devem ser tratadas por uma estratégia de resolução de colisões.

- **Estratégias de resolução de colisões**:

  - **Encadeamento**: Cada índice do array aponta para uma lista ligada que armazena todas as entradas que mapeiam para o mesmo índice do bucket.

  - **Endereçamento aberto**: Busca pelo próximo índice disponível no array usando uma sequência predefinida quando ocorre uma colisão.

## Quando usar cada estrutura de dados

- **Listas**: Quando você precisa de acesso ordenado e indexado e não sabe o tamanho antecipadamente.

- **Pilhas**: Para operações LIFO (funcionalidade de desfazer, avaliação de expressões, backtracking).

- **Filas**: Para operações FIFO (agendamento de tarefas, busca em largura).

- **Listas ligadas**: Quando há inserção/exclusão frequente no início, tamanho desconhecido, sem necessidade de acesso aleatório.

- **Hash maps**: Para buscas rápidas de chave-valor, contagem de ocorrências, cache.

- **Sets**: Para verificação de unicidade, operações matemáticas de conjuntos, remoção de duplicatas.
