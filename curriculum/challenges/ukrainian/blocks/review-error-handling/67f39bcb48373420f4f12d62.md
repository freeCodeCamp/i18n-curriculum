## Загальні помилки в Python

- **`SyntaxError`**: Це помилка, яку Python видає, коли ваш код не відповідає його правилам синтаксису. Наприклад, код `print("Hello there"` призведе до синтаксичної помилки з повідомленням `SyntaxError: '(' was never closed`, оскільки у коді бракує закриваючої дужки.
- **`NameError`**: Python видає `NameError`, коли ви намагаєтеся отримати доступ до змінної або функції, яку не було визначено. Наприклад, якщо у вас є рядок `print(username)` у коді без попереднього визначення змінної `username`, ви отримаєте помилку з повідомленням `NameError: name 'username' is not defined`.
- **`TypeError`**: Це помилка, яку Python видає, коли операція або функція застосовується до об’єкта невідповідного типу. Наприклад, якщо ви спробуєте додати рядок до числа, отримаєте помилку `TypeError: can only concatenate str (not "int") to str`.
- **`IndexError`**: Ви отримаєте `IndexError`, якщо звернетеся до індексу, якого не існує у списку або інших послідовностях, таких як кортежі чи рядки. Наприклад, у рядку `Hello world` індекс останнього символу — `10`. Якщо ви спробуєте звернутися до символу так: `greet = "hello world"; print(greet[11])`, отримаєте помилку з повідомленням `IndexError: string index out of range`.
- **`AttributeError`**: Python видає цю помилку, коли ви намагаєтеся використати метод або властивість, якої не існує у об’єкта цього типу. Наприклад, виклик `.append()` для рядка, як у `"hello".append("!")`, призведе до помилки з повідомленням `AttributeError: 'str' object has no attribute 'append'`.

## Хороші техніки налагодження в Python

- **Використання функції `print`**: Вставлення операторів `print()` у різних місцях вашого коду під час налагодження допомагає бачити значення змінних і як проходить потік вашого коду.
- **Використання вбудованого налагоджувача Python (`pdb`)**: Python надає модуль `pdb` для налагодження як частину стандартної бібліотеки. Виклик `pdb.set_trace()` призупиняє виконання і відкриває інтерактивний запит. Ви можете ввести `help` для списку команд, `whatis` для перевірки типу виразу, а також `continue` (або його псевдоніми `cont` і `c`) для відновлення виконання програми.
- **Використання інструментів налагодження IDE**: Інтегровані середовища розробки (IDE) та редактори коду, як PyCharm і VS Code, пропонують візуальні інструменти налагодження. Наприклад, VS Code надає наступне:
  - **Точки зупинки**: Натисніть у вертикальному розриві редактора, щоб встановити точку зупинки (представлену червоною крапкою), де виконання має призупинитися.
  - **Перевірка змінних і консоль налагодження**: Наведіть курсор на змінні або перегляньте панель Variables, щоб побачити поточні значення, а також використовуйте консоль налагодження для інтерактивної оцінки виразів.
  - **Керування кроками**:
    - **Продовжити (<kbd>F5</kbd>)**: Відновлює виконання до наступної точки зупинки.
    - **Крок через (<kbd>F10</kbd>)**: Виконує поточну лінію і переходить до наступної, не заходячи у виклики функцій.
    - **Крок у (<kbd>F11</kbd>)**: Заходить у викликану функцію, щоб пройти її лінії.
    - **Крок з виходу (<kbd>Shift</kbd> + <kbd>F11</kbd>)**: Завершує поточну функцію і повертається до виклику.

## Обробка виключень

- **`try...except`**: це використовується для виконання блоку коду, який може викликати виняток. Блок `try` — це місце, де ви очікуєте, що може виникнути помилка, а блок `except` перехоплює вказаний виняток і виконується, якщо ця помилка виникає. Ось приклад:

  ```py
  try:
    print(22 / 0)
  except ZeroDivisionError:
    print('You can\'t divide by zero!')
    # You can't divide by zero!
  ```

  Ви також можете ланцюжити кілька блоків `except`, щоб обробляти різні типи виключень:

  ```py
  try:
    number = int(input('Enter a number: '))
    print(22 / number)
  except ZeroDivisionError:
    print('You cannot divide by zero!')
    # You cannot divide by zero! prints when you enter 0
  except ValueError:
    print('Please enter a valid number!')
    # Please enter a valid number! prints when you don't enter an integer
  ```

  Ви також можете обробляти кілька типів виключень в одному блоці `except`, згрупувавши їх у кортеж:

  ```py
  try:
    number = int(input('Enter a number: '))
    result = 10 / number
  except (ValueError, ZeroDivisionError) as e:
    print(f'Error occurred: {e}')
  ```

- **`else` і `finally`**: Ці блоки розширюють `try...except`. Якщо виключення не виникає, виконується блок `else`. Блок `finally` виконується завжди, незалежно від помилок.

  ```py
  try:
    result = 100 / 4
  except ZeroDivisionError:
    print('You cannot divide by zero!') # This will not run
  else:
    print(f'Result is {result}') # Result is 25.0
  finally:
    print('Execution complete!') # Execution complete!
  ```

- **Об’єкт виключення**: Дозволяє отримати доступ до самого виключення для кращого налагодження і виведення прямого повідомлення про помилку. Щоб отримати об’єкт виключення, потрібно використати ключове слово `as`. Ось приклад:

  ```py
  try:
      value = int('This will raise an error')
  except ValueError as e:
      print(f'Caught an error: {e}')
      # Caught an error: invalid literal for int() with base 10: 'This will raise an error'
  ```

- **Інструкція `raise`**: Вона дозволяє вручну викликати виняток. Ви можете використовувати її, щоб викликати виняток, коли певна умова виконується:

  ```py
  def divide(a, b):
      if b == 0:
          raise ZeroDivisionError('You cannot divide by zero')
      return a / b
  ```

  Використання `raise` без аргументів всередині блоку `except` повторно викликає поточне виключення, яке обробляється. Це дозволяє вам зареєструвати помилку або виконати очищення, одночасно передаючи виключення далі по стеку викликів:

  ```py
  def process_data(data):
      try:
          result = int(data)
          return result * 2
      except ValueError:
          print('Logging: Invalid data received')
          raise
  ```

- **Інструкція `assert`**: Інструкція `assert` перевіряє припущення під час налагодження і викликає `AssertionError`, коли умова є хибною. Оскільки Python видаляє твердження під час запуску в оптимізованому режимі (`-O`), твердження не слід використовувати для критичної валідації вхідних даних, яка має виконуватися завжди. Замість цього використовуйте явну умову та `raise` для необхідних перевірок.

## Сигналізація виключень

- **Кастомні виключення**: Інструкція `raise` також корисна, коли ви створюєте власні кастомні виключення, наслідуючи клас `Exception`. Це дозволяє викидати помилки з логікою та повідомленнями, специфічними для вашої предметної області:

  ```py
  class InvalidCredentialsError(Exception):
      def __init__(self, message="Invalid username or password"):
          self.message = message
          super().__init__(self.message)

  def login(username, password):
      stored_username = "admin"
      stored_password = "password123"
      
      if username != stored_username or password != stored_password:
          raise InvalidCredentialsError()
      
      return f"Welcome, {username}!"
  ```

  Ось як ви можете використати функцію `login` з виключенням `InvalidCredentialsError`:

  ```py
  # failed login attempt
  try:
      message = login("user", "wrongpassword")
  except InvalidCredentialsError as e:
      print(f"Login failed: {e}")
  else:
      print(message)

  # successful login attempt
  try:
      message = login("admin", "password123")
  except InvalidCredentialsError as e:
      # This block is not executed because the login was successful
      print(f"Login failed: {e}")
  else:
      # The else block runs if the 'try' block completes without an exception
      print(message)
  ```

- **Ланцюжок виключень**: інструкцію `raise` можна використовувати з ключовим словом `from` для ланцюжка виключень. Використання `from None` приховує контекст початкового виключення у відображеному трасуванні, тоді як `from e` явно фіксує початкове виключення як причину:

  ```py
  def parse_config(filename):
      try:
          with open(filename, 'r') as file:
              data = file.read()
              return int(data)
      except FileNotFoundError:
          raise ValueError('Configuration file is missing') from None
      except ValueError as e:
          raise ValueError('Invalid configuration format') from e

  config = parse_config('config.txt')
  ```
