## 搜尋演算法

- **目的**：搜尋演算法讓你能在一個項目列表中搜尋標的。
- **搜尋演算法類型**：兩種常見的搜尋演算法是線性搜尋和二分搜尋法。了解它們的差異有助於判斷何時使用哪一種。

### 線性搜尋

- **線性搜尋演算法**：從列表開頭開始逐項檢查，直到找到標的為止。
- **成功搜尋**：如果找到標的項目，會傳回該項目在列表中的索引。
- **失敗搜尋**：課程中的實作會傳回 `-1` 表示未找到標的。在 Python 中，`-1` 也會索引非空列表的最後一個元素，因此在用作索引前要先檢查結果是否為 `-1`。否則，失敗的搜尋可能會錯誤地取得最後一個元素。
- **效率**：因為線性搜尋是逐項檢查，對於大型列表可能效率不佳。
- **時間複雜度**：`O(n)`，因為搜尋所需時間會隨列表大小線性增加。
- **空間複雜度**：`O(1)`，因為不論輸入大小，都只使用固定量的額外空間。

### 二元搜尋

- **二分搜尋法演算法**：一種高效的搜尋演算法，透過反覆將已排序的列表分成兩半來尋找標的值。
- **排序輸入前提**：二分搜尋法要求輸入列表必須以遞增順序排序。
- **搜尋範圍初始化**：將 `low = 0` 設為第一個元素的索引，`high = len(arr) - 1` 設為最後一個元素的索引。這兩個變數定義了包含邊界的搜尋區間。
- **搜尋持續條件**：當 `low <= high` 時繼續搜尋。如果 `low > high`，表示搜尋範圍為空，代表未找到標的。
- **中點計算**：使用整數除法計算中間索引：`mid = (low + high) // 2`。
- **標的比較**：將標的值與 `arr[mid]` 比較。如果兩者相等，表示在索引 `mid` 找到標的。
- **下界更新**：如果 `arr[mid] < target`，表示標的若存在，必定在右半部。將 `low = mid + 1` 更新為排除中點及其之前的所有元素。
- **上界更新**：如果 `arr[mid] > target`，表示標的若存在，必定在左半部。將 `high = mid - 1` 更新為排除中點及其之後的所有元素。
- **講義成功搜尋**：講義的實作在找到標的時會傳回該標的的索引。
- **講義失敗搜尋**：講義的實作在搜尋範圍變空時會傳回 `-1`。
- **工作坊路徑追蹤**：工作坊的實作初始化一個空的 `path_to_target` 列表，並在搜尋過程中將每個訪問過的中點值加入其中。
- **工作坊成功搜尋**：當找到標的時，工作坊會傳回一個包含 `path_to_target` 和一則指出標的索引的訊息的元組。
- **工作坊未成功搜尋**：當搜尋範圍變空時，工作坊會傳回一個空列表和一則 `"Value not found"` 訊息。
- **時間複雜度**：`O(log n)`，因為每次比較後搜尋範圍大約減半。
- **空間複雜度**：講義實作使用 `O(1)` 的輔助空間，包含 `low`、`high` 和 `mid` 等變數。工作坊實作使用 `O(log n)` 的輔助空間，因為 `path_to_target` 儲存了搜尋過程中訪問的中點值。

### 線性搜尋與二元搜尋的差異

- **前提條件**：線性搜尋不需要排序列表，而二分搜尋要求輸入資料必須以遞增順序排序。
- **擴展性**：與線性搜尋相比，二分搜尋更適合用於大型項目列表。
- **時間複雜度比較**：線性搜尋的時間複雜度為 `O(n)`，而二分搜尋為 `O(log n)`。

## 排序演算法與分治法

- **分治法**：一種將問題拆解成較小子問題以便更容易解決的技巧。遞迴常用於實作這種方法，並且是高效排序演算法（如合併排序）常用的策略。

### 合併排序

- **合併排序演算法**：一種遵循分治法的排序演算法。
- **基底條件**：長度為零或一的列表已經排序完成，當 `len(array) <= 1` 時遞迴停止。
- **拆分列表**：將列表分割成兩個切片的半部，並遞迴排序每一半。
- **合併子列表**：比較兩個已排序半部中尚未合併的下一個元素，將較小的元素複製到下一個輸出位置，並前進該半部的索引。當其中一半用盡後，將另一半剩餘的所有元素複製過去。
- **工作坊實作**：工作坊會創建切片半部，並將合併後的值寫回原始列表，每寫入一次就前進 `sorted_index`。修改原始列表並不代表這是就地排序演算法，因為切片半部仍需要額外的儲存空間。
- **時間複雜度**：`O(n log n)`，因為列表被反覆分成兩半（`log n` 層級），每層合併元素花費 `O(n)` 時間。
- **空間複雜度**：`O(n)`，因為合併排序需要額外記憶體來合併子列表，並非就地排序演算法。
