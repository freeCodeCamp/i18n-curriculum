## Introducción a la programación dinámica

- **Definición**: La programación dinámica es una técnica algorítmica que resuelve problemas complejos dividiéndolos en subproblemas más simples y almacenando los resultados para evitar cálculos redundantes.
- **Subproblemas superpuestos**: Los mismos problemas más pequeños aparecen varias veces al resolver el problema mayor. En lugar de recalcular estos subproblemas repetidamente, almacenamos sus soluciones.
- **Subestructura óptima**: La solución óptima al problema contiene soluciones óptimas a sus subproblemas. Esto significa que podemos construir la mejor solución combinando las mejores soluciones a partes más pequeñas.

## El problema de subir escaleras

Una ilustración clásica de la programación dinámica es contar las formas distintas de llegar a la cima de una escalera con un número positivo de escalones `n`, donde cada movimiento puede subir 1 o 2 escalones:

- **Recursión ingenua**: Como el número de formas de llegar al escalón `n` es la suma de las formas de llegar al escalón `n - 1` y al escalón `n - 2`, una solución recursiva directa recalcula subproblemas idénticos repetidamente. Por ejemplo, calcular el escalón `5` recalcula el escalón `3` dos veces y el escalón `2` tres veces. Esto conduce a una complejidad temporal exponencial de orden superior `O(2^n)` y un espacio de pila de llamadas `O(n)`.

## Soluciones de programación dinámica

La programación dinámica elimina el cálculo redundante mediante dos enfoques principales:

- **Memorización (enfoque de arriba hacia abajo)**: La memorización almacena los resultados de las llamadas a funciones en una caché (como un diccionario) y devuelve el resultado almacenado cuando se encuentra el mismo subproblema nuevamente:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

Con una caché inicialmente vacía, la memorización reduce la complejidad temporal a lineal `O(n)`, requiriendo un espacio `O(n)` para almacenar los subproblemas en caché junto con la pila de llamadas recursivas.

- **Tabulación (enfoque de abajo hacia arriba)**: La tabulación elimina la recursión construyendo iterativamente la solución desde los subproblemas más pequeños hasta el objetivo, almacenando resultados intermedios en una lista:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

La tabulación se ejecuta en tiempo `O(n)` y usa espacio `O(n)` para la lista, con la ventaja clave de evitar el crecimiento de la pila de llamadas recursivas.

- **Optimización de tabulación con espacio constante**: Debido a que cada nuevo escalón depende solo de los dos valores anteriores, la tabla completa puede reemplazarse con dos variables que almacenan los dos últimos conteos:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

Tratando cada operación aritmética como tiempo constante y cada conteo almacenado como una unidad de espacio, esta optimización mantiene el tiempo `O(n)` mientras reduce la complejidad de espacio auxiliar a `O(1)`.

## Ejemplo Práctico: Problema del Cambio de Monedas

El problema del cambio de monedas es un problema clásico de optimización que pregunta por el número mínimo de monedas necesarias para alcanzar una cantidad objetivo:

- **Algoritmo**: El algoritmo usa tabulación creando un arreglo `dp` de tamaño `amount + 1`, inicializado a infinito (`float('inf')`) para representar valores inicialmente inalcanzables. El caso base es `dp[0] = 0` porque no se necesitan monedas para hacer una cantidad de `0`. Para cada cantidad `i` desde `1` hasta `amount`, el algoritmo minimiza `dp[i - coin] + 1` entre todas las denominaciones de monedas elegibles (`coin <= i`). Si `dp[amount]` sigue siendo infinito, no se puede formar el objetivo, por lo que se devuelve `-1`:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

Para las denominaciones `[1, 3, 4]` y el objetivo `6`, el algoritmo calcula `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`, produciendo una combinación óptima de dos monedas (`3 + 3`).

- **Complejidad**: El algoritmo verifica cada denominación para cada subcantidad hasta el objetivo, resultando en una complejidad temporal de `O(amount * number_of_coins)` y una complejidad de espacio auxiliar de `O(amount)` para el arreglo DP.

## Aplicaciones reales usando programación dinámica

- **Optimización de rutas**: Los sistemas GPS usan algoritmos de programación dinámica para encontrar las rutas más cortas entre ubicaciones.
- **Procesamiento de texto**: Los correctores ortográficos y las funciones de autocompletar suelen apoyarse en la programación dinámica para calcular las distancias de edición entre palabras.
- **Modelado financiero**: Las estrategias de inversión y la optimización de portafolios emplean con frecuencia técnicas de programación dinámica.
- **Asignación de recursos**: El problema de la mochila y sus variantes aparecen en la programación de tareas, presupuestos y gestión de recursos.

## Cuándo usar programación dinámica

Deberías considerar usar programación dinámica en los siguientes casos:

- El problema puede dividirse en subproblemas que se superponen.
- El problema presenta una subestructura óptima.
- Una solución recursiva ingenua implicaría cálculos repetidos.
- Necesitas optimizar la complejidad temporal a costa de la complejidad espacial.
