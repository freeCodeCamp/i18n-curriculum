## Introduzione alla programmazione dinamica

- **Definizione**: la programmazione dinamica è una tecnica algoritmica che risolve problemi complessi scomponendoli in sottoproblemi più semplici e memorizzando i risultati per evitare calcoli ridondanti.
- **Sottoproblemi sovrapposti**: gli stessi sottoproblemi più piccoli appaiono più volte quando si risolve il problema più grande. Invece di ricalcolare questi sottoproblemi ripetutamente, memorizziamo le loro soluzioni.
- **Sottostruttura ottimale**: la soluzione ottimale al problema contiene soluzioni ottimali ai suoi sottoproblemi. Questo significa che possiamo costruire la migliore soluzione combinando le migliori soluzioni alle parti più piccole.

## Il problema della scala

Un classico esempio di programmazione dinamica è contare i modi distinti per raggiungere la cima di una scala con un numero positivo di gradini `n`, dove ogni mossa può salire di 1 o 2 gradini:

- **Ricorsione ingenua**: Poiché il numero di modi per raggiungere il gradino `n` è la somma dei modi per raggiungere il gradino `n - 1` e il gradino `n - 2`, una soluzione ricorsiva diretta ricalcola ripetutamente gli stessi sottoproblemi. Per esempio, calcolare il gradino `5` ricalcola il gradino `3` due volte e il gradino `2` tre volte. Questo porta a una complessità temporale esponenziale con limite superiore `O(2^n)` e a uno spazio di pila di chiamate `O(n)`.

## Soluzioni di programmazione dinamica

La programmazione dinamica elimina i calcoli ridondanti attraverso due approcci principali:

- **Memoizzazione (approccio top-down)**: La memoizzazione archivia i risultati delle chiamate di funzione in una cache (come un dizionario) e restituisce il risultato memorizzato quando si incontra di nuovo lo stesso sottoproblema:

```py
def climb_stairs_memo(n, memo={}):
    """Dynamic programming with memoization"""
    # Check if we've already calculated this value
    if n in memo:
        return memo[n]  # Return cached result - O(1) lookup!
    
    # Base cases
    if n <= 2:
        return n
    
    # Calculate once and store in memo for future use
    memo[n] = climb_stairs_memo(n-1, memo) + climb_stairs_memo(n-2, memo)
    return memo[n]
```

Con una cache inizialmente vuota, la memoizzazione riduce la complessità temporale a lineare `O(n)`, richiedendo uno spazio `O(n)` per archiviare i sottoproblemi memorizzati insieme alla pila di chiamate ricorsive.

- **Tabulazione (approccio bottom-up)**: La tabulazione elimina la ricorsione costruendo iterativamente la soluzione dai sottoproblemi più piccoli fino all'obiettivo, archiviando i risultati intermedi in una lista:

```py
def climb_stairs_tabulation(n):
    """Dynamic programming with tabulation"""
    if n <= 2:
        return n
    
    # Create array to store results for all steps from 0 to n
    dp = [0] * (n + 1)
    dp[1] = 1  # 1 way to reach step 1
    dp[2] = 2  # 2 ways to reach step 2
    
    # Build up the solution iteratively
    for i in range(3, n + 1):
        # Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
        dp[i] = dp[i-1] + dp[i-2]
    
    return dp[n]
```

La tabulazione ha una complessità temporale `O(n)` e usa uno spazio `O(n)` per la lista, con il vantaggio chiave di evitare la crescita della pila di chiamate ricorsive.

- **Ottimizzazione della tabulazione a spazio costante**: Poiché ogni nuovo gradino dipende solo dai due valori precedenti, la tabella completa può essere sostituita da due variabili che archiviano gli ultimi due conteggi:

```py
def climb_stairs_optimized(n):
    if n <= 2:
        return n
    
    prev2, prev1 = 1, 2  # Only store the last two values
    for i in range(3, n + 1):
        current = prev1 + prev2
        prev2, prev1 = prev1, current
    return prev1
```

Considerando ogni operazione aritmetica come tempo costante e ogni conteggio memorizzato come un'unità di spazio, questa ottimizzazione mantiene il tempo `O(n)` riducendo la complessità dello spazio ausiliario a `O(1)`.

## Esempio pratico: problema del cambio monete

Il problema del cambio monete è un classico problema di ottimizzazione che chiede il numero minimo di monete necessario per raggiungere un importo obiettivo:

- **Algoritmo**: L'algoritmo usa la tabulazione creando un array `dp` di dimensione `amount + 1`, inizializzato a infinito (`float('inf')`) per rappresentare valori inizialmente irraggiungibili. Il caso base è `dp[0] = 0` perché non servono monete per ottenere un importo di `0`. Per ogni importo `i` da `1` a `amount`, l'algoritmo minimizza `dp[i - coin] + 1` tra tutte le denominazioni di monete ammissibili (`coin <= i`). Se `dp[amount]` rimane infinito, l'obiettivo non può essere raggiunto, quindi si restituisce `-1`:

```py
def min_coins(amount, coins):
    """Find minimum number of coins needed to make the given amount"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # Base case: 0 coins needed for amount 0
    
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1
```

Per le denominazioni `[1, 3, 4]` e l'obiettivo `6`, l'algoritmo calcola `dp[6] = min(dp[5] + 1, dp[3] + 1, dp[2] + 1) = 2`, producendo una combinazione ottimale di due monete (`3 + 3`).

- **Complessità**: L'algoritmo verifica ogni denominazione per ogni sottoimporto fino all'obiettivo, risultando in una complessità temporale `O(amount * number_of_coins)` e in una complessità spaziale ausiliaria `O(amount)` per l'array DP.

## Applicazioni reali che usano la programmazione dinamica

- **Ottimizzazione delle rotte**: i sistemi GPS usano algoritmi di programmazione dinamica per trovare i percorsi più brevi tra le località.
- **Elaborazione del testo**: i correttori ortografici e le funzionalità di completamento automatico spesso si basano sulla programmazione dinamica per calcolare le distanze di modifica tra le parole.
- **Modellazione finanziaria**: le strategie di investimento e l'ottimizzazione del portfolio impiegano frequentemente tecniche di programmazione dinamica.
- **Assegnazione delle risorse**: il problema dello zaino e le sue varianti compaiono nella pianificazione, nel budgeting e nella gestione delle risorse.

## Quando usare la programmazione dinamica

Dovresti considerare di usare la programmazione dinamica nei seguenti casi:

- Il problema può essere suddiviso in sotto-problemi sovrapposti.
- Il problema presenta una struttura ottimale dei sotto-problemi.
- Una soluzione ricorsiva ingenua comporterebbe calcoli ripetuti.
- Hai bisogno di ottimizzare la complessità temporale a scapito della complessità spaziale.
