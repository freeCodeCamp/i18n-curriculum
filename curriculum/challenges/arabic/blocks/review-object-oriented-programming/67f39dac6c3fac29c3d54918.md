## ما هو البرمجة الموجهة للكائنات؟

- **البرمجة كائنية التوجه**: أسلوب برمجي يعامل فيه المطوّرون كل شيء في كودهم ككائن من العالم الحقيقي. يُعرف هذا الأسلوب اختصارًا بـ OOP. المبادئ الأربعة الأساسية التي تساعدك على تنظيم وإدارة الكود بفعالية هي **التغليف**، **الوراثة**، **تعدد الأشكال**، و**التجريد**.
- **الأصناف**: هي المخطط لإنشاء الكائنات. كل كائن يُنشأ من صنف يحتوي على خصائص تحدد البيانات وطرق تحدد سلوكيات الكائن.

## ما هو التغليف؟

- **التغليف**: تجميع الخصائص والطرق الخاصة بكائن في وحدة واحدة. يسمح لك بإخفاء الحالة الداخلية للكائن خلف مجموعة بسيطة من الطرق والخصائص العامة التي تعمل كبوابات. خلف هذه البوابات توجد خصائص وطرق خاصة تتحكم في كيفية تغير البيانات ومن يمكنه رؤيتها.
- **مثال على التغليف**: إذا أردت تتبع رصيد محفظة، ستسمح بالإيداع والسحب، لكنك لن تسمح لأي شخص بالتلاعب برصيد المحفظة نفسه:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **الفرق بين بادئة الخاصيات بشرطة سفلية واحدة وشرطتين سفليتين**: وضع شرطة سفلية واحدة كبادئة للخاصيات والطرق يشير إلى أنها مخصصة للاستخدام الداخلي فقط. هذا مجرد اصطلاح، وPython لا يمنع الوصول إليها من خارج الصنف. أما وضع شرطتين سفليتين كبادئة فيُفعّل عملية تشويش الأسماء، التي تعيد تسمية `__balance` إلى `_Wallet__balance`. هذا يساعد على تجنب التصادمات العرضية في الأسماء داخل الأصناف الفرعية، لكنه لا يمنع الوصول الخارجي تمامًا:

```py
print(account._Wallet__balance) # 500
```

## ما هي الدوال الجالبة والمضبوطة (Getters and Setters)؟

- **الدوال الجالبة والمضبوطة**: طرق تتيح لك التحكم في كيفية الوصول إلى خاصيات الصنف وتعديلها. تسترجع القيم باستخدام الدوال الجالبة وتعيّن القيم باستخدام الدوال المضبوطة.
- **الخصائص**: تربط بين الدوال الجالبة والمضبوطة، وتسمح بالوصول إلى البيانات. تنفذ منطقًا إضافيًا خلف الكواليس عند الحصول على القيم أو تعيينها أو حذفها.
- **لماذا الخصائص بدلًا من الطرق؟** تُستخدم الخصائص بدلاً من الطرق لتحسين قابلية القراءة وتنظيف الكود. تتيح لك الوصول إلى القيم باستخدام ترميز النقطة، مثل الخاصيات العادية، بدون الحاجة إلى أقواس عادية.
- **المزخرفات**: المزخرف هو دالة تعدل أو تغلف دوال أو أصناف أخرى دون تغيير كودها الأصلي. تطبق المزخرف بوضع `@decorator_name` مباشرة فوق تعريف دالة أو صنف. على سبيل المثال، وضع المزخرف `@property` فوق طريقة يحولها إلى خاصية، بحيث يمكن الوصول إليها كخاصية بينما تستدعي داخليًا الطريقة المزخرفة.
- **إنشاء دالة جالبة**: لإنشاء دالة جالبة، تستخدم المزخرف `@property`. إليك دالة جالبة تسترجع نصف قطر دائرة:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **إنشاء دالة مضبوطة**: لإنشاء الدالة المضبوطة التي تعيّن نصف القطر، يجب تعريف دالة أخرى بنفس الاسم واستخدام المزخرف `@<property_name>.setter` فوقها:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **كيفية تعامل Python مع الدوال الجالبة والمضبوطة**: بمجرد تعريف الدوال الجالبة والمضبوطة، يستدعيها Python تلقائيًا تحت الكواليس كلما استخدمت صيغة الوصول العادية للخاصية بهذه الطريقة:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

داخل الدالة المضبوطة، يجب ألا تعيّن إلى اسم الخاصية نفسه لأن ذلك سيسبب `RecursionError`.

- **المزيل (Deleter)**: بعد تعيين القيمة واسترجاعها باستخدام setter وgetter، يمكنك التحكم في كيفية حذفها باستخدام `deleter`. ينفذ المزيل منطقًا مخصصًا عند استخدام عبارة `del` على خاصية. لإنشاء مزيل، استخدم الـ `@<property_name>.deleter` decorator.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## ما هي الوراثة وكيف تعزز إعادة استخدام الكود؟

- **الوراثة**: هي العملية التي يستخدم فيها الصنف الفرعي خصائص وطرق الصنف الأب. تعزز الوراثة إعادة استخدام الكود، وتوفر تسلسلات هرمية واضحة، وتخصص السلوك دون الحاجة لإعادة كتابة كل شيء. لتنفيذ الوراثة، يأخذ الصنف الفرعي اسم الصنف الأب:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **الوراثة المفردة والمتعددة**: عندما يرث صنف فرعي الخصائص والطرق من صنف أبوي واحد، كما في المثال أعلاه، تسمى هذه **الوراثة المفردة**. أما عندما يرث صنف فرعي من أكثر من صنف أبوي، فتسمى **الوراثة المتعددة**. إليك الصيغة لذلك:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **دالة `super()`**: دالة تتيح لك **استدعاء** طريقة من صنف الأب، عندما يكون للصنف تنفيذ مختلف لتلك الطريقة، أو عندما يوسع الطريقة، دون تكرار الكود.

## ما هو التعددية الشكلية (Polymorphism) وكيف تعزز إعادة استخدام الكود؟

- **تعدد الأشكال**: مبدأ في البرمجة كائنية التوجه يسمح لأصناف مختلفة باستخدام نفس اسم الطريقة، لكن كل صنف ينفذها بطريقة مختلفة عند الاستدعاء. إليك الصيغة لذلك:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **تعدد الأشكال القائم على الوراثة**: يحدد الصنف الأبوي طريقة، ويعدل كل صنف فرعي هذه الطريقة حسب استخدامه.

## ما هو تشويش الأسماء وكيف يعمل؟

- **تشويش الأسماء**: عملية يعيد فيها Python داخليًا تسمية خاصية تبدأ بشرطتين سفليتين بإضافة شرطة سفلية واسم الصنف كبادئة، محولًا `__attribute` إلى `_ClassName__attribute`.
- **هدف تشويش الأسماء**: الهدف الرئيسي من تشويش الأسماء هو منع تجاوز الخاصيات والطرق عن طريق الخطأ عند استخدام الوراثة. إليك مثال كود يوضح ذلك بشكل أفضل:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## ما هو التجريد وكيف يساعد في تنظيم الأنظمة المعقدة؟

- **التجريد**: مفهوم برمجي يخفي تفاصيل التنفيذ المعقدة لكائن أو نظام ويُظهر فقط الميزات الأساسية. في Python ولغات برمجة أخرى، يبسط التجريد الأنظمة المعقدة بزيادة إعادة الاستخدام.
- **مثال على التجريد**: مثال جيد على التجريد في الحياة اليومية هو السيارة التي تتيح لك استخدام المقود والدواسات وناقل الحركة فقط دون معرفة كيفية عمل المحرك أو المكابح.
- **كيف ينفذ Python التجريد**: يمكنك إنشاء تجريدات باستخدام الدوال والأصناف العادية عن طريق إخفاء تفاصيل التنفيذ خلف واجهة بسيطة. للواجهات الأكثر رسمية، يوفر وحدة `abc` في Python الصنف المساعد `ABC` والمزخرف `@abstractmethod`. يحدد الصنف الأساسي المجرد الطرق والخصائص المشتركة التي يُتوقع من الأصناف الفرعية الملموسة توفيرها.
- **كيفية تعريف الطرق المجردة**: تُعرف الطريقة المجردة باستخدام `@abstractmethod`. لا يمكن إنشاء نسخة من الصنف إلا إذا قدم أو ورث تنفيذات ملموسة لكل طرقه المجردة. يبقى الصنف الفرعي مجردًا إذا ترك أي طريقة مجردة غير منفذة. يمكن أن تحتوي الطريقة المجردة على تنفيذ افتراضي يمكن للأصناف الفرعية استدعاؤه باستخدام `super()`. الوراثة من `ABC` وحدها لا تمنع إنشاء النسخ: يمكن إنشاء نسخ من `ABC()` ومن الأصناف الفرعية التي لا تحتوي على طرق مجردة. الصيغة الأساسية للتجريد تبدو هكذا:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## تمثيلات الكائنات

- **طريقة `__repr__`**: طريقة خاصة تُرجع تمثيلًا نصيًا للكائن. من المثالي أن يبدو هذا النص مثل الكود المستخدم لإنشاء الكائن. على سبيل المثال، يجب تمثيل `Employee('Charlie', 'developer')` كـ `Employee('Charlie', 'developer')`.
- **دالة `repr()`**: عند استدعاء `repr()` على كائن، يستدعي Python داخليًا طريقة `__repr__` لذلك الكائن. بالنسبة للسلاسل النصية، تضيف `repr()` علامات اقتباس وتُهرب أي أحرف تحتاج ذلك:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **تحويل `!r`**: داخل سلسلة f، إضافة `!r` بعد تعبير يطبق `repr()` عليه. استخدام `!r` في `__repr__` يحافظ على صحة التمثيل عندما تحتوي القيمة على علامات اقتباس أو شرطات مائلة عكسية، على عكس تغليف القيم بالاقتباسات يدويًا:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## سلاسل التوثيق وفحوصات النوع

- **سلاسل التوثيق**: سلسلة نصية توضع كأول بيان في صنف أو دالة لتوثيقها. عادةً ما تُحاط بسلاسل علامات اقتباس مزدوجة ثلاثية:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()` مقابل `type()`**: تعيد `isinstance(obj, ClassName)` القيمة `True` إذا كان `obj` نسخة من `ClassName` أو أي من أصنافه الفرعية، لأنها تأخذ في الاعتبار سلسلة الوراثة كاملة. للتحقق من صنف محدد بدقة، قارن مع `type(obj)` بدلاً من ذلك:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## الاستثناءات المخصصة مع سياق إضافي

- **تخزين السياق على استثناء**: يمكن للاستثناء المخصص قبول بيانات إضافية مع رسالته. استدعاء `super().__init__(message)` يسمح للصنف المدمج `Exception` بتخزين الرسالة وعرضها، ثم يمكنك تخزين البيانات الإضافية كخاصية. عند التقاط الاستثناء، يمكنك قراءة تلك الخاصية للمساعدة في تصحيح الأخطاء:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## تلميحات النوع

- **تلميحات النوع**: تعليقات اختيارية تشير إلى المطوّرين الآخرين نوع البيانات المتوقع لمتغير أو معلمة أو قيمة إرجاع. Python لا تفرضها أثناء التشغيل.
- **تلميحات نوع المعلمات وقيمة الإرجاع**: تضيف تلميح نوع المعلمة بنقطتين بعد اسم المعلمة، وتلميح نوع الإرجاع بـ `-> return_type` بعد قائمة المعلمات. بما أن `__init__` هو مهيئ يجب أن تكون قيمة إرجاعه `None`، فإن تلميح نوع الإرجاع له هو `None`:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **الأصناف والقوائم المخصصة كأنواع**: يمكنك استخدام أصنافك الخاصة كتلميحات نوع، و`list[ClassName]` تحدد قائمة تحتوي على كائنات من ذلك الصنف:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
