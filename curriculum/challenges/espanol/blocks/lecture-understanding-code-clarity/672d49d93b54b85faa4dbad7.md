# --description--

Así como un punto (`.`) puede marcar el final de una oración en inglés, un punto y coma (`;`) puede usarse para marcar el final de una sentencia en JavaScript. Sin embargo, las sentencias no son necesariamente lo mismo que las líneas de código fuente. Una sentencia puede abarcar varias líneas y una sola línea puede contener más de una sentencia.

Por ejemplo:

```js
let variableOne = 5;
let variableTwo = 10;
```

En este código, los puntos y coma hacen explícito el final de cada sentencia. JavaScript también tiene la inserción automática de punto y coma (ASI), que permite que estas declaraciones sean válidas sin puntos y coma explícitos:

```js
let variableOne = 5
let variableTwo = 10
```

En este ejemplo, ASI permite que JavaScript trate cada declaración como una sentencia separada aunque no haya puntos y coma. Sin embargo, ASI no inserta simplemente un punto y coma después de cada salto de línea.

Por ejemplo, un salto de línea después de una sentencia `return` puede causar un comportamiento inesperado:

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

Aquí, ASI inserta un punto y coma después de `return`, por lo que la función devuelve `undefined` en lugar del objeto. Escribir el objeto en la misma línea evita este comportamiento:

```js
function getValue() {
  return {
    value: 42
  };
}
```

Esto muestra por qué los saltos de línea y los límites de las sentencias no siempre son lo mismo.

Los puntos y coma también pueden ser útiles cuando un salto de línea podría permitir que dos fragmentos de código se interpreten como una sola expresión. Una expresión de función inmediatamente invocada (IIFE) es una función que se ejecuta tan pronto como se define. Una forma de crear una IIFE es envolver una función anónima, que es una función sin nombre, entre paréntesis y agregar `()` al final para llamarla. Una IIFE puede causar un problema cuando la sentencia anterior no termina con un punto y coma:

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

Aquí, JavaScript no inserta un punto y coma después de la declaración de la cadena porque el siguiente `(` puede continuar la expresión inicializadora. JavaScript interpreta la inicialización como una llamada a la cadena `"Hello"`, con la expresión de función como argumento. Esto lanza un `TypeError` antes de que la IIFE pueda ejecutarse. Agregar un punto y coma termina la declaración antes de la IIFE:

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

El punto y coma explícito mantiene la declaración de la variable y la IIFE como sentencias separadas.

Los puntos y coma se usan en muchos lenguajes de programación, incluidos C, C++ y Java. Sus reglas exactas varían entre lenguajes, pero comúnmente ayudan a indicar dónde terminan las sentencias.

Un compilador traduce el código fuente a otra forma, como código máquina, bytecode o una representación intermedia, según el lenguaje y el compilador. La compilación no necesariamente produce un archivo ejecutable independiente.

Usar puntos y coma de forma consistente puede hacer que los límites de las sentencias sean más claros y que el código sea más fácil de leer y mantener.
