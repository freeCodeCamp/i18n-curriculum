## 객체지향 프로그래밍이란?

- **객체지향 프로그래밍**: 개발자가 코드 내 모든 것을 실제 세계의 객체처럼 다루는 프로그래밍 스타일입니다. 흔히 OOP라고 부릅니다. 코드를 효과적으로 조직하고 관리하는 데 도움이 되는 네 가지 핵심 원칙은 **캡슐화**, **상속**, **다형성**, 그리고 **추상화**입니다.
- **클래스**: 객체를 생성하기 위한 청사진입니다. 클래스에서 생성된 모든 객체는 데이터를 정의하는 속성과 객체의 동작을 결정하는 메서드를 가집니다.

## 캡슐화란 무엇인가?

- **캡슐화**: 객체의 속성과 메서드를 하나의 단위로 묶는 것입니다. 객체의 내부 상태를 단순한 공개 메서드와 속성 뒤에 숨겨서, 그 문을 통해서만 접근하도록 합니다. 그 문 뒤에는 데이터 변경과 접근을 제어하는 비공개 속성과 메서드가 있습니다.
- **캡슐화 예시**: 지갑 잔액을 추적하려면 입금과 출금은 허용하지만, 잔액 자체를 아무나 조작하지 못하게 합니다:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **속성에 단일 및 이중 밑줄 접두사를 붙이는 차이점**: 속성과 메서드에 단일 밑줄을 접두사로 붙이면 내부 용도로 사용됨을 나타내는 관례입니다. 이는 단지 관례일 뿐이며, Python은 클래스 외부에서의 접근을 제한하지 않습니다. 이중 밑줄을 접두사로 붙이면 이름 맹글링이 발생하여 `__balance`가 `_Wallet__balance`로 이름이 변경됩니다. 이는 하위 클래스에서 우발적인 이름 충돌을 방지하는 데 도움이 되지만 외부 접근을 완전히 막지는 않습니다:

```py
print(account._Wallet__balance) # 500
```

## 게터와 세터란?

- **게터와 세터**: 클래스 속성에 어떻게 접근하고 수정할지 제어할 수 있는 메서드입니다. 게터로 값을 가져오고 세터로 값을 설정합니다.
- **속성**: 게터와 세터를 연결하며 데이터에 접근할 수 있게 합니다. 값을 가져오거나 설정하거나 삭제할 때 내부에서 추가 로직을 실행합니다.
- **메서드 대신 속성을 사용하는 이유**: 속성은 더 나은 가독성과 깔끔한 코드를 위해 메서드 대신 사용됩니다. 소괄호 없이 점 표기법으로 일반 속성처럼 값을 접근할 수 있게 합니다.
- **데코레이터**: 원래 코드를 변경하지 않고 다른 함수나 클래스의 동작을 수정하거나 감싸는 함수입니다. 함수나 클래스 정의 바로 위에 `@decorator_name`을 붙여 적용합니다. 예를 들어, 메서드 위에 `@property` 데코레이터를 붙이면 해당 메서드를 속성처럼 접근할 수 있게 하면서 내부적으로는 데코레이터된 메서드를 호출합니다.
- **게터 생성하기**: 게터를 만들려면 `@property` 데코레이터를 사용하세요. 다음은 원의 반지름을 가져오는 게터 예시입니다:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **세터 생성**: 반지름을 설정하는 세터를 만들려면 같은 이름의 메서드를 정의하고 위에 `@<property_name>.setter`를 붙입니다:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Python의 게터와 세터 처리 방식**: 게터와 세터를 정의하면, 일반 속성 문법을 사용할 때 Python이 자동으로 호출합니다:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

세터 내부에서 프로퍼티 이름에 직접 할당하면 `RecursionError`가 발생하므로 피해야 합니다.

- **딜리터**: 세터와 게터로 값을 설정하고 가져온 후, `deleter`를 사용해 삭제 방식을 제어할 수 있습니다. 딜리터는 프로퍼티에 `del` 문을 사용할 때 사용자 정의 로직을 실행합니다. 딜리터를 만들려면 `@<property_name>.deleter` 데코레이터를 사용합니다.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## 상속이란 무엇이며 코드 재사용에 어떻게 도움이 되나요?

- **상속**: 자식 클래스가 부모 클래스의 속성과 메서드를 사용하는 과정입니다. 상속은 코드 재사용을 촉진하고 명확한 계층 구조를 제공하며, 모든 것을 다시 작성하지 않고 동작을 맞춤화할 수 있게 합니다. 상속을 구현하려면 자식 클래스가 부모 클래스 이름을 받습니다:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **단일 상속과 다중 상속**: 자식 클래스가 단일 부모로부터 속성과 메서드를 상속받으면 **단일 상속**이라 부릅니다. 여러 부모로부터 상속받으면 **다중 상속**입니다. 문법은 다음과 같습니다:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **`super()` 함수**: 클래스가 메서드를 다르게 구현하거나 확장할 때, 부모 클래스의 메서드를 중복 없이 **호출**할 수 있게 해주는 함수입니다.

## 다형성이란 무엇이며 코드 재사용에 어떻게 도움이 되나요?

- **다형성**: OOP 원칙으로, 서로 다른 클래스가 같은 메서드 이름을 사용하지만 호출 시 각 클래스가 다르게 구현하는 것을 말합니다. 문법은 다음과 같습니다:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **상속 기반 다형성**: 부모가 메서드를 정의하고, 각 자식 클래스가 이를 자신에게 맞게 변형합니다.

## 이름 맹글링이란 무엇이며 어떻게 작동하나요?

- **이름 맹글링**: Python이 이중 밑줄로 시작하는 속성 이름에 클래스 이름과 밑줄을 접두사로 붙여 내부적으로 이름을 변경하는 과정입니다. 예를 들어 `__attribute`는 `_ClassName__attribute`로 바뀝니다.
- **이름 맹글링의 목적**: 이름 맹글링의 주요 목적은 상속을 사용할 때 우발적인 속성 및 메서드 재정의를 방지하는 것입니다. 다음 코드는 이를 더 쉽게 이해할 수 있게 합니다:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## 추상이란 무엇이며 복잡한 시스템을 어떻게 정리하나요?

- **추상화**: 객체나 시스템의 복잡한 구현 세부사항을 숨기고 필수 기능만 보여주는 프로그래밍 개념입니다. Python과 다른 프로그래밍 언어에서 추상화는 재사용성을 높여 복잡한 시스템을 단순화합니다.
- **추상화 예시**: 일상생활에서 추상화의 좋은 예는 자동차가 엔진이나 브레이크 작동 방식을 몰라도 핸들, 페달, 변속기만 사용하게 하는 것입니다.
- **Python에서 추상화 구현 방법**: 일반 함수와 클래스로 구현 세부사항을 단순한 인터페이스 뒤에 숨겨 추상화를 만들 수 있습니다. 더 공식적인 인터페이스를 위해 Python의 `abc` 모듈은 `ABC` 도우미 클래스와 `@abstractmethod` 데코레이터를 제공합니다. 추상 기본 클래스는 구체적인 하위 클래스가 제공해야 하는 공통 메서드와 속성을 정의합니다.
- **추상 메서드 정의 방법**: 추상 메서드는 `@abstractmethod`로 정의합니다. 모든 추상 메서드를 구체적으로 구현하거나 상속받아야만 클래스 인스턴스를 만들 수 있습니다. 추상 메서드를 구현하지 않은 하위 클래스는 여전히 추상 클래스입니다. 추상 메서드는 기본 구현을 가질 수 있으며, 하위 클래스는 `super()`로 호출할 수 있습니다. `ABC`를 상속하는 것만으로는 인스턴스 생성을 막지 않습니다: `ABC()`와 추상 메서드가 없는 하위 클래스는 인스턴스화할 수 있습니다. 추상화의 기본 구문은 다음과 같습니다:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## 객체 표현

- **`__repr__` 메서드**: 객체의 문자열 표현을 반환하는 특수 메서드입니다. 이상적으로는 그 문자열이 객체를 생성하는 데 사용된 코드처럼 보여야 합니다. 예를 들어, `Employee('Charlie', 'developer')`는 `Employee('Charlie', 'developer')`로 표현되어야 합니다.
- **`repr()` 함수**: 객체에 `repr()`을 호출하면 Python이 내부적으로 해당 객체의 `__repr__` 메서드를 호출합니다. 문자열의 경우 `repr()`은 큰따옴표를 추가하고 필요한 문자를 이스케이프합니다:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **`!r` 변환**: f-string 내에서 표현식 뒤에 `!r`을 추가하면 `repr()`이 적용됩니다. `__repr__`에서 `!r`을 사용하면 값에 큰따옴표나 역슬래시가 포함되어도 표현이 유효하게 유지되며, 수동으로 큰따옴표를 감싸는 것과 다릅니다:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## 도큐스트링과 타입 검사

- **도큐스트링**: 클래스나 함수의 첫 번째 문장으로 문서화를 위해 넣는 문자열입니다. 보통 세 개의 큰따옴표로 감쌉니다:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()`와 `type()`의 차이**: `isinstance(obj, ClassName)`은 `obj`가 `ClassName` 또는 그 하위 클래스의 인스턴스면 `True`를 반환합니다. 이는 전체 상속 체인을 고려하기 때문입니다. 정확히 한 클래스인지 확인하려면 대신 `type(obj)`를 비교하세요:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## 추가 컨텍스트가 있는 사용자 정의 예외

- **예외에 컨텍스트 저장하기**: 사용자 정의 예외는 메시지와 함께 추가 데이터를 받을 수 있습니다. `super().__init__(message)`를 호출하면 내장 `Exception` 클래스가 메시지를 저장하고 표시하며, 추가 데이터는 속성으로 저장할 수 있습니다. 예외를 잡으면 그 속성을 읽어 디버깅에 도움을 줄 수 있습니다:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## 타입 힌트

- **타입 힌트**: 변수, 매개변수, 반환값이 어떤 데이터 타입이어야 하는지 다른 개발자에게 알려주는 선택적 주석입니다. Python은 실행 시 이를 강제하지 않습니다.
- **매개변수와 반환 타입 힌트**: 매개변수 이름 뒤에 콜론을 붙여 매개변수 타입 힌트를 추가하고, 매개변수 목록 뒤에 `-> return_type`을 붙여 반환 타입 힌트를 추가합니다. `__init__`은 반환값이 반드시 `None`이어야 하는 초기화 메서드이므로, 반환 타입 힌트는 `None`입니다:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **사용자 정의 클래스와 리스트 타입**: 사용자 정의 클래스를 타입 힌트로 사용할 수 있으며, `list[ClassName]`은 해당 클래스 객체를 담은 리스트를 의미합니다:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
