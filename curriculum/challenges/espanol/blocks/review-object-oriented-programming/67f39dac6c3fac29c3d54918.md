## ¿Qué es la programación orientada a objetos?

- **Programación orientada a objetos**: Un estilo de programación en el que los desarrolladores tratan todo en su código como un objeto del mundo real. Popularmente se llama OOP. Los cuatro principios clave que te ayudan a organizar y gestionar el código de forma efectiva son **encapsulación**, **herencia**, **polimorfismo** y **abstracción**.
- **Clases**: La estructura para crear objetos. Cada objeto creado a partir de una clase tiene atributos que definen datos y métodos que determinan los comportamientos del objeto.

## ¿Qué es la encapsulación?

- **Encapsulación**: Agrupar los atributos y métodos de un objeto en una sola unidad. Permite ocultar el estado interno del objeto detrás de un conjunto simple de métodos y atributos públicos que actúan como puertas. Detrás de esas puertas hay atributos y métodos privados que controlan cómo cambian los datos y quién puede verlos.
- **Ejemplo de encapsulación**: Si quieres llevar el saldo de una cartera, permitirás depósitos y retiros, pero no querrás que nadie manipule directamente el saldo de la cartera:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **Diferencia entre prefijar atributos con un guion bajo simple y doble**: Prefijar atributos y métodos con un guion bajo simple indica que están destinados para uso interno. Esto es solo una convención, y Python no restringe el acceso a ellos desde afuera de la clase. Prefijar atributos y métodos con un doble guion bajo activa el name mangling, que renombra `__balance` a `_Wallet__balance`. Esto ayuda a evitar colisiones accidentales de nombres en subclases, pero no hace imposible el acceso desde afuera:

```py
print(account._Wallet__balance) # 500
```

## ¿Qué son getters y setters?

- **Getters y setters**: Métodos que te permiten controlar cómo se accede y modifica los atributos de una clase. Recuperas valores con getters y los asignas con setters.
- **Propiedades**: Conectan getters y setters, y permiten el acceso a datos. Ejecutan lógica extra detrás de escena cuando obtienes, asignas o eliminas valores.
- **Por qué usar propiedades en lugar de métodos**: Las propiedades se usan en lugar de métodos para mejorar la legibilidad y tener un código más limpio. Permiten acceder a valores con notación de punto, como atributos regulares, sin paréntesis.
- **Decoradores**: Un decorador es una función que modifica o envuelve otras funciones o clases sin cambiar su código original. Se aplica un decorador colocando `@decorator_name` justo encima de la definición de una función o clase. Por ejemplo, colocar el decorador `@property` sobre un método lo convierte en una propiedad, para que pueda accederse como un atributo mientras internamente llama al método decorado.
- **Crear un getter**: Para crear un getter, usas el decorador `@property`. Aquí tienes un getter que obtiene el radio de un círculo:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **Crear un setter**: Para crear el setter que asignará el radio, debes definir otro método con el mismo nombre y usar `@<property_name>.setter` encima:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Cómo Python maneja getters y setters**: Una vez definidos getters y setters, Python los llama automáticamente internamente cada vez que usas la sintaxis normal de atributos así:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

Dentro del setter, no debes asignar al nombre de la propiedad directamente porque eso causará un `RecursionError`.

- **Deleter**: Después de asignar y obtener un valor con setter y getter, puedes controlar cómo se elimina con un `deleter`. Un deleter ejecuta lógica personalizada cuando usas la sentencia `del` en una propiedad. Para crear un deleter, usas el decorador `@<property_name>.deleter`.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## ¿Qué es la herencia y cómo promueve la reutilización de código?

- **Herencia**: El proceso por el cual una clase hija usa los atributos y métodos de una clase padre. La herencia promueve la reutilización de código, proporciona jerarquías claras y personaliza el comportamiento sin reescribir todo. Para implementar herencia, una clase hija recibe el nombre de una clase padre:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **Herencia simple y múltiple**: Cuando una clase hija hereda propiedades y métodos de un solo padre, como se ve arriba, se llama **herencia simple**. Cuando una clase hija hereda propiedades y métodos de más de un padre, eso es **herencia múltiple**. Aquí está la sintaxis para eso:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **Función `super()`**: Una función que te permite **llamar** un método de una clase padre, cuando una clase tiene una implementación diferente de ese método o extiende el método, sin duplicar código.

## ¿Qué es el polimorfismo y cómo promueve la reutilización de código?

- **Polimorfismo**: El principio de OOP que permite que diferentes clases usen el mismo nombre de método, pero cada clase lo implemente de forma diferente cuando se llama. Aquí está la sintaxis para ello:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **Polimorfismo basado en herencia**: Un padre define un método, y cada clase hija lo adapta a su uso.

## ¿Qué es el name mangling y cómo funciona?

- **Name mangling**: Un proceso en el que Python renombra internamente un atributo prefijado con doble guion bajo añadiendo un guion bajo y el nombre de la clase como prefijo, convirtiendo `__attribute` en `_ClassName__attribute`.
- **Propósito del name mangling**: El propósito principal del name mangling es evitar la sobrescritura accidental de atributos y métodos cuando usas herencia. Aquí tienes un ejemplo de código que lo hace más comprensible:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## ¿Qué es la abstracción y cómo ayuda a mantener organizados sistemas complejos?

- **Abstracción**: Un concepto de programación en el que se ocultan los detalles complejos de implementación de un objeto o sistema y solo se muestran las funcionalidades esenciales. En Python y otros lenguajes, la abstracción simplifica sistemas complejos aumentando la reutilización.
- **Ejemplo de abstracción**: Un buen ejemplo de abstracción en la vida cotidiana es un auto que te permite usar solo el volante, los pedales y la palanca sin saber cómo funciona el motor o los frenos.
- **Cómo Python implementa la abstracción**: Puedes crear abstracciones con funciones y clases ordinarias ocultando detalles de implementación detrás de una interfaz simple. Para interfaces más formales, el módulo `abc` de Python provee la clase auxiliar `ABC` y el decorador `@abstractmethod`. Una clase base abstracta define los métodos y propiedades comunes que se espera que las subclases concretas proporcionen.
- **Cómo se definen los métodos abstractos**: Un método abstracto se define con `@abstractmethod`. Una clase solo puede instanciarse si provee o hereda implementaciones concretas de todos sus métodos abstractos. Una subclase que deja algún método abstracto sin implementar sigue siendo abstracta. Un método abstracto puede tener una implementación predeterminada, que las subclases pueden llamar con `super()`. Heredar solo de `ABC` no bloquea la instanciación: `ABC()` y subclases sin métodos abstractos pueden instanciarse. La sintaxis básica de la abstracción es esta:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## Representaciones de objetos

- **Método `__repr__`**: Un método especial que devuelve una representación en cadena de un objeto. Idealmente, esa cadena se parece al código usado para crear el objeto. Por ejemplo, `Employee('Charlie', 'developer')` debería representarse como `Employee('Charlie', 'developer')`.
- **Función `repr()`**: Cuando llamas a `repr()` sobre un objeto, Python llama internamente al método `__repr__` de ese objeto. Para cadenas, `repr()` añade comillas y escapa cualquier carácter que lo necesite:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **Conversión `!r`**: Dentro de una f-string, añadir `!r` después de una expresión aplica `repr()` a esa expresión. Usar `!r` en `__repr__` mantiene la representación válida cuando un valor contiene comillas o barras invertidas, a diferencia de envolver valores en comillas manualmente:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## Docstrings y comprobaciones de tipo

- **Docstrings**: Un docstring es una cadena colocada como la primera sentencia en una clase o función para documentarla. Normalmente se encierra entre triples comillas dobles:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()` vs. `type()`**: `isinstance(obj, ClassName)` devuelve `True` si `obj` es una instancia de `ClassName` o de cualquiera de sus subclases, porque considera toda la cadena de herencia. Para verificar una clase exacta, compara con `type(obj)` en su lugar:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## Excepciones personalizadas con contexto extra

- **Almacenar contexto en una excepción**: Una excepción personalizada puede aceptar datos extra junto con su mensaje. Llamar a `super().__init__(message)` permite que la clase integrada `Exception` almacene y muestre el mensaje, y luego puedes almacenar los datos extra como un atributo. Cuando capturas la excepción, puedes leer ese atributo para ayudar a depurar:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## Anotaciones de tipo

- **Indicaciones de tipo**: Anotaciones opcionales que indican a otros desarrolladores qué tipo de dato se espera para una variable, parámetro o valor de retorno. Python no las aplica en tiempo de ejecución.
- **Indicaciones de tipo para parámetros y valores de retorno**: Se agrega una indicación de tipo para un parámetro con dos puntos después del nombre del parámetro, y una indicación de tipo de retorno con `-> return_type` después de la lista de parámetros. Como `__init__` es un inicializador cuyo valor de retorno debe ser `None`, su indicación de tipo de retorno es `None`:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **Clases personalizadas y listas como tipos**: Puedes usar tus propias clases como anotaciones de tipo, y `list[ClassName]` especifica una lista que contiene objetos de esa clase:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
