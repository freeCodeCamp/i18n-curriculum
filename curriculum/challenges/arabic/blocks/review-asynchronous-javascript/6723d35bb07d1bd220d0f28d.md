# --description--

- **جافاسكريبت المتزامنة** تُنفذ بشكل تسلسلي وتنتظر انتهاء العملية السابقة قبل الانتقال إلى التالية.
- **جافاسكريبت غير المتزامنة** تسمح بتنفيذ عمليات متعددة في الخلفية دون حظر الخيط الرئيسي.
- **الخيط (Thread)** هو تسلسل تعليمات يمكن تنفيذه بشكل مستقل عن تدفق البرنامج الرئيسي.
- **دوال الاستدعاء الراجع (Callback functions)** هي دوال تُمرر كمعلمات إلى دوال أخرى وتُنفذ بعد إتمام العملية أو نتيجة حدث.

## محرك جافاسكريبت وبيئة التشغيل

- **محرك جافاسكريبت** هو برنامج ينفذ كود جافاسكريبت في متصفح الويب. يعمل كمحول يأخذ الكود الخاص بك، ويحوّله إلى تعليمات يمكن للكمبيوتر فهمها والعمل بناءً عليها.
- V8 هو مثال على محرك جافاسكريبت طورته شركة Google.
- **بيئة تشغيل جافاسكريبت** هي البيئة التي يُنفذ فيها كود جافاسكريبت. تشمل محرك جافاسكريبت الذي يعالج وينفذ الكود، وميزات إضافية مثل متصفح الويب أو Node.js.

## واجهة Fetch API

- تتيح واجهة Fetch API لتطبيقات الويب إجراء طلبات شبكة، عادةً لاسترجاع أو إرسال بيانات إلى الخادم. توفر دالة `fetch()` التي يمكنك استخدامها لإجراء هذه الطلبات.
- يمكنك استرجاع نصوص، صور، صوت، JSON، وأنواع أخرى من البيانات باستخدام Fetch API.

## طرق HTTP لواجهة Fetch API

تدعم Fetch API عدة طرق HTTP للتفاعل مع الخادم. الطرق الأكثر شيوعًا هي:

- **GET**: تُستخدم لاسترجاع البيانات من الخادم. افتراضيًا، تستخدم Fetch API طريقة `GET` لاسترجاع البيانات.

```js
fetch('https://api.example.com/data')
```

لاستخدام البيانات المسترجعة، يجب تحويلها إلى صيغة JSON باستخدام دالة `.json()`:

```js
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => console.log(data))
```

في هذا الكود، تُرجع الدالة `fetch()` وعدًا، ويحوّل معالِج `.then()` الاستجابة المحققة إلى صيغة JSON.

- **POST**: تُستخدم لإرسال بيانات إلى الخادم. تُستخدم طريقة `POST` لإنشاء موارد جديدة على الخادم.

```js
fetch('https://api.example.com/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    name: 'John Doe',
    email: 'john@example.com'
  })
})
```

في هذا المثال، نرسل طلب `POST` لإنشاء مستخدم جديد. حددنا الطريقة كـ `POST`، وضبطنا الرؤوس المناسبة، وضمنّا جسم الطلب بالبيانات التي نريد إرسالها. يجب أن يكون الجسم نصًا، لذا نستخدم `JSON.stringify()` لتحويل كائننا إلى سلسلة JSON.

- **PUT**: تُستخدم لتحديث البيانات على الخادم. تُستخدم طريقة `PUT` لتحديث الموارد الموجودة على الخادم.

```js
fetch('https://api.example.com/users/45', {
  method: 'PUT',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    name: 'John Smith',
    email: 'john@example.com'
  })
})
```

في هذا المثال، نُحدّث المعرف `45` المحدد في نهاية عنوان URL. استخدمنا طريقة `PUT` في الكود وحددنا البيانات في الجسم التي ستُستخدم لتحديث البيانات المحددة.

- **DELETE**: تُستخدم لحذف البيانات على الخادم. تُستخدم طريقة `DELETE` لحذف الموارد على الخادم.

```js
fetch('https://api.example.com/users/45', {
  method: 'DELETE'
})
```

في هذا المثال، نرسل طلب `DELETE` لحذف مستخدم بالمعرف `45`.

## الوعود (Promise) وتسلسل الوعود

- **الوعود** هي كائنات تمثل إتمام أو فشل عملية غير متزامنة وقيمتها الناتجة. تُعرف قيمة الوعد فقط عند إتمام العملية غير المتزامنة.
- إليك مثال لإنشاء وعد بسيط:

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve('Data received successfully');
  }, 2000);
});
```

- تُستخدم طريقة `.then()` في الوعد لتحديد ما يجب أن يحدث عند تحقيق الوعد، بينما تُستخدم `.catch()` لمعالجة أي أخطاء تحدث.
- إليك مثالًا على استخدام `.then()` و `.catch()` مع وعد:

```js
promise
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error(error);
  });
```

في المثال أعلاه، تُستخدم طريقة `.then()` لتسجيل البيانات المستلمة من الوعد، بينما تُستخدم طريقة `.catch()` لتسجيل أي أخطاء تحدث.

- **تسلسل الوعود**: من الميزات القوية للوعود أنه يمكننا تسلسل عدة عمليات غير متزامنة معًا. كل `.then()` يمكن أن تُرجع وعدًا جديدًا، مما يسمح لك بأداء سلسلة من العمليات غير المتزامنة واحدة تلو الأخرى.
- فيما يلي مثال على تسلسل الوعود:

```js
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => {
    console.log(data);
    return fetch('https://api.example.com/other-data');
  })
  .then(response => response.json())
  .then(otherData => {
    console.log(otherData);
  })
  .catch(error => {
    console.error(error);
  });
```

في المثال أعلاه، نقوم أولاً بجلب البيانات من عنوان URL واحد، ثم نجلب بيانات من عنوان URL آخر بناءً على الاستجابة الأولى، وأخيرًا نسجل البيانات الثانية المستلمة.

طريقة `catch` تتولى معالجة أي أخطاء تحدث أثناء العملية. هذا يعني أنك لا تحتاج إلى إضافة معالجة الأخطاء لكل خطوة، مما يبسط كودك كثيرًا.

## استخدام `async/await` للتعامل مع الوعود

`async`/`await` يجعل كتابة وقراءة الكود غير المتزامن أسهل، وهو مبني على أساس الوعود.

- **async**: تُستخدم الكلمة المفتاحية `async` لتعريف دالة غير متزامنة. تُعيد الدالة `async` وعدًا (Promise) يُحلّ بالقيمة التي تُعيدها الدالة `async`.
- **await**: تُستخدم الكلمة المفتاحية `await` داخل دالة `async` لإيقاف تنفيذ الدالة مؤقتًا حتى يُحل الوعد. يمكن استخدامها فقط داخل دالة `async`.
- فيما يلي مثال على استخدام `async/await`:

```js
async function delayedGreeting(name) {
  console.log("A Messenger entered the chat...");
  await new Promise(resolve => setTimeout(resolve, 2000));
  console.log(`Hello, ${name}!`);
}

delayedGreeting("Alice");
console.log("First Printed Message!");
```

في المثال أعلاه، الدالة `delayedGreeting` هي دالة `async` تتوقف لمدة ثانيتين قبل طباعة رسالة الترحيب. تُستخدم الكلمة المفتاحية `await` لإيقاف تنفيذ الدالة حتى يتم حل الـ `Promise`.

- من أكبر مزايا `async/await` هو التعامل مع الأخطاء عبر كتل `try/catch`. إليك مثالًا:

```js
async function fetchData() {
  try {
    const response = await fetch('https://api.example.com/data');
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}

fetchData();
```

في المثال أعلاه، يحتوي كتلة `try` على الكود الذي قد يرجع خطأ، وكتلة `catch` تتولى معالجة الخطأ إذا حدث. هذا يجعل معالجة الأخطاء أكثر وضوحًا وسهولة في القراءة.

## الخاصية `async`

- تخبر الخاصية `async` المتصفح بتحميل ملف السكريبت بشكل غير متزامن مع استمرار تحليل مستند HTML.
- بمجرد تحميل السكريبت، يتوقف تحليل HTML، يُنفذ السكريبت، ثم يستأنف تحليل HTML.
- يجب استخدام `async` للسكريبتات المستقلة التي لا يهم ترتيب تنفيذها.

## الخاصية `defer`

- تقوم الخاصية `defer` أيضًا بتحميل السكريبت بشكل غير متزامن، لكنها تؤجل تنفيذ السكريبت حتى يتم تحليل مستند HTML بالكامل.
- تحافظ سكريبتات `defer` على ترتيب التنفيذ كما تظهر في مستند HTML.

- من المهم ملاحظة أن الخاصيتين `async` و `defer` يتم تجاهلهما للسكريبتات المضمّنة وتعملان فقط مع ملفات السكريبت الخارجية.

- عندما تكون الخاصيتان `async` و `defer` موجودتين معًا، تعطي الخاصية `async` الأولوية.

## واجهة برمجة تطبيقات تحديد الموقع الجغرافي

- توفر واجهة برمجة تطبيقات تحديد الموقع الجغرافي طريقة للمواقع لطلب موقع المستخدم.

- المثال أدناه يوضح طريقة `getCurrentPosition()` من الواجهة، والتي تُستخدم للحصول على الموقع الحالي للمستخدم.

```js
navigator.geolocation.getCurrentPosition(
  (position) => {
    console.log("Latitude: " + position.coords.latitude);
    console.log("Longitude: " + position.coords.longitude);
  },
  (error) => {
    console.log("Error: " + error.message);
  }
);
```

في هذا الكود، نستدعي `getCurrentPosition` ونمرر لها دالة، ستُستدعى عند الحصول على الموقع بنجاح.

كائن `position` يحتوي على معلومات متنوعة، لكننا اخترنا هنا فقط `latitude` و `longitude`.

إذا حدثت مشكلة في الحصول على `position`، فسيتم تسجيل الخطأ في وحدة التحكم.

- من المهم احترام خصوصية المستخدم وطلب موقعه فقط عند الضرورة.
