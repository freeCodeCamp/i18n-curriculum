# --description--

让我们了解你的系统语言和键盘设置如何影响 Bash 和 PostgreSQL 研讨会。

许多编程工具期望命令使用标准的英文键盘字符。在 Bash 和 PostgreSQL 研讨会中，这对于分号（`;`）、引号、斜线以及其他特殊符号尤其重要。

如果你的操作系统或键盘版型使用非英语语言配置，某些字符的行为可能与预期不同。这可能导致输入 SQL 命令或终端命令时出现令人困惑的误差。

为了在完成课程时获得最佳体验，建议暂时切换到英文（美国）键盘版型。如果在 Bash 或 PostgreSQL 中输入诸如 `;` 或 `\` 等符号时命令产生意外字符或语法误差，这尤其有帮助。

GitHub Codespaces 使用你的本地键盘版型，因此更改你电脑上的版型也会影响 Codespaces 中的输入。

在 Windows 上：

1. 打开 **设置** > **时间和语言** > **语言和区域**
2. 如果尚未安装，添加 **English (United States)**
3. 在键盘版型下，选择 **US** 键盘
4. 如有需要，将 US 键盘版型移到列表顶部

在 macOS 上：

1. 打开 **系统设置** > **键盘** > **输入源**
2. 添加 **English (US)** 键盘版型
3. 确保 US 版型被选为活动键盘

在 Ubuntu、Debian 或 Mint 等 Linux 发行（版本）上：

1. 打开系统键盘设置
2. 添加 **English (US)** 键盘版型
3. 如果可能，将其移到键盘版型列表顶部

一些 Linux 系统还允许从终端查看和更改键盘版型。首先，查看你当前的版型：

```bash
setxkbmap -query
```

然后切换到 US 版型：

```bash
setxkbmap us
```

切换版型后，在文本框或终端中测试以下字符：

```md
; : / \ | ' " $ { } [ ] ( )
```

如果符号显示正确，说明你的键盘版型配置可能正确。

一些非英语版型将 `'` 和 `"` 视为死键，意味着它们会等待后续按键而不是立即输入。切换到 US 版型后，这些符号应立即输入。如果某个字符仍未立即出现，说明你的版型尚未完全切换。

如果你使用非 US 的物理键盘版型，如 AZERTY、QWERTZ 或区域性 QWERTY 变体，符号键可能位于不同的物理位置。在这种情况下，切换到 US 版型后，使用操作系统的屏幕键盘或键盘查看器来定位诸如 `;`、`/`、`\`、`|`、`'` 和 `"` 等键。

使用英文（美国）键盘版型有助于确保 Bash 和 PostgreSQL 命令在整个研讨会中按预期运行。

完成研讨会后，你可以切换回原来的键盘版型。
