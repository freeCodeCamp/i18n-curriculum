## Python의 일반적인 오류

- **`SyntaxError`**: 코드가 Python의 구문 규칙을 따르지 않을 때 Python이 발생시키는 오류입니다. 예를 들어, `print("Hello there"` 코드는 닫는 괄호가 빠져 있어서 `SyntaxError: '(' was never closed`라는 메시지와 함께 구문 오류가 발생합니다.
- **`NameError`**: 정의하지 않은 변수나 함수에 접근하려고 하면 Python이 `NameError`를 발생시킵니다. 예를 들어, 코드에 `username` 변수를 먼저 정의하지 않고 `print(username)` 줄을 작성하면 `NameError: name 'username' is not defined`라는 메시지와 함께 이름 오류가 발생합니다.
- **`TypeError`**: 연산이나 함수가 부적절한 타입의 객체에 적용될 때 Python이 발생시키는 오류입니다. 예를 들어, 문자열과 숫자를 더하려고 하면 `TypeError: can only concatenate str (not "int") to str`라는 오류가 발생합니다.
- **`IndexError`**: 리스트나 튜플, 문자열 같은 수열에서 존재하지 않는 인덱스에 접근하면 `IndexError`가 발생합니다. 예를 들어, `Hello world` 문자열에서 마지막 문자의 인덱스는 `10`입니다. 만약 `greet = "hello world"; print(greet[11])`처럼 접근하면 `IndexError: string index out of range`라는 메시지와 함께 오류가 발생합니다.
- **`AttributeError`**: 해당 타입의 객체에 존재하지 않는 메서드나 속성을 사용하려고 할 때 Python이 발생시키는 오류입니다. 예를 들어, `"hello".append("!")`처럼 문자열에서 `.append()`를 호출하면 `AttributeError: 'str' object has no attribute 'append'`라는 메시지와 함께 오류가 발생합니다.

## Python에서 좋은 디버깅 기법

- **`print` 함수 사용하기**: 디버깅할 때 코드 여러 지점에 `print()` 문을 삽입하면 변수 값과 코드 흐름을 확인하는 데 도움이 됩니다.
- **Python 내장 디버거(`pdb`) 사용하기**: Python 표준 라이브러리의 일부인 `pdb` 모듈을 사용해 디버깅할 수 있습니다. `pdb.set_trace()`를 호출하면 실행이 일시 중지되고 대화형 프롬프트가 열립니다. `help`를 입력하면 명령 목록을 볼 수 있고, `whatis`로 표현식의 타입을 확인하며, `continue`(또는 별칭 `cont`, `c`)로 프로그램 실행을 재개할 수 있습니다.
- **IDE 디버깅 도구 활용하기**: PyCharm, VS Code 같은 통합 개발 환경(IDE)과 코드 편집기는 시각적 디버깅 도구를 제공합니다. 예를 들어 VS Code는 다음 기능을 제공합니다:
  - **중단점**: 편집기 거터를 클릭해 실행을 일시 중지할 중단점(빨간 점으로 표시)을 설정하세요.
  - **변수 검사 및 디버그 콘솔**: 변수 위에 마우스를 올리거나 변수 패널을 확인해 현재 값을 보고, 디버그 콘솔에서 표현식을 대화형으로 평가할 수 있습니다.
  - **단계별 실행 제어**:
    - **계속하기 (<kbd>F5</kbd>)**: 다음 중단점까지 실행을 재개합니다.
    - **한 줄씩 실행하기 (<kbd>F10</kbd>)**: 현재 줄을 실행하고 함수 호출 내부로 들어가지 않고 다음 줄로 이동합니다.
    - **함수 내부로 들어가기 (<kbd>F11</kbd>)**: 호출된 함수 내부로 들어가 그 줄들을 단계별로 실행합니다.
    - **함수 밖으로 나오기 (<kbd>Shift</kbd> + <kbd>F11</kbd>)**: 현재 함수 실행을 마치고 호출한 곳으로 돌아갑니다.

## 예외 처리

- **`try...except`**: 예외가 발생할 수 있는 코드 블록을 실행할 때 사용합니다. `try` 블록은 오류가 발생할 것으로 예상되는 부분이고, `except` 블록은 지정한 예외가 발생했을 때 실행됩니다. 예를 들어 다음과 같습니다:

  ```py
  try:
    print(22 / 0)
  except ZeroDivisionError:
    print('You can\'t divide by zero!')
    # You can't divide by zero!
  ```

  여러 `except` 블록을 연결해 다양한 예외를 처리할 수도 있습니다:

  ```py
  try:
    number = int(input('Enter a number: '))
    print(22 / number)
  except ZeroDivisionError:
    print('You cannot divide by zero!')
    # You cannot divide by zero! prints when you enter 0
  except ValueError:
    print('Please enter a valid number!')
    # Please enter a valid number! prints when you don't enter an integer
  ```

  여러 예외 유형을 하나의 `except` 절에서 튜플로 묶어 처리할 수도 있습니다:

  ```py
  try:
    number = int(input('Enter a number: '))
    result = 10 / number
  except (ValueError, ZeroDivisionError) as e:
    print(f'Error occurred: {e}')
  ```

- **`else` 와 `finally`**: 이 블록들은 `try...except`를 확장합니다. 예외가 없으면 `else` 블록이 실행되고, `finally` 블록은 오류 여부와 상관없이 항상 실행됩니다.

  ```py
  try:
    result = 100 / 4
  except ZeroDivisionError:
    print('You cannot divide by zero!') # This will not run
  else:
    print(f'Result is {result}') # Result is 25.0
  finally:
    print('Execution complete!') # Execution complete!
  ```

- **예외 객체**: 예외 자체에 접근해 디버깅과 직접적인 오류 메시지 출력을 할 수 있습니다. 예외 객체에 접근하려면 `as` 키워드를 사용합니다. 예:

  ```py
  try:
      value = int('This will raise an error')
  except ValueError as e:
      print(f'Caught an error: {e}')
      # Caught an error: invalid literal for int() with base 10: 'This will raise an error'
  ```

- **`raise` 문**: 이 문은 수동으로 예외를 발생시키도록 합니다. 특정 조건이 충족될 때 예외를 발생시키는 데 사용할 수 있습니다:

  ```py
  def divide(a, b):
      if b == 0:
          raise ZeroDivisionError('You cannot divide by zero')
      return a / b
  ```

  `except` 블록 안에서 인수 없이 `raise`를 사용하면 현재 처리 중인 예외를 다시 발생시킵니다. 이렇게 하면 오류를 기록하거나 정리 작업을 하면서도 예외가 호출 스택 위로 전달되도록 할 수 있습니다:

  ```py
  def process_data(data):
      try:
          result = int(data)
          return result * 2
      except ValueError:
          print('Logging: Invalid data received')
          raise
  ```

- **`assert` 문**: `assert` 문은 디버깅 중 가정을 확인하고 조건이 거짓일 때 `AssertionError`를 발생시킵니다. Python은 최적화 모드(`-O`)로 실행할 때 어서션을 제거하므로, 항상 실행되어야 하는 중요한 입력 유효성 검사에는 어서션을 사용하지 마세요. 필요한 검사는 명시적인 조건과 `raise`를 사용해 처리하세요.

## 예외 신호 보내기

- **사용자 정의 예외**: `raise` 문은 `Exception`을 서브클래싱하여 자신만의 사용자 정의 예외를 만들 때도 유용합니다. 이를 통해 도메인별 논리와 메시지를 가진 오류를 발생시킬 수 있습니다:

  ```py
  class InvalidCredentialsError(Exception):
      def __init__(self, message="Invalid username or password"):
          self.message = message
          super().__init__(self.message)

  def login(username, password):
      stored_username = "admin"
      stored_password = "password123"
      
      if username != stored_username or password != stored_password:
          raise InvalidCredentialsError()
      
      return f"Welcome, {username}!"
  ```

  다음은 `InvalidCredentialsError` 예외와 함께 `login` 함수를 사용하는 방법입니다:

  ```py
  # failed login attempt
  try:
      message = login("user", "wrongpassword")
  except InvalidCredentialsError as e:
      print(f"Login failed: {e}")
  else:
      print(message)

  # successful login attempt
  try:
      message = login("admin", "password123")
  except InvalidCredentialsError as e:
      # This block is not executed because the login was successful
      print(f"Login failed: {e}")
  else:
      # The else block runs if the 'try' block completes without an exception
      print(message)
  ```

- **예외 체이닝**: `raise` 문은 `from` 키워드와 함께 사용하여 예외를 체이닝할 수 있습니다. `from None`을 사용하면 표시되는 추적에서 원래 예외 컨텍스트가 숨겨지고, `from e`를 사용하면 원래 예외를 명시적으로 원인으로 기록합니다:

  ```py
  def parse_config(filename):
      try:
          with open(filename, 'r') as file:
              data = file.read()
              return int(data)
      except FileNotFoundError:
          raise ValueError('Configuration file is missing') from None
      except ValueError as e:
          raise ValueError('Invalid configuration format') from e

  config = parse_config('config.txt')
  ```
