# --description--

Так само, як крапка (`.`) може позначати кінець речення в англійській мові, крапка з комою (`;`) може використовуватися для позначення кінця інструкції в JavaScript. Однак інструкції не обов’язково збігаються з лініями вихідного коду. Інструкція може охоплювати кілька ліній, а одна лінія може містити більше ніж одну інструкцію.

Наприклад:

```js
let variableOne = 5;
let variableTwo = 10;
```

У цьому коді крапки з комою явно позначають кінець кожної інструкції. У JavaScript також є автоматичне додавання крапок з комою (Automatic Semicolon Insertion, ASI), що дозволяє цим оголошенням залишатися дійсними без явних крапок з комою:

```js
let variableOne = 5
let variableTwo = 10
```

У цьому прикладі ASI дозволяє JavaScript розглядати кожне оголошення як окрему інструкцію, навіть якщо крапок з комою немає. Однак ASI не просто вставляє крапку з комою після кожного переносу рядка.

Наприклад, перенос рядка після інструкції `return` може спричинити несподівану поведінку:

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

Тут ASI вставляє крапку з комою після `return`, тому функція повертає `undefined` замість об’єкта. Запис об’єкта в тому ж рядку уникає такої поведінки:

```js
function getValue() {
  return {
    value: 42
  };
}
```

Це показує, чому переноси рядків і межі інструкцій не завжди збігаються.

Крапки з комою також корисні, коли перенос рядка міг би дозволити двом частинам коду інтерпретуватися як один вираз. Вираз негайно викликаної функції (IIFE) — це функція, яка запускається одразу після визначення. Один зі способів створити IIFE — обгорнути анонімну функцію, тобто функцію без імені, в круглі дужки і додати `()` в кінці для її виклику. IIFE може спричинити проблему, якщо попередня інструкція не закінчується крапкою з комою:

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

Тут JavaScript не вставляє крапку з комою після оголошення рядка, бо наступна `(` може продовжити вираз ініціалізації. JavaScript аналізує ініціалізатор як виклик рядка `"Hello"`, де функція є аргументом. Це викликає `TypeError` до того, як IIFE встигне запуститися. Додавання крапки з комою завершує оголошення перед IIFE:

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

Явна крапка з комою розділяє оголошення змінної та IIFE як окремі інструкції.

Крапки з комою використовуються у багатьох мовах програмування, включно з C, C++ та Java. Їхні точні правила відрізняються між мовами, але зазвичай вони допомагають позначати, де закінчується інструкція.

Компілятор перетворює вихідний код у іншу форму, наприклад машинний код, байткод або проміжне представлення, залежно від мови та компілятора. Компіляція не обов’язково створює самостійний виконуваний файл.

Послідовне використання крапок з комою може зробити межі інструкцій чіткішими та полегшити читання й підтримку коду.
