# --description--

英語でピリオド（`.`）が文の終わりを示すように、JavaScriptではセミコロン（`;`）が文の終わりを示すために使われます。ただし、文は必ずしもソースコードの行と同じではありません。文は複数行にまたがることもあり、1行に複数の文が含まれることもあります。

例えば：

```js
let variableOne = 5;
let variableTwo = 10;
```

このコードでは、セミコロンが各文の終わりを明示しています。JavaScriptには自動セミコロン挿入（ASI）もあり、これにより明示的なセミコロンがなくてもこれらの宣言は有効なままです：

```js
let variableOne = 5
let variableTwo = 10
```

この例では、ASIによりセミコロンがなくてもJavaScriptは各宣言を別々の文として扱います。ただし、ASIは単にすべての改行の後にセミコロンを挿入するわけではありません。

例えば、`return`文の後の改行は予期しない動作を引き起こすことがあります：

```js
function getValue() {
  return
  {
    value: 42
  };
}
```

ここでは、ASIが`return`の後にセミコロンを挿入するため、関数はオブジェクトではなく`undefined`を返します。同じ行にオブジェクトを書くことでこの動作を避けられます：

```js
function getValue() {
  return {
    value: 42
  };
}
```

これは改行と文の境界が必ずしも同じではない理由を示しています。

セミコロンは、改行によって2つのコードが1つの式として解釈されてしまう場合にも役立ちます。即時実行関数式（IIFE）は定義されるとすぐに実行される関数です。IIFEを作る方法の一つは、名前のない関数である無名関数を丸括弧で囲み、最後に`()`を付けて呼び出すことです。前の文がセミコロンで終わっていないと、IIFEは問題を引き起こすことがあります：

```js
const message = "Hello"

(function () {
  console.log(message);
})()
```

ここでは、後続の`(`が初期化式を続けられるため、JavaScriptは文字列宣言の後にセミコロンを挿入しません。JavaScriptは初期化式を文字列`"Hello"`への呼び出しとしてパースし、関数式を引数として扱います。これによりIIFEが実行される前に`TypeError`がスローされます。セミコロンを追加するとIIFEの前に宣言が終了します：

```js
const message = "Hello";

(function () {
  console.log(message);
})()
```

明示的なセミコロンにより、変数宣言とIIFEが別々の文として保たれます。

セミコロンはC、C++、Javaなど多くのプログラミング言語で使われています。ルールは言語によって異なりますが、一般的に文の終わりを示すのに役立ちます。

コンパイラはソースコードを、言語やコンパイラによって機械語、バイトコード、中間表現など別の形式に変換します。コンパイルは必ずしも単独の実行可能ファイルを生成するわけではありません。

セミコロンを一貫して使うことで文の境界が明確になり、コードが読みやすく保守しやすくなります。
