## Was ist objektorientierte Programmierung?

- **Objektorientierte Programmierung**: Ein Programmierstil, bei dem Entwickler alles in ihrem Code wie ein reales Objekt behandeln. Es wird oft OOP genannt. Die vier wichtigsten Grundsätze, die Ihnen helfen, Code effektiv zu organisieren und zu verwalten, sind **Kapselung**, **Vererbung**, **Polymorphismus** und **Abstraktion**.
- **Klassen**: Die Vorlage zur Erstellung von Objekten. Jedes einzelne Objekt, das aus einer Klasse erstellt wird, hat Attribute, die Daten definieren, und Methoden, die das Verhalten des Objekts bestimmen.

## Was ist Kapselung?

- **Kapselung**: Das Bündeln der Attribute und Methoden eines Objekts zu einer einzigen Einheit. Sie ermöglicht es, den internen Zustand des Objekts hinter einer einfachen Menge öffentlicher Methoden und Attribute zu verbergen, die wie Türen fungieren. Hinter diesen Türen befinden sich private Attribute und Methoden, die steuern, wie sich die Daten ändern und wer sie sehen kann.
- **Beispiel für Kapselung**: Wenn Sie den Kontostand einer Brieftasche verfolgen möchten, erlauben Sie Einzahlungen und Abhebungen, aber niemand soll den Kontostand selbst manipulieren können:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **Unterschied zwischen dem Präfix von Attributen mit einfachem und doppeltem Unterstrich**: Das Präfix von Attributen und Methoden mit einem einfachen Unterstrich signalisiert, dass sie für den internen Gebrauch bestimmt sind. Dies ist nur eine Konvention, und Python schränkt den Zugriff von außerhalb der Klasse nicht ein. Das Präfix von Attributen und Methoden mit einem doppelten Unterstrich löst Name Mangling aus, das `__balance` in `_Wallet__balance` umbenennt. Dies hilft, versehentliche Namenskollisionen in Unterklassen zu vermeiden, macht den Zugriff von außen aber nicht unmöglich:

```py
print(account._Wallet__balance) # 500
```

## Was sind Getter und Setter?

- **Getter und Setter**: Methoden, mit denen Sie steuern können, wie auf die Attribute einer Klasse zugegriffen und wie sie geändert werden. Sie rufen Werte mit Gettern ab und setzen Werte mit Settern.
- **Eigenschaften**: Sie verbinden Getter und Setter und ermöglichen den Zugriff auf Daten. Sie führen hinter den Kulissen zusätzliche Logik aus, wenn Sie Werte abrufen, setzen oder löschen.
- **Warum Eigenschaften statt Methoden**: Eigenschaften werden anstelle von Methoden verwendet, um die Lesbarkeit zu verbessern und den Code sauberer zu machen. Sie ermöglichen den Zugriff auf Werte mit Punktnotation, wie bei regulären Attributen, ohne runde Klammern.
- **Dekoratoren**: Ein Dekorator ist eine Funktion, die andere Funktionen oder Klassen modifiziert oder umhüllt, ohne deren ursprünglichen Code zu ändern. Sie wenden einen Dekorator an, indem Sie `@decorator_name` direkt über eine Funktions- oder Klassendefinition setzen. Zum Beispiel verwandelt der `@property`-Dekorator eine Methode in eine Eigenschaft, sodass sie wie ein Attribut aufgerufen werden kann, während intern die dekorierte Methode ausgeführt wird.
- **Erstellen eines Getters**: Um einen Getter zu erstellen, verwenden Sie den `@property`-Dekorator. Hier ist ein Getter, der den Radius eines Kreises abruft:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **Einen Setter erstellen**: Um den Setter zu erstellen, der den Radius setzt, müssen Sie eine weitere Methode mit demselben Namen definieren und `@<property_name>.setter` darüber verwenden:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Wie Python Getter und Setter behandelt**: Sobald Sie Getter und Setter definiert haben, ruft Python sie automatisch im Hintergrund auf, wann immer Sie die normale Attributsyntax auf diese Weise verwenden:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

Innerhalb des Setters sollten Sie nicht dem Eigenschaftsnamen selbst einen Wert zuweisen, da dies zu einem `RecursionError` führt.

- **Deleter**: Nach dem Setzen und Abrufen eines Werts mit Setter und Getter können Sie steuern, wie er mit einem `deleter` gelöscht wird. Ein Deleter führt benutzerdefinierte Logik aus, wenn Sie die `del`-Anweisung für eine Property verwenden. Um einen Deleter zu erstellen, verwenden Sie den `@<property_name>.deleter`-Decorator.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## Was ist Vererbung und wie fördert sie die Wiederverwendung von Code?

- **Vererbung**: Der Prozess, bei dem eine Kindklasse die Attribute und Methoden einer Elternklasse verwendet. Vererbung fördert die Wiederverwendung von Code, schafft klare Hierarchien und ermöglicht die Anpassung des Verhaltens, ohne alles neu schreiben zu müssen. Um Vererbung zu implementieren, nimmt eine Kindklasse den Namen einer Elternklasse an:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **Einfache und Mehrfachvererbung**: Wenn eine Kindklasse Eigenschaften und Methoden von nur einer Elternklasse erbt, wie oben gezeigt, nennt man das **einfache Vererbung**. Wenn eine Kindklasse Eigenschaften und Methoden von mehr als einer Elternklasse erbt, spricht man von **Mehrfachvererbung**. Hier ist die Syntax dafür:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **`super()`-Funktion**: Eine Funktion, mit der Sie eine Methode einer Elternklasse **aufrufen** können, wenn eine Klasse eine andere Implementierung dieser Methode hat oder die Methode erweitert, ohne Code zu duplizieren.

## Was ist Polymorphismus und wie fördert er die Wiederverwendung von Code?

- **Polymorphismus**: Das OOP-Prinzip, das es verschiedenen Klassen erlaubt, denselben Methodennamen zu verwenden, wobei jede Klasse die Methode unterschiedlich implementiert, wenn sie aufgerufen wird. Hier ist die Syntax dafür:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **Vererbungsbasierter Polymorphismus**: Eine Elternklasse definiert eine Methode, und jede Kindklasse passt sie für ihre Zwecke an.

## Was ist Name Mangling und wie funktioniert es?

- **Name Mangling**: Ein Prozess, bei dem Python intern ein Attribut mit doppeltem Unterstrich umbenennt, indem es einen Unterstrich und den Klassennamen als Präfix hinzufügt, wodurch `__attribute` zu `_ClassName__attribute` wird.
- **Zweck des Name Mangling**: Der Hauptzweck des Name Mangling ist es, versehentliches Überschreiben von Attributen und Methoden bei Verwendung von Vererbung zu verhindern. Hier ist ein Codebeispiel, das das verständlicher macht:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## Was ist Abstraktion und wie hilft sie, komplexe Systeme organisiert zu halten?

- **Abstraktion**: Ein Programmierkonzept, bei dem komplexe Implementierungsdetails eines Objekts oder Systems verborgen bleiben und nur die wesentlichen Funktionen gezeigt werden. In Python und anderen Programmiersprachen vereinfacht Abstraktion komplexe Systeme durch erhöhte Wiederverwendbarkeit.
- **Beispiel für Abstraktion**: Ein gutes Beispiel für Abstraktion im Alltag ist ein Auto, bei dem Sie nur das Lenkrad, die Pedale und den Schalthebel benutzen, ohne zu wissen, wie der Motor oder die Bremsen funktionieren.
- **Wie Python Abstraktion implementiert**: Sie können Abstraktionen mit gewöhnlichen Funktionen und Klassen erstellen, indem Sie Implementierungsdetails hinter einer einfachen Schnittstelle verbergen. Für formellere Schnittstellen bietet Pythons `abc`-Modul die Hilfsklasse `ABC` und den Dekorator `@abstractmethod`. Eine abstrakte Basisklasse definiert die gemeinsamen Methoden und Eigenschaften, die konkrete Unterklassen bereitstellen sollen.
- **Wie abstrakte Methoden definiert werden**: Eine abstrakte Methode wird mit `@abstractmethod` definiert. Eine Klasse kann nur instanziiert werden, wenn sie konkrete Implementierungen aller abstrakten Methoden bereitstellt oder erbt. Eine Unterklasse, die eine abstrakte Methode nicht implementiert, bleibt abstrakt. Eine abstrakte Methode kann dennoch eine Standardimplementierung haben, die Unterklassen mit `super()` aufrufen können. Das Erben von `ABC` allein verhindert keine Instanziierung: `ABC()` und Unterklassen ohne abstrakte Methoden können instanziiert werden. Die grundlegende Syntax der Abstraktion sieht so aus:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## Objektrepräsentationen

- **`__repr__`-Methode**: Eine spezielle Methode, die eine String-Darstellung eines Objekts zurückgibt. Idealerweise sieht dieser String wie der Code aus, der das Objekt erstellt hat. Zum Beispiel sollte `Employee('Charlie', 'developer')` als `Employee('Charlie', 'developer')` dargestellt werden.
- **`repr()`-Funktion**: Wenn Sie `repr()` auf ein Objekt aufrufen, ruft Python intern die `__repr__`-Methode dieses Objekts auf. Für Strings fügt `repr()` Anführungszeichen hinzu und maskiert alle erforderlichen Zeichen:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **`!r`-Konvertierung**: Innerhalb eines f-Strings wendet das Hinzufügen von `!r` nach einem Ausdruck `repr()` darauf an. Die Verwendung von `!r` in `__repr__` hält die Darstellung gültig, wenn ein Wert Anführungszeichen oder Backslashes enthält, im Gegensatz zum manuellen Einfügen von Anführungszeichen:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## Docstrings und Typprüfungen

- **Docstrings**: Ein Docstring ist ein String, der als erste Anweisung in einer Klasse oder Funktion steht, um diese zu dokumentieren. Docstrings sind typischerweise in dreifache doppelte Anführungszeichen eingeschlossen:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()` vs. `type()`**: `isinstance(obj, ClassName)` gibt `True` zurück, wenn `obj` eine Instanz von `ClassName` oder einer seiner Unterklassen ist, da die gesamte Vererbungskette berücksichtigt wird. Um genau eine Klasse zu prüfen, vergleichen Sie stattdessen `type(obj)`:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## Benutzerdefinierte Ausnahmen mit zusätzlichem Kontext

- **Kontext in einer Ausnahme speichern**: Eine benutzerdefinierte Ausnahme kann neben ihrer Nachricht zusätzliche Daten akzeptieren. Der Aufruf von `super().__init__(message)` ermöglicht es der eingebauten `Exception`-Klasse, die Nachricht zu speichern und anzuzeigen, und Sie können dann die zusätzlichen Daten als Attribut speichern. Wenn Sie die Ausnahme abfangen, können Sie dieses Attribut lesen, um beim Debuggen zu helfen:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## Typ-Hinweise

- **Typ-Hinweise**: Optionale Annotationen, die anderen Entwicklern signalisieren, welchen Datentyp eine Variable, ein Parameter oder ein Rückgabewert haben soll. Python erzwingt sie nicht zur Laufzeit.
- **Parameter- und Rückgabetyp-Hinweise**: Sie fügen einen Parameter-Typ-Hinweis mit einem Doppelpunkt nach dem Parameternamen hinzu und einen Rückgabetyp-Hinweis mit `-> return_type` nach der Parameterliste. Da `__init__` ein Initialisierer ist, dessen Rückgabewert `None` sein muss, ist sein Rückgabetyp-Hinweis `None`:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **Benutzerdefinierte Klassen und Listen als Typen**: Sie können Ihre eigenen Klassen als Typ-Hinweise verwenden, und `list[ClassName]` gibt eine Liste an, die Objekte dieser Klasse enthält:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
