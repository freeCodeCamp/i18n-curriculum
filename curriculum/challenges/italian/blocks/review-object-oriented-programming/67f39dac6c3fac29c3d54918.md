## Che cos'è la programmazione orientata agli oggetti?

- **Programmazione orientata agli oggetti**: Uno stile di programmazione in cui gli sviluppatori trattano tutto nel loro codice come un oggetto del mondo reale. È comunemente chiamata OOP. I quattro principi chiave che ti aiutano a organizzare e gestire il codice in modo efficace sono **incapsulamento**, **ereditarietà**, **polimorfismo** e **astrazione**.
- **Classi**: Il modello per creare oggetti. Ogni singolo oggetto creato da una classe ha attributi che definiscono i dati e metodi che determinano i comportamenti dell'oggetto.

## Che cos'è l'incapsulamento?

- **Incapsulamento**: Raggruppare gli attributi e i metodi di un oggetto in un’unità singola. Ti permette di nascondere lo stato interno dell’oggetto dietro un semplice insieme di metodi e attributi pubblici che funzionano come porte. Dietro quelle porte ci sono attributi e metodi privati che controllano come i dati cambiano e chi può vederli.
- **Esempio di incapsulamento**: Se vuoi tenere traccia del saldo di un portafoglio, permetterai depositi e prelievi, ma non vorrai che nessuno possa manomettere direttamente il saldo del portafoglio:

```py
class Wallet:
   def __init__(self, balance):
       self.__balance = balance # Private attribute

   def deposit(self, amount):
       if amount > 0:
           self.__balance += amount # Add to the balance safely

   def withdraw(self, amount):
       if 0 < amount <= self.__balance:
           self.__balance -= amount # Remove from the balance safely

account = Wallet(500)
print(account.__balance) # AttributeError: 'Wallet' object has no attribute '__balance'
```

- **Differenza tra prefissare gli attributi con un underscore singolo e doppio**: Prefissare attributi e metodi con un underscore singolo segnala che sono destinati all'uso interno. Questa è solo una convenzione, e Python non limita l'accesso a essi dall'esterno della classe. Prefissare attributi e metodi con un doppio underscore attiva il name mangling, che rinomina `__balance` in `_Wallet__balance`. Questo aiuta a evitare collisioni accidentali di nomi nelle sottoclassi, ma non rende impossibile l'accesso esterno:

```py
print(account._Wallet__balance) # 500
```

## Cosa sono getter e setter?

- **Getter e setter**: Metodi che ti permettono di controllare come gli attributi di una classe vengono consultati e modificati. Recuperi i valori con i getter e li imposti con i setter.
- **Proprietà**: Collegano getter e setter e permettono di consultare i dati. Eseguono una logica aggiuntiva dietro le quinte quando ottieni, imposti o elimini valori.
- **Perché usare le proprietà invece dei metodi**: Le proprietà si usano invece dei metodi per una migliore leggibilità e un codice più pulito. Permettono di consultare i valori con la notazione a punto, come normali attributi, senza parentesi.
- **Decorator**: Un decorator è una funzione che modifica o avvolge altre funzioni o classi senza cambiare il loro codice originale. Applichi un decorator posizionando `@decorator_name` direttamente sopra la definizione di una funzione o classe. Per esempio, posizionare il decorator `@property` sopra un metodo lo trasforma in una proprietà, così può essere consultato come un attributo mentre internamente chiama il metodo decorato.
- **Creare un getter**: Per creare un getter, usi il decorator `@property`. Ecco un getter che ottiene il raggio di un cerchio:

```py
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self): # A getter to get the radius
        return self._radius
  
    @property
    def area(self):  # A getter to calculate area
        return 3.14 * (self._radius ** 2)

my_circle = Circle(3)

print(my_circle.radius) # 3
print(my_circle.area) # 28.26
```

- **Creare un setter**: Per creare il setter che imposta il raggio, devi definire un altro metodo con lo stesso nome e usare `@<property_name>.setter` sopra di esso:

```py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):  # A getter to get the radius
        return self._radius

    @radius.setter
    def radius(self, value):  # A setter to set the radius
        if value <= 0:
            raise ValueError('Radius must be positive')
        self._radius = value

my_circle = Circle(3)
print('Initial radius:', my_circle.radius) # Initial radius: 3

my_circle.radius = 8
print('After modifying the radius:', my_circle.radius) # After modifying the radius: 8
```

- **Come Python gestisce getter e setter**: Una volta definiti getter e setter, Python li chiama automaticamente sotto il cofano ogni volta che usi la sintassi normale degli attributi in questo modo:

```py
my_circle.radius # This will call the getter
my_circle.radius = 4 # This will call the setter
```

Dentro il setter, non dovresti assegnare al nome della proprietà stessa perché questo causerebbe un `RecursionError`.

- **Deleter**: Dopo aver impostato e ottenuto un valore con setter e getter, puoi controllare come viene eliminato con un `deleter`. Un deleter esegue logica personalizzata quando usi l’istruzione `del` su una proprietà. Per creare un deleter, usi il decoratore `@<property_name>.deleter`.

```py
  # Deleter
    @radius.deleter
    def radius(self):
        print("Deleting radius...")
        del self._radius
```

## Cos’è l’ereditarietà e come favorisce il riuso del codice?

- **Ereditarietà**: Il processo con cui una classe figlia usa gli attributi e i metodi di una classe genitore. L’ereditarietà favorisce il riuso del codice, fornisce gerarchie chiare e personalizza il comportamento senza riscrivere tutto. Per implementare l’ereditarietà, una classe figlia prende il nome di una classe genitore:

```py
class Parent:
    # Parent attributes and methods

class Child(Parent):
    # Child inherits, extends, and/or overrides where necessary
```

- **Ereditarietà singola e multipla**: Quando una classe figlia eredita proprietà e metodi da un solo genitore, come vedi sopra, si chiama **ereditarietà singola**. Quando una classe figlia eredita proprietà e metodi da più genitori, si chiama **ereditarietà multipla**. Ecco la sintassi per questo:

```py
class Parent:
    # Attributes and methods for Parent

class Child:
    # Attributes and methods for Child

class GrandChild(Parent, Child):
    # GrandChild inherits from both Parent and Child
    # GrandChild can combine or override behavior from each
```

- **Funzione `super()`**: Una funzione che ti permette di **chiamare** un metodo di una classe genitore, quando una classe ha una diversa implementazione di quel metodo o lo estende, senza duplicare codice.

## Cos’è il polimorfismo e come favorisce il riuso del codice?

- **Polimorfismo**: Il principio OOP che permette a classi diverse di usare lo stesso nome di metodo, ma ogni classe lo implementa in modo diverso quando viene chiamato. Ecco la sintassi per questo:

```py
class A:
   def action(self): ...

class B:
   def action(self): ...

class C:
   def action(self): ...

Class().method()  # Works for A, B, or C
```

- **Polimorfismo basato sull’ereditarietà**: Un genitore definisce un metodo, e ogni classe figlia lo adatta al proprio uso.

## Cos'è il name mangling e come funziona?

- **Name mangling**: Un processo in cui Python rinomina internamente un attributo prefissato con un doppio underscore aggiungendo un underscore e il nome della classe come prefisso, trasformando `__attribute` in `_ClassName__attribute`.
- **Scopo del name mangling**: Lo scopo principale del name mangling è prevenire la sovrascrittura accidentale di attributi e metodi quando si usa l'ereditarietà. Ecco un esempio di codice che rende questo più comprensibile:

```py
class Parent:
    def __init__(self):
        self.__data = 'Parent data'

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = 'Child data'

c = Child()
print(c.__dict__) # {'_Parent__data': 'Parent data', '_Child__data': 'Child data'}
```

## Cos’è l’astrazione e come aiuta a mantenere organizzati sistemi complessi?

- **Astrazione**: Un concetto di programmazione in cui i dettagli complessi di implementazione di un oggetto o sistema sono nascosti e vengono mostrati solo gli aspetti essenziali. In Python e in altri linguaggi di programmazione, l'astrazione semplifica sistemi complessi aumentando la riusabilità.
- **Esempio di astrazione**: Un buon esempio di astrazione nella vita quotidiana è un'auto che ti permette di usare solo il volante, i pedali e il cambio senza sapere come funzionano il motore o i freni.
- **Come Python implementa l'astrazione**: Puoi creare astrazioni con funzioni e classi ordinarie nascondendo i dettagli di implementazione dietro un'interfaccia semplice. Per interfacce più formali, il modulo `abc` di Python fornisce la classe helper `ABC` e il decorator `@abstractmethod`. Una classe base astratta definisce i metodi e le proprietà comuni che le sottoclassi concrete devono fornire.
- **Come si definiscono i metodi astratti**: Un metodo astratto si definisce con `@abstractmethod`. Una classe può essere istanziata solo se fornisce o eredita implementazioni concrete di tutti i suoi metodi astratti. Una sottoclasse che lascia un metodo astratto non implementato rimane astratta. Un metodo astratto può comunque avere un'implementazione predefinita, che le sottoclassi possono chiamare con `super()`. Ereditare da `ABC` da solo non blocca l'istanza: `ABC()` e sottoclassi senza metodi astratti possono essere istanziate. La sintassi base dell'astrazione è questa:

```py
from abc import ABC, abstractmethod

# Define an abstract base class
class AbstractClass(ABC):
    @abstractmethod
    def abstract_method(self):
        pass

# Concrete subclass that implements the abstract method
class ConcreteClassOne(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassOne')

# Another concrete subclass
class ConcreteClassTwo(AbstractClass):
    def abstract_method(self):
        print('Implementation in ConcreteClassTwo')

AbstractClass() # TypeError
ConcreteClassOne().abstract_method() # Implementation in ConcreteClassOne
```

## Rappresentazioni degli oggetti

- **Metodo `__repr__`**: Un metodo speciale che restituisce una rappresentazione stringa di un oggetto. Idealmente, quella stringa dovrebbe assomigliare al codice usato per creare l'oggetto. Per esempio, `Employee('Charlie', 'developer')` dovrebbe essere rappresentato come `Employee('Charlie', 'developer')`.
- **Funzione `repr()`**: Quando chiami `repr()` su un oggetto, Python chiama internamente il metodo `__repr__` di quell'oggetto. Per le stringhe, `repr()` aggiunge virgolette e fa escape di eventuali caratteri necessari:

```py
print(repr('Charlie')) # 'Charlie'
print(repr("O'Reilly")) # "O'Reilly"
print('C:\\new', repr('C:\\new')) # C:\new 'C:\\new'
```

- **Conversione `!r`**: All'interno di una f-string, aggiungere `!r` dopo un'espressione applica `repr()` a essa. Usare `!r` in `__repr__` mantiene valida la rappresentazione quando un valore contiene virgolette o barre rovesciate, a differenza di racchiudere i valori manualmente tra virgolette:

```py
class Employee:
    def __init__(self, name, level):
        self.name = name
        self.level = level

    def __repr__(self):
        return f'Employee({self.name!r}, {self.level!r})'

print(repr(Employee("O'Reilly", 'junior'))) # Employee("O'Reilly", 'junior')
```

## Docstring e controlli di tipo

- **Docstring**: Una stringa posta come prima istruzione in una classe o funzione per documentarla. Le docstring sono tipicamente racchiuse tra triple virgolette doppie:

```py
class Movie:
    """Parent class representing a movie."""

def add(x, y):
    """A function that returns the sum of two numbers."""
    return x + y
```

- **`isinstance()` vs. `type()`**: `isinstance(obj, ClassName)` restituisce `True` se `obj` è un'istanza di `ClassName` o di una sua sottoclasse, perché considera tutta la catena di ereditarietà. Per verificare una classe esatta, confronta invece `type(obj)`:

```py
class Movie:
    pass

class TVSeries(Movie):
    pass

series = TVSeries()
print(isinstance(series, Movie)) # True
print(type(series) == Movie) # False
print(type(series) == TVSeries) # True
```

## Eccezioni personalizzate con contesto extra

- **Memorizzare il contesto in un'eccezione**: Un'eccezione personalizzata può accettare dati extra insieme al suo messaggio. Chiamare `super().__init__(message)` permette alla classe integrata `Exception` di memorizzare e mostrare il messaggio, e puoi poi memorizzare i dati extra come attributo. Quando catturi l'eccezione, puoi leggere quell'attributo per aiutarti nel debugging:

```py
class MediaError(Exception):
    """Custom exception for media-related errors."""

    def __init__(self, message, obj):
        super().__init__(message)
        self.obj = obj

try:
    raise MediaError('Only Movie or TVSeries instances can be added', 42)
except MediaError as e:
    print(f'Media Error: {e}') # Media Error: Only Movie or TVSeries instances can be added
    print(f'Unable to add {e.obj}: {type(e.obj)}') # Unable to add 42: <class 'int'>
```

## Annotazioni di tipo

- **Annotazioni di tipo**: Annotazioni opzionali che segnalano ad altri sviluppatori quale tipo di dato ci si aspetta per una variabile, parametro o valore di ritorno. Python non le applica a runtime.
- **Annotazioni di tipo per parametri e ritorni**: Aggiungi un'annotazione di tipo a un parametro con due punti dopo il nome del parametro, e un'annotazione di tipo di ritorno con `-> return_type` dopo la lista dei parametri. Poiché `__init__` è un inizializzatore il cui valore di ritorno deve essere `None`, la sua annotazione di tipo di ritorno è `None`:

```py
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def is_affordable(self, budget: float) -> bool:
        return self.price <= budget
```

- **Classi personalizzate e liste come tipi**: Puoi usare le tue classi come annotazioni di tipo, e `list[ClassName]` specifica una lista contenente oggetti di quella classe:

```py
class DiscountStrategy:
    pass

class DiscountEngine:
    def __init__(self, strategies: list[DiscountStrategy]) -> None:
        self.strategies = strategies
```
